Un **GPIO** (*General Purpose Input/Output*) es un pin del chip que el programa puede usar como salida, para encender o apagar algo, o como entrada, para leer si algo está encendido o apagado. En el ESP32, `HIGH` son 3,3 V y `LOW` son 0 V. Para leer botones y contactos sin errores hacen falta dos cosas más: una resistencia de **pull-up** o **pull-down** que defina el valor cuando nada está conectado, y un **antirrebote** que ignore las oscilaciones de los contactos mecánicos.

## Por qué te importa

El controlador del invernadero usa GPIO para casi todo lo que no es un sensor con su propio protocolo: relés de la bomba y del ventilador, el botón de cambiar de modo, el botón de emergencia, el interruptor de flotante que avisa que el tanque está vacío, el contacto magnético de la puerta.

Los errores con GPIO no dan mensajes. Una entrada sin pull-up lee pulsaciones que nadie hizo. Un botón sin antirrebote cuenta tres pulsaciones por cada una. Un relé en el pin equivocado se activa solo durante el arranque y enciende la bomba medio segundo cada vez que el equipo se reinicia. Todo se resuelve sabiendo cómo funciona el pin.

## Paso a paso

### 1. Salidas

```cpp
// nodo (ESP32 clásico)
constexpr uint8_t PIN_LED = 2;

void setup() {
  pinMode(PIN_LED, OUTPUT);
  digitalWrite(PIN_LED, HIGH);   // 3,3 V en el pin
}
```

Un pin de salida entrega muy poca corriente: unos 20 mA como máximo recomendable. Alcanza para un LED con su resistencia, o para la entrada de un módulo de relé o de un transistor. **Nunca** conectes directamente un motor, una bomba, una bobina de relé o una tira de LEDs a un GPIO: se usa un módulo de relé, un transistor o un MOSFET que maneja la carga, y el GPIO solo le da la orden.

Muchos módulos de relé son **activos en bajo**: el relé se activa con `LOW`. Conviene esconder ese detalle en una función:

```cpp
constexpr uint8_t PIN_RELE_BOMBA = 4;

void encenderBomba() { digitalWrite(PIN_RELE_BOMBA, LOW); }    // activo en bajo
void apagarBomba()   { digitalWrite(PIN_RELE_BOMBA, HIGH); }
```

### 2. Entradas y el problema del pin flotante

```cpp
pinMode(PIN_BOTON, INPUT);
int estado = digitalRead(PIN_BOTON);   // HIGH o LOW
```

Si el botón conecta el pin a GND al presionarlo, ¿qué lee el pin con el botón suelto? Nada lo conecta a ningún lado: está **flotando**, y lee cualquier cosa según la electricidad estática del ambiente, la cercanía de tu mano o el cable de al lado. Un pin flotante es la causa más común de "pulsaciones fantasma".

### 3. Pull-up y pull-down

La solución es una resistencia que lleve el pin a un valor conocido cuando nada lo fuerza:

- **Pull-up**: una resistencia del pin a 3,3 V. Con el botón suelto, el pin lee `HIGH`. Al presionar, el botón lo conecta a GND y lee `LOW`.
- **Pull-down**: una resistencia del pin a GND. Con el botón suelto lee `LOW`; el botón va a 3,3 V y al presionarlo lee `HIGH`.

El ESP32 tiene estas resistencias dentro del chip, y se activan desde el código:

```cpp
pinMode(PIN_BOTON, INPUT_PULLUP);     // suelto = HIGH, presionado = LOW
pinMode(PIN_SENSOR, INPUT_PULLDOWN);  // suelto = LOW, activado = HIGH
```

La convención más usada es pull-up con el botón a GND: la lógica queda invertida (presionado es `LOW`), así que conviene una función `presionado()` que lo traduzca. Los pull-ups internos son débiles (decenas de kΩ); con cables largos, como el de un sensor en la otra punta del invernadero, conviene una resistencia externa de 4,7 a 10 kΩ.

### 4. Pines con reglas especiales en el ESP32

No todos los pines del ESP32 clásico sirven para todo:

| Pines | Restricción |
|---|---|
| 6 a 11 | conectados a la flash interna: no los uses |
| 34 a 39 | solo entrada, y sin pull-up ni pull-down internos |
| 0, 2, 5, 12, 15 | *strapping pins*: su valor al arrancar define cómo arranca el chip. Un relé o un botón ahí puede impedir el arranque o activarse solo al encender |
| 1 y 3 | TX y RX del `Serial` (el USB): mejor no usarlos |

El ESP32-S3 del controlador tiene sus propias reglas:

| Pines | Restricción |
|---|---|
| 0, 3, 45, 46 | *strapping pins* |
| 19 y 20 | el USB nativo |
| 26 a 32 | la flash interna; en placas con PSRAM OPI (como la N16R8), también 33 a 37 |
| 43 y 44 | TX y RX del `Serial` |
| 22 a 25 | no existen |

El C3 tiene otras. Antes de elegir pines, mirá el diagrama de pines (*pinout*) de tu placa; el mapa completo del controlador y del nodo de este curso está en [0.2](/conceptos/0-2). Una regla segura: para relés y actuadores, pines que no sean de strapping; para botones, pines con pull-up interno.

### 5. El rebote

Un botón mecánico no pasa de abierto a cerrado limpiamente. Durante 1 a 20 milisegundos, el contacto rebota: se abre y se cierra varias veces. `loop()` es tan rápido que ve cada rebote como una pulsación distinta.

El **antirrebote** (*debounce*) por tiempo funciona así: cada vez que la lectura cambia, se anota el momento; el cambio se acepta recién cuando la lectura se mantiene igual durante un tiempo, por ejemplo 30 ms.

### 6. Detectar el flanco

Muchas veces no interesa si el botón *está* presionado, sino el momento en que *se presiona*: una pulsación, una acción. Eso es detectar el **flanco**: el paso de suelto a presionado. Se logra comparando el estado estable actual con el anterior.

## Ejemplos

### Ejemplo 1. Un botón enciende un LED

```cpp boton-led.ino
// nodo (ESP32 clásico)
constexpr uint8_t PIN_BOTON = 27;
constexpr uint8_t PIN_LED = 2;

void setup() {
  pinMode(PIN_BOTON, INPUT_PULLUP);
  pinMode(PIN_LED, OUTPUT);
}

void loop() {
  bool presionado = digitalRead(PIN_BOTON) == LOW;   // con pull-up, presionado es LOW
  digitalWrite(PIN_LED, presionado ? HIGH : LOW);
}
```

Probá cambiar `INPUT_PULLUP` por `INPUT` y acercá la mano al cable: el LED parpadea solo. Eso es una entrada flotante.

### Ejemplo 2. Una clase `Boton` con antirrebote y pulsación larga

El botón del controlador cambia de modo con una pulsación corta, y con una pulsación de 3 segundos entra a la configuración.

```cpp boton-clase.ino
class Boton {
public:
  explicit Boton(uint8_t pin, uint32_t antirreboteMs = 30)
    : _pin(pin), _antirreboteMs(antirreboteMs) {}

  void begin() { pinMode(_pin, INPUT_PULLUP); }

  // Llamar en cada vuelta de loop()
  void actualizar() {
    _presionadoAhora = false;
    _soltadoAhora = false;

    bool lectura = digitalRead(_pin) == LOW;
    if (lectura != _ultimaLectura) {
      _ultimaLectura = lectura;
      _momentoCambio = millis();           // todavía puede estar rebotando
    }
    if (millis() - _momentoCambio >= _antirreboteMs && lectura != _estable) {
      _estable = lectura;                  // estable: se acepta el cambio
      if (_estable) {
        _presionadoAhora = true;
        _inicioPresion = millis();
      } else {
        _soltadoAhora = true;
        _duracionUltima = millis() - _inicioPresion;
      }
    }
  }

  bool sePresiono() const { return _presionadoAhora; }   // flanco de bajada: una vez por pulsación
  bool seSolto() const { return _soltadoAhora; }
  bool presionado() const { return _estable; }
  uint32_t msPresionado() const { return _estable ? millis() - _inicioPresion : 0; }
  uint32_t duracionUltima() const { return _duracionUltima; }

private:
  uint8_t _pin;
  uint32_t _antirreboteMs;
  bool _ultimaLectura = false;
  bool _estable = false;
  uint32_t _momentoCambio = 0;
  uint32_t _inicioPresion = 0;
  uint32_t _duracionUltima = 0;
  bool _presionadoAhora = false;
  bool _soltadoAhora = false;
};

Boton botonModo(41);   // el botón OK del controlador
int modo = 0;

void setup() {
  Serial.begin(115200);
  botonModo.begin();
}

void loop() {
  botonModo.actualizar();

  if (botonModo.seSolto()) {
    if (botonModo.duracionUltima() >= 3000) {
      Serial.println("entrar a configuración");
    } else {
      modo = (modo + 1) % 3;
      Serial.printf("modo %d\n", modo);
    }
  }
}
```

La decisión entre pulsación corta y larga se toma al soltar, cuando ya se sabe cuánto duró. `sePresiono()` y `seSolto()` son verdaderos durante una sola vuelta de `loop()`: cada pulsación genera exactamente un evento. Todo el tiempo se mide con `millis()`, sin `delay` (ver [0.1](/conceptos/0-1)).

### Ejemplo 3. Corte de la bomba por tanque vacío

Un interruptor de flotante dentro del tanque se cierra cuando el agua baja del mínimo. Si la bomba funciona en seco, se quema. El controlador tiene que cortar el riego, pero el flotante oscila cuando el agua se mueve, así que el antirrebote acá es de segundos, no de milisegundos.

```cpp tanque-vacio.ino
constexpr uint8_t PIN_FLOTANTE = 2;      // flotante entre el pin y GND: cerrado = tanque bajo
constexpr uint8_t PIN_RELE_BOMBA = 4;    // módulo de relé activo en bajo
constexpr uint32_t CONFIRMACION_MS = 2000;

bool tanqueVacio = false;

void encenderBomba() { digitalWrite(PIN_RELE_BOMBA, LOW); }
void apagarBomba()   { digitalWrite(PIN_RELE_BOMBA, HIGH); }

void actualizarTanque() {
  static bool ultimaLectura = false;
  static uint32_t momentoCambio = 0;

  bool lectura = digitalRead(PIN_FLOTANTE) == LOW;
  if (lectura != ultimaLectura) {
    ultimaLectura = lectura;
    momentoCambio = millis();
  }
  if (millis() - momentoCambio >= CONFIRMACION_MS && lectura != tanqueVacio) {
    tanqueVacio = lectura;
    Serial.println(tanqueVacio ? "tanque vacío: riego bloqueado" : "tanque con agua");
  }
}

void setup() {
  Serial.begin(115200);
  digitalWrite(PIN_RELE_BOMBA, HIGH);    // primero el nivel "apagado"...
  pinMode(PIN_RELE_BOMBA, OUTPUT);       // ...después el pin pasa a salida
  pinMode(PIN_FLOTANTE, INPUT_PULLUP);
}

void loop() {
  actualizarTanque();

  bool quiereRegar = true;               // acá iría la lógica de riego real
  if (quiereRegar && !tanqueVacio) {
    encenderBomba();
  } else {
    apagarBomba();
  }
}
```

Fijate en el orden de `setup()`: escribir `HIGH` antes de `pinMode(OUTPUT)` hace que el pin pase a salida ya en el nivel de "apagado". En el orden inverso, el pin sale un instante en `LOW` y un relé activo en bajo hace un clic, encendiendo la bomba por un momento en cada arranque. Las funciones `encenderBomba` y `apagarBomba` esconden la lógica invertida del módulo.

## Errores comunes

### Entrada sin pull-up

```cpp
// Mal
pinMode(PIN_PUERTA, INPUT);          // con el contacto abierto, flota

// Bien
pinMode(PIN_PUERTA, INPUT_PULLUP);
```

### Un relé en un strapping pin

```cpp
// Mal: GPIO 12 decide el voltaje de la flash al arrancar en el ESP32 clásico
constexpr uint8_t PIN_RELE = 12;

// Bien: un pin sin funciones de arranque
constexpr uint8_t PIN_RELE = 4;
```

Los síntomas van desde que la placa no arranca con el módulo conectado hasta que el relé se activa un instante al encender.

### Conectar la carga directo al pin

```text
Mal:   GPIO ── bobina del relé / motor ── GND
Bien:  GPIO ── entrada del módulo de relé (o transistor/MOSFET) ── la carga con su propia fuente
```

Un motor o una bobina piden mucha más corriente que la que puede dar un pin, y al apagarse generan picos de voltaje que pueden destruir el ESP32.

### Señales de 5 V en un pin del ESP32

Los GPIO del ESP32 trabajan con 3,3 V. Un sensor o un módulo que entrega 5 V en su salida puede dañar el pin. Usá un divisor resistivo o un adaptador de niveles (*level shifter*).

### Antirrebote con `delay`

```cpp
// Mal: congela todo 50 ms por cada pulsación
if (digitalRead(PIN_BOTON) == LOW) {
  delay(50);
  if (digitalRead(PIN_BOTON) == LOW) cambiarModo();
}

// Bien: la clase Boton del ejemplo 2, que mide el tiempo con millis()
```

## Ejercicio

La puerta del invernadero tiene un sensor magnético (un *reed switch*) entre el GPIO 2 y GND: está cerrado cuando la puerta está cerrada. El controlador debería contar cuántas veces se abre la puerta por día, pero cuenta cientos de aperturas, incluso de noche. Corregí el código.

```cpp puerta.ino
constexpr uint8_t PIN_PUERTA = 2;
int aperturasHoy = 0;

void setup() {
  Serial.begin(115200);
  pinMode(PIN_PUERTA, INPUT);
}

void loop() {
  if (digitalRead(PIN_PUERTA) == HIGH) {   // HIGH = contacto abierto = puerta abierta
    aperturasHoy++;
    Serial.println(aperturasHoy);
  }
}
```

<details>
<summary>Pista</summary>

Hay tres problemas: qué lee el pin cuando el contacto está abierto, qué pasa en cada vuelta de `loop()` mientras la puerta sigue abierta, y los rebotes del contacto.

</details>

<details>
<summary>Ver solución</summary>

```cpp puerta.ino
constexpr uint8_t PIN_PUERTA = 2;
constexpr uint32_t ANTIRREBOTE_MS = 50;

int aperturasHoy = 0;

void setup() {
  Serial.begin(115200);
  pinMode(PIN_PUERTA, INPUT_PULLUP);           // contacto abierto = HIGH, sin flotar
}

void loop() {
  static bool ultimaLectura = false;
  static bool abiertaEstable = false;
  static uint32_t momentoCambio = 0;

  bool abierta = digitalRead(PIN_PUERTA) == HIGH;
  if (abierta != ultimaLectura) {
    ultimaLectura = abierta;
    momentoCambio = millis();
  }
  if (millis() - momentoCambio >= ANTIRREBOTE_MS && abierta != abiertaEstable) {
    abiertaEstable = abierta;
    if (abiertaEstable) {                       // flanco: cerrada -> abierta
      aperturasHoy++;
      Serial.printf("puerta abierta (%d hoy)\n", aperturasHoy);
    }
  }
}
```

Con `INPUT`, el pin flotaba cada vez que el contacto se abría, y también podía leer `HIGH` con la puerta cerrada si el cable captaba ruido: esas eran las aperturas de noche. El código original además sumaba uno en *cada vuelta* de `loop()` mientras la puerta estaba abierta, miles de veces por segundo. Ahora se cuenta solo el flanco, una vez por apertura, y el antirrebote ignora las oscilaciones del contacto al moverse la puerta.

</details>

## Resumen

- Un GPIO como salida da la orden; la carga (relé, bomba, motor) se maneja con un módulo, transistor o MOSFET. Pensá si el módulo es activo en bajo.
- Una entrada sin nada que la fije flota y lee valores al azar. `INPUT_PULLUP` (o una resistencia externa) la define. Con pull-up, presionado es `LOW`.
- En el ESP32, los pines 6 a 11 no se usan, los 34 a 39 son solo de entrada y sin pull-up, y los strapping pins (0, 2, 5, 12, 15) pueden interferir con el arranque.
- Los contactos mecánicos rebotan: aceptá un cambio recién cuando la lectura se mantiene estable unos milisegundos.
- Para acciones, detectá el flanco (el cambio), no el estado.
