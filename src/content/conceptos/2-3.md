En [0.1](/conceptos/0-1) viste el patrón básico: en lugar de esperar con `delay()`, preguntar en cada vuelta de `loop()` si ya pasó el tiempo. Cuando el controlador tiene diez cosas que hacer con distintos ritmos, ese patrón repetido diez veces se vuelve difícil de seguir. Un **scheduler cooperativo** lo ordena: cada tarea es una función o un objeto que hace un poco de trabajo y **devuelve el control enseguida**, y un pequeño planificador decide cuál corre en cada momento. Es multitarea sin sistema operativo, y funciona mientras todas las tareas cooperen.

## Por qué te importa

El controlador del invernadero tiene que leer sensores cada 2 segundos, revisar el riego cada segundo, mover el servo de la ventana suavemente, atender los toques de la pantalla al instante, enviar al backend cada minuto y escribir el historial en la SD. Si cualquiera de esas cosas bloquea, las demás se atrasan: la pantalla no responde, el riego se pasa de tiempo, el servo se mueve a saltos.

El scheduler da tres cosas: un lugar único donde se ve qué corre y cada cuánto, una forma de medir cuánto tarda cada tarea (para encontrar a la que bloquea), y una disciplina: ninguna tarea tiene derecho a quedarse con el procesador.

## Paso a paso

### 1. El problema de los temporizadores sueltos

```cpp
void loop() {
  static uint32_t a = 0, b = 0, c = 0, d = 0;
  if (millis() - a >= 2000) { a = millis(); leerSensores(); }
  if (millis() - b >= 1000) { b = millis(); controlarRiego(); }
  if (millis() - c >= 20)   { c = millis(); moverServo(); }
  if (millis() - d >= 60000){ d = millis(); enviarAlBackend(); }   // ¿cuánto tarda esto?
  atenderPantalla();
}
```

Funciona, pero cada tarea nueva agrega otro temporizador, nadie sabe cuánto tarda cada una, y si `enviarAlBackend()` tarda 3 segundos, el servo deja de moverse durante 3 segundos sin que nada lo avise.

### 2. Qué es una tarea cooperativa

Una tarea cooperativa cumple una regla: **cada llamada hace poco y vuelve rápido**. "Poco" depende del sistema, pero una referencia útil para el controlador es: menos de unos pocos milisegundos por llamada. Si una tarea necesita hacer algo largo, lo divide en pasos y hace uno por llamada.

Las clases que vienen apareciendo en las lecciones (`Boton`, `ServoVentana`, `Sht31`, `CicloRiego`) ya son tareas cooperativas: tienen un `actualizar()` que revisa, hace un paso y vuelve.

### 3. Un planificador con una tabla

```cpp
struct Tarea {
  const char* nombre;
  void (*funcion)();
  uint32_t periodoMs;
  uint32_t ultimaMs;
};

Tarea tareas[] = {
  {"sensores", leerSensores,    2000, 0},
  {"riego",    controlarRiego,  1000, 0},
  {"servo",    moverServo,        20, 0},
  {"reporte",  enviarPendientes, 1000, 0},
};

void loop() {
  for (Tarea& t : tareas) {
    if (millis() - t.ultimaMs >= t.periodoMs) {
      t.ultimaMs = millis();
      t.funcion();
    }
  }
}
```

`void (*funcion)()` es un **puntero a función**: guarda qué función llamar. La tabla muestra todo el sistema de un vistazo: qué tareas hay y cada cuánto corren. Agregar una tarea es agregar una línea.

### 4. Medir cuánto tarda cada tarea

Con `micros()` antes y después de cada llamada, el scheduler sabe cuánto tarda cada tarea, en promedio y en el peor caso:

```cpp
uint32_t inicio = micros();
t.funcion();
uint32_t duracion = micros() - inicio;
if (duracion > t.maximaUs) t.maximaUs = duracion;
```

La duración **máxima** es la que importa: una tarea que tarda 1 ms casi siempre pero 800 ms una vez por minuto es la que traba la pantalla. Informar estos números cada tanto convierte "a veces se traba" en "la tarea de reporte tarda hasta 800 ms".

### 5. Dividir el trabajo largo

Cuando una tarea tiene mucho que hacer, se convierte en una pequeña máquina de estados (ver [2.2](/conceptos/2-2)) o en un recorrido que recuerda por dónde va:

```cpp
void exportarHistorial() {
  static size_t siguiente = 0;
  for (int i = 0; i < 10 && siguiente < historial.cantidad(); i++) {
    escribirLinea(historial.lectura(siguiente++));   // 10 líneas por llamada
  }
  if (siguiente == historial.cantidad()) siguiente = 0;   // terminó
}
```

Mil cuatrocientas líneas a 2 ms cada una son casi 3 segundos; diez por llamada son 20 ms, y el resto del sistema sigue funcionando entre llamada y llamada.

### 6. Los límites del enfoque cooperativo

El scheduler cooperativo es simple, predecible y no necesita protección entre tareas (nunca corren dos a la vez). Su límite son las operaciones que **no se pueden dividir**: una petición HTTP que espera la respuesta del servidor, una conexión BLE, un escaneo de WiFi. Esas bloquean aunque estén bien escritas. Para ellas, la solución es una tarea de FreeRTOS propia, que corre en paralelo y que el sistema interrumpe cuando hace falta (ver [2.4](/conceptos/2-4)). En la práctica, el controlador combina las dos cosas: un scheduler cooperativo para el control y la interfaz, y una o dos tareas de FreeRTOS para la comunicación.

## Ejemplos

### Ejemplo 1. Un scheduler con tabla de tareas

```cpp scheduler.ino
void leerSensores()   { Serial.println("sensores"); }
void controlarRiego() { /* decidir y actuar */ }
void parpadearLed()   {
  static bool on = false;
  on = !on;
  digitalWrite(2, on ? HIGH : LOW);
}

struct Tarea {
  const char* nombre;
  void (*funcion)();
  uint32_t periodoMs;
  uint32_t ultimaMs;
};

Tarea tareas[] = {
  {"sensores", leerSensores,   2000, 0},
  {"riego",    controlarRiego, 1000, 0},
  {"led",      parpadearLed,    500, 0},
};

void ejecutarTareas() {
  uint32_t ahora = millis();
  for (Tarea& t : tareas) {
    if (ahora - t.ultimaMs >= t.periodoMs) {
      t.ultimaMs = ahora;              // si se atrasó, no se recuperan ejecuciones perdidas
      t.funcion();
    }
  }
}

void setup() {
  Serial.begin(115200);
  pinMode(2, OUTPUT);
}

void loop() {
  ejecutarTareas();
}
```

`t.ultimaMs = ahora` reprograma la tarea desde el momento en que corrió. Si una tarea se atrasó por algún motivo, corre una vez y sigue su ritmo, sin una ráfaga de ejecuciones atrasadas. Para tareas que necesitan un ritmo exacto a largo plazo, se usa `t.ultimaMs += t.periodoMs`, como en el temporizador de [0.1](/conceptos/0-1).

### Ejemplo 2. Medir y detectar la tarea que bloquea

El mismo scheduler, con estadísticas por tarea y un informe cada 10 segundos. Una de las tareas simula un envío al backend que a veces tarda mucho.

```cpp scheduler-medido.ino
struct Tarea {
  const char* nombre;
  void (*funcion)();
  uint32_t periodoMs;
  uint32_t ultimaMs = 0;
  uint32_t ejecuciones = 0;
  uint32_t maximaUs = 0;
  uint64_t totalUs = 0;
};

void leerSensores() { delayMicroseconds(800); }      // simula una lectura de ~1 ms
void dibujar()      { delayMicroseconds(3000); }     // simula dibujar ~3 ms
void enviar() {
  static int n = 0;
  if (++n % 5 == 0) delay(600);                      // simula un envío que a veces bloquea
}

Tarea tareas[] = {
  {"sensores", leerSensores, 2000},
  {"pantalla", dibujar,       100},
  {"reporte",  enviar,       1000},
};

constexpr uint32_t ALERTA_US = 20000;   // más de 20 ms en una llamada es demasiado

void ejecutarTareas() {
  for (Tarea& t : tareas) {
    if (millis() - t.ultimaMs < t.periodoMs) continue;
    t.ultimaMs = millis();

    uint32_t inicio = micros();
    t.funcion();
    uint32_t dur = micros() - inicio;

    t.ejecuciones++;
    t.totalUs += dur;
    if (dur > t.maximaUs) t.maximaUs = dur;
    if (dur > ALERTA_US) {
      Serial.printf("! %s tardó %u ms\n", t.nombre, static_cast<unsigned>(dur / 1000));
    }
  }
}

void informar() {
  Serial.println("tarea      ejec   prom(us)   max(us)");
  for (const Tarea& t : tareas) {
    uint32_t prom = t.ejecuciones ? static_cast<uint32_t>(t.totalUs / t.ejecuciones) : 0;
    Serial.printf("%-9s %5u %10u %9u\n", t.nombre, static_cast<unsigned>(t.ejecuciones),
                  static_cast<unsigned>(prom), static_cast<unsigned>(t.maximaUs));
  }
}

void setup() {
  Serial.begin(115200);
}

void loop() {
  ejecutarTareas();
  static uint32_t ultimoInforme = 0;
  if (millis() - ultimoInforme >= 10000) {
    ultimoInforme = millis();
    informar();
  }
}
```

El informe muestra que `reporte` tiene un promedio razonable pero un máximo de 600 ms, y la alerta lo marca en el momento. En el sistema real, esa es la señal para mover el envío a una tarea de FreeRTOS. Los inicializadores en la declaración del `struct` (`= 0`) permiten escribir la tabla con solo los tres primeros campos. `delayMicroseconds` y `delay` acá solo simulan trabajo.

### Ejemplo 3. Una tarea larga dividida en pasos

El operario pide desde la pantalla exportar el historial del día a la tarjeta SD: 1440 lecturas. La tarea de exportación es una pequeña máquina de estados que escribe 20 líneas por llamada.

```cpp exportar.ino
struct Lectura { float temperatura; float humedadSuelo; };

Lectura historial[1440];
size_t cantidadHistorial = 1440;

class Exportacion {
public:
  void iniciar() {
    if (_estado != Estado::Inactiva) return;
    _siguiente = 0;
    _estado = Estado::Escribiendo;
    Serial.println("exportación: inicio");
    // acá se abriría el archivo en la SD
  }

  // Tarea cooperativa: llamar seguido; nunca escribe más de LINEAS_POR_PASO
  void actualizar() {
    if (_estado != Estado::Escribiendo) return;

    for (int i = 0; i < LINEAS_POR_PASO && _siguiente < cantidadHistorial; i++, _siguiente++) {
      const Lectura& l = historial[_siguiente];
      char linea[32];
      snprintf(linea, sizeof(linea), "%u,%.1f,%.0f", static_cast<unsigned>(_siguiente),
               l.temperatura, l.humedadSuelo);
      // acá: archivo.println(linea);
    }

    if (_siguiente >= cantidadHistorial) {
      // acá se cerraría el archivo
      _estado = Estado::Inactiva;
      Serial.println("exportación: terminada");
    }
  }

  bool activa() const { return _estado == Estado::Escribiendo; }
  int progreso() const {
    return cantidadHistorial ? static_cast<int>(_siguiente * 100 / cantidadHistorial) : 100;
  }

private:
  enum class Estado : uint8_t { Inactiva, Escribiendo };
  static constexpr int LINEAS_POR_PASO = 20;
  Estado _estado = Estado::Inactiva;
  size_t _siguiente = 0;
};

Exportacion exportacion;

void setup() {
  Serial.begin(115200);
  exportacion.iniciar();
}

void loop() {
  exportacion.actualizar();

  static uint32_t ultimo = 0;
  if (exportacion.activa() && millis() - ultimo >= 200) {
    ultimo = millis();
    Serial.printf("progreso: %d%%\n", exportacion.progreso());   // la pantalla mostraría una barra
  }
  // las demás tareas siguen corriendo entre paso y paso
}
```

Cada llamada a `actualizar()` escribe 20 líneas y vuelve. Entre llamada y llamada, el resto del controlador sigue funcionando, y la pantalla puede mostrar el progreso. El tamaño del paso (20 líneas) se ajusta midiendo, como en el ejemplo 2, para que cada llamada quede dentro del presupuesto de tiempo.

## Errores comunes

### Una tarea que bloquea

```cpp
// Mal: una tarea cooperativa con un delay o una espera
void tareaSensores() {
  pedirMedicion();
  delay(20);              // todas las demás esperan
  leerMedicion();
}

// Bien: pedir en una llamada, leer en otra (ver 0.7)
void tareaSensores() {
  if (!pedido) { pedirMedicion(); pedido = true; momento = millis(); }
  else if (millis() - momento >= 20) { leerMedicion(); pedido = false; }
}
```

### Operaciones de red en el scheduler cooperativo

Una petición HTTP puede tardar segundos esperando al servidor, y no se puede dividir en pasos con la API de `HTTPClient`. Va en una tarea de FreeRTOS (ver [2.4](/conceptos/2-4)), y el scheduler solo deja los datos en una cola.

### Recuperar ejecuciones atrasadas en ráfaga

```cpp
// Mal: si la tarea se atrasó 5 períodos, corre 5 veces seguidas
while (millis() - t.ultimaMs >= t.periodoMs) {
  t.ultimaMs += t.periodoMs;
  t.funcion();
}

// Bien para la mayoría de las tareas: correr una vez y seguir
if (millis() - t.ultimaMs >= t.periodoMs) {
  t.ultimaMs = millis();
  t.funcion();
}
```

### Suponer que los períodos son exactos

Un scheduler cooperativo garantiza "no antes del período", no "exactamente en el período": si otra tarea tarda, la siguiente corre un poco más tarde. Para algo que necesita tiempos exactos (contar pulsos, generar una señal), se usan interrupciones o periféricos de hardware (ver [0.8](/conceptos/0-8) y [0.5](/conceptos/0-5)).

```cpp loop-ordenado.ino
void exportarPorPasos() {
  static int siguiente = -1;                    // -1 = no hay exportación en curso
  if (siguiente < 0) {
    if (!pedidoExportar) return;
    pedidoExportar = false;
    siguiente = 0;
  }
  for (int i = 0; i < 4 && siguiente < 500; i++) {
    escribirEventoEnSd(siguiente++);            // 4 x 5 ms = 20 ms por llamada
  }
  if (siguiente >= 500) siguiente = -1;         // terminó
}

struct Tarea {
  const char* nombre;
  void (*funcion)();
  uint32_t periodoMs;
  uint32_t ultimaMs;
};

Tarea tareas[] = {
  {"sensores",  leerSensores,     2000, 0},
  {"riego",     controlarRiego,   1000, 0},
  {"pantalla",  dibujarPantalla,   100, 0},
  {"exportar",  exportarPorPasos,    0, 0},   // período 0: en cada vuelta
};

void loop() {
  for (Tarea& t : tareas) {
    if (millis() - t.ultimaMs >= t.periodoMs) {
      t.ultimaMs = millis();
      t.funcion();
    }
  }
}
```

## Resumen

- Un scheduler cooperativo ejecuta tareas de a una, dentro de `loop()`. Cada tarea tiene que hacer poco y volver rápido.
- Una tabla de tareas (nombre, función, período) muestra todo el sistema en un lugar.
- Medí con `micros()` la duración máxima de cada tarea: es la que explica las trabas.
- Un trabajo largo se divide en pasos chicos, recordando por dónde se va.
- Lo que no se puede dividir (HTTP, BLE, escaneos) va a una tarea de FreeRTOS. Para la mayoría de las tareas, si se atrasan, se corren una vez y se sigue.
