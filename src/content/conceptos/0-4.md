Muchos sensores no hablan un protocolo digital: entregan un **voltaje** que cambia con lo que miden. Un sensor de humedad de suelo capacitivo da más voltaje cuanto más seco está el suelo; una fotorresistencia en un divisor da más o menos voltaje según la luz. El **ADC** (*conversor analógico-digital*) del ESP32 convierte ese voltaje en un número. `analogRead` devuelve ese número, y `analogReadMilliVolts` lo devuelve ya convertido a milivoltios.

## Por qué te importa

En el invernadero, la humedad del suelo decide cuándo regar. Esa lectura sale del ADC, y el ADC del ESP32 tiene particularidades que hay que conocer. No es perfectamente lineal, tiene ruido, mide hasta poco más de 3 V, y en el ESP32 clásico la mitad de sus pines deja de funcionar apenas se enciende el WiFi.

Si no las tenés en cuenta, el controlador riega cuando no hace falta porque una lectura ruidosa cruzó el umbral, o deja de regar del todo el día que se conecta a la red porque el sensor quedó en un pin del ADC2.

## Paso a paso

### 1. Del voltaje al número

El ADC compara el voltaje del pin con una referencia y devuelve un número proporcional. El del ESP32 es de 12 bits: devuelve valores de 0 a 4095.

```cpp
int crudo = analogRead(34);               // 0 a 4095
uint32_t mv = analogReadMilliVolts(34);   // milivoltios, calibrado
```

Con la configuración por defecto, el rango útil va de 0 a unos 3,1 V. `analogReadMilliVolts` usa los datos de calibración que Espressif graba en cada chip en la fábrica, así que da un valor más preciso que convertir `analogRead` con una regla de tres. Para casi todo, usá `analogReadMilliVolts`.

### 2. ADC1 y ADC2

El ESP32 tiene dos ADC, y cada pin analógico pertenece a uno:

| Chip | ADC1 | ADC2 |
|---|---|---|
| ESP32 | GPIO 32 a 39 | GPIO 0, 2, 4, 12 a 15, 25 a 27 |
| ESP32-S3 | GPIO 1 a 10 | GPIO 11 a 20 |

El WiFi usa el ADC2. En el ESP32 clásico, mientras el WiFi está encendido, leer un pin del ADC2 falla. En otros chips de la familia hay restricciones parecidas. La regla segura: **sensores analógicos siempre en pines del ADC1**.

### 3. Ruido y no linealidad

Dos lecturas seguidas del mismo voltaje pueden diferir en decenas de cuentas. Además, cerca de 0 V y del máximo, el ADC deja de ser lineal: por debajo de unos 100 mV casi no distingue valores.

Dos medidas simples ayudan mucho:

- **Promediar** varias lecturas: el ruido aleatorio se compensa.
- **Usar la mediana** si hay lecturas sueltas muy desviadas (un pico por un relé que conmuta, por ejemplo): se ordenan las lecturas y se toma la del medio, sin que los extremos influyan.

Y en el diseño, que el sensor trabaje en la zona media del rango, no en los extremos.

### 4. Voltajes mayores a 3,3 V: el divisor resistivo

Un pin del ESP32 no tolera más de 3,3 V. Para medir algo mayor, como una batería de litio (hasta 4,2 V), se usa un **divisor resistivo**: dos resistencias en serie entre el voltaje a medir y GND, con el pin conectado en el medio.

```text
Batería (+) ── R1 (100 kΩ) ──┬── R2 (100 kΩ) ── GND
                              │
                           GPIO 34
```

Con dos resistencias iguales, el pin recibe la mitad del voltaje: 4,2 V llegan como 2,1 V. En el código, la lectura se multiplica por 2. En general, el factor es `(R1 + R2) / R2`. Resistencias de 100 kΩ gastan poca corriente de la batería; más altas que eso empiezan a afectar la lectura.

### 5. De milivoltios a la magnitud real

Lo que importa no son milivoltios sino porcentaje de humedad, nivel de luz, voltaje de batería. Para la mayoría de los sensores analógicos baratos, la forma práctica es **calibrar con dos puntos**: medir los milivoltios en dos situaciones conocidas y suponer una relación lineal entre ellas.

Para un sensor de humedad de suelo capacitivo:

1. Con el sensor al aire (0 % de humedad): por ejemplo, 2600 mV.
2. Con el sensor en un vaso de agua (100 %): por ejemplo, 1150 mV.
3. Cualquier lectura intermedia se convierte con una regla de tres:

```cpp
float porcentaje = (2600.0f - mv) / (2600.0f - 1150.0f) * 100.0f;
```

Cada sensor es un poco distinto: estos dos valores se miden para cada uno y se guardan en la configuración (ver [0.11](/conceptos/0-11)).

## Ejemplos

### Ejemplo 1. Ver el ADC en acción

Un potenciómetro (resistencia variable) conectado a 3,3 V, GND y al GPIO 34 permite ver las lecturas al girarlo.

```cpp potenciometro.ino
// nodo (ESP32 clásico)
constexpr uint8_t PIN_POTE = 34;   // ADC1

void setup() {
  Serial.begin(115200);
}

void loop() {
  static uint32_t ultimo = 0;
  if (millis() - ultimo >= 200) {
    ultimo = millis();
    int crudo = analogRead(PIN_POTE);
    uint32_t mv = analogReadMilliVolts(PIN_POTE);
    Serial.printf("crudo %4d   %4u mV\n", crudo, static_cast<unsigned>(mv));
  }
}
```

Girá el potenciómetro hasta los extremos y mirá los números: cerca de 0 V y de 3,3 V el crudo se queda trabado, aunque sigas girando. Esa es la no linealidad de los extremos.

### Ejemplo 2. Voltaje de la batería de un nodo

El nodo sensor funciona con una batería de litio. Con un divisor de dos resistencias de 100 kΩ, mide su voltaje y estima la carga.

```cpp bateria.ino
// nodo (ESP32 clásico)
constexpr uint8_t PIN_BATERIA = 35;   // ADC1, solo entrada
constexpr float FACTOR_DIVISOR = 2.0f;  // (100k + 100k) / 100k
constexpr int MUESTRAS = 16;

float leerBateriaV() {
  uint32_t suma = 0;
  for (int i = 0; i < MUESTRAS; i++) {
    suma += analogReadMilliVolts(PIN_BATERIA);
  }
  float mvPin = static_cast<float>(suma) / MUESTRAS;
  return mvPin * FACTOR_DIVISOR / 1000.0f;
}

int cargaAproximada(float voltios) {
  // Aproximación lineal entre 3,3 V (vacía para este uso) y 4,2 V (llena)
  float fraccion = (voltios - 3.3f) / (4.2f - 3.3f);
  return constrain(static_cast<int>(lroundf(fraccion * 100.0f)), 0, 100);
}

void setup() {
  Serial.begin(115200);
}

void loop() {
  static uint32_t ultimo = 0;
  if (millis() - ultimo >= 5000) {
    ultimo = millis();
    float v = leerBateriaV();
    Serial.printf("batería: %.2f V, ~%d%%\n", v, cargaAproximada(v));
  }
}
```

La descarga de una batería de litio no es lineal, así que el porcentaje es aproximado; para decidir cuándo avisar "batería baja", el voltaje es más confiable que el porcentaje. La cuenta se hace en `float` para no perder decimales (ver [B.1](/conceptos/b-1)).

### Ejemplo 3. Una clase para el sensor de humedad de suelo

Un nodo con dos canteros cerca tiene un sensor por cantero. La clase toma 9 lecturas, usa la mediana, convierte con la calibración de dos puntos y detecta si el sensor está desconectado.

```cpp sensor-suelo.ino
// nodo (ESP32 clásico)
#include <algorithm>

class SensorSuelo {
public:
  SensorSuelo(uint8_t pin, uint32_t mvSeco, uint32_t mvMojado)
    : _pin(pin), _mvSeco(mvSeco), _mvMojado(mvMojado) {}

  // Devuelve false si la lectura no es confiable
  bool leer() {
    uint32_t muestras[9];
    for (uint32_t& m : muestras) {
      m = analogReadMilliVolts(_pin);
    }
    std::sort(muestras, muestras + 9);
    _mv = muestras[4];                        // la mediana

    if (_mv < 200 || _mv > 3000) {            // fuera del rango posible: desconectado o en corto
      _valida = false;
      return false;
    }
    float fraccion = (static_cast<float>(_mvSeco) - _mv) /
                     (static_cast<float>(_mvSeco) - _mvMojado);
    _porcentaje = constrain(fraccion * 100.0f, 0.0f, 100.0f);
    _valida = true;
    return true;
  }

  bool valida() const { return _valida; }
  float porcentaje() const { return _porcentaje; }
  uint32_t mv() const { return _mv; }

private:
  uint8_t _pin;
  uint32_t _mvSeco;
  uint32_t _mvMojado;
  uint32_t _mv = 0;
  float _porcentaje = 0.0f;
  bool _valida = false;
};

SensorSuelo cantero1(34, 2600, 1150);   // calibración medida para este sensor
SensorSuelo cantero2(32, 2550, 1180);

void informar(const char* nombre, SensorSuelo& s) {
  if (s.leer()) {
    Serial.printf("%s: %.0f%% (%u mV)\n", nombre, s.porcentaje(), static_cast<unsigned>(s.mv()));
  } else {
    Serial.printf("%s: sensor sin lectura válida (%u mV)\n", nombre, static_cast<unsigned>(s.mv()));
  }
}

void setup() {
  Serial.begin(115200);
}

void loop() {
  static uint32_t ultimo = 0;
  if (millis() - ultimo >= 10000) {
    ultimo = millis();
    informar("cantero 1", cantero1);
    informar("cantero 2", cantero2);
  }
}
```

La mediana de 9 lecturas descarta picos sueltos, que un promedio dejaría pasar en parte. El chequeo de rango es importante: un sensor desconectado deja el pin flotando o en 0, y sin el chequeo el controlador creería que el suelo está empapado o completamente seco, y regaría (o dejaría de regar) por un cable suelto. `std::sort` es una función de la librería estándar de C++ que ordena un arreglo.

## Errores comunes

### Un sensor en un pin del ADC2

```cpp
// Mal (ESP32 clásico): GPIO 4 es ADC2, falla con el WiFi encendido
constexpr uint8_t PIN_SUELO = 4;

// Bien: ADC1
constexpr uint8_t PIN_SUELO = 34;
```

### Más de 3,3 V en el pin

Medir directamente una batería de 4,2 V, o un sensor alimentado con 5 V cuya salida llega a 5 V, puede dañar el pin. Siempre un divisor resistivo si el voltaje puede pasar de 3,3 V.

### Confiar en una sola lectura

```cpp
// Mal: una lectura ruidosa cruza el umbral y dispara el riego
if (analogReadMilliVolts(PIN_SUELO) > 2200) regar();

// Bien: varias lecturas, y además un margen alrededor del umbral
```

Para decisiones como regar, además de filtrar el ruido conviene un margen: empezar a regar por debajo de un valor y dejar de regar por encima de otro, más alto. Así una lectura que oscila alrededor del umbral no prende y apaga la bomba una y otra vez.

### Suponer que el sensor va de 0 a 3,3 V

```cpp
// Mal: el sensor nunca llega a 0 ni a 3300 mV
int porcentaje = map(mv, 0, 3300, 100, 0);

// Bien: calibrar con los valores reales del sensor (ejemplo 3)
```

## Ejercicio

Un nodo (un ESP32 clásico) mide la luz con una fotorresistencia en un divisor, conectada al GPIO 4. Debería encender las luces de cultivo cuando la luz baja del 30 %; en el banco de pruebas, el LED del GPIO 2 hace de luces. Funcionaba en el banco de pruebas, pero en el invernadero las luces nunca se encienden, y en los momentos de transición parpadean. Corregí el código.

```cpp luz.ino
// nodo (ESP32 clásico)
constexpr uint8_t PIN_LUZ = 4;
constexpr uint8_t PIN_LUCES = 2;

void setup() {
  pinMode(PIN_LUCES, OUTPUT);
  WiFi.begin("invernadero", "clave");
}

void loop() {
  int luz = analogRead(PIN_LUZ) * 100 / 4095;
  digitalWrite(PIN_LUCES, luz < 30 ? HIGH : LOW);
}
```

<summary>Pista</summary>

Hay un problema de pin relacionado con el WiFi, uno de ruido y uno de decisión: con un solo umbral, cualquier oscilación alrededor del 30 % prende y apaga las luces.

</details>

<details>
<summary>Ver solución</summary>

```cpp luz.ino
// nodo (ESP32 clásico)
#include <WiFi.h>

constexpr uint8_t PIN_LUZ = 33;            // ADC1: funciona con WiFi
constexpr uint8_t PIN_LUCES = 2;
constexpr int ENCENDER_DEBAJO = 30;        // %
constexpr int APAGAR_ENCIMA = 40;          // %: margen para no oscilar

bool lucesEncendidas = false;

int leerLuzPorcentaje() {
  uint32_t suma = 0;
  for (int i = 0; i < 16; i++) {
    suma += analogRead(PIN_LUZ);
  }
  float promedio = static_cast<float>(suma) / 16.0f;
  return static_cast<int>(lroundf(promedio * 100.0f / 4095.0f));
}

void setup() {
  pinMode(PIN_LUCES, OUTPUT);
  WiFi.begin("invernadero", "clave");
}

void loop() {
  static uint32_t ultimo = 0;
  if (millis() - ultimo < 1000) return;
  ultimo = millis();

  int luz = leerLuzPorcentaje();
  if (!lucesEncendidas && luz < ENCENDER_DEBAJO) {
    lucesEncendidas = true;
  } else if (lucesEncendidas && luz > APAGAR_ENCIMA) {
    lucesEncendidas = false;
  }
  digitalWrite(PIN_LUCES, lucesEncendidas ? HIGH : LOW);
}
```

El GPIO 4 es del ADC2: en el banco de pruebas no había WiFi y funcionaba, en el invernadero la lectura fallaba y las luces no se encendían. El promedio de 16 lecturas reduce el ruido. Y con dos umbrales (encender por debajo del 30 %, apagar por encima del 40 %), las luces no parpadean al atardecer. Además, se mide una vez por segundo: la luz natural cambia despacio y no hace falta medirla miles de veces por segundo. Las credenciales del WiFi no deberían ir en el código (ver [6.1](/conceptos/6-1)).

</details>

## Resumen

- El ADC del ESP32 convierte un voltaje de 0 a unos 3,1 V en un número de 0 a 4095. `analogReadMilliVolts` da milivoltios calibrados.
- Los sensores analógicos van en pines del ADC1: el ADC2 deja de funcionar con el WiFi encendido en el ESP32 clásico.
- Las lecturas tienen ruido: promediá o usá la mediana. Evitá trabajar cerca de 0 V y del máximo.
- Para voltajes mayores a 3,3 V, un divisor resistivo y multiplicar por el factor del divisor.
- Convertí a la magnitud real con una calibración de dos puntos, y validá que la lectura esté en un rango posible.
