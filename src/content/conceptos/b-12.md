Hay dos formas de manejar texto en un sketch de Arduino. La clase **`String`** de Arduino es cómoda: crece sola, se concatena con `+` y se convierte desde números. Para eso pide memoria al heap cada vez que necesita más lugar. Las **cadenas de C** son arreglos de `char` de tamaño fijo, terminados en un carácter `\0`: no piden memoria nunca, pero hay que manejarlas con funciones como `snprintf` y `strcmp`, y respetar su tamaño. En un equipo que funciona semanas, elegir bien entre las dos evita reinicios.

## Por qué te importa

El controlador del invernadero arma texto todo el tiempo: la línea de estado de la pantalla cada medio segundo, el mensaje para el backend cada minuto, los logs del monitor serie. Con `String`, cada `"temp: " + String(t) + " C"` crea varias cadenas temporales en el heap y las libera. En una prueba de una hora no pasa nada. Después de varios días, el heap queda fragmentado en huecos chicos, una reserva grande (por ejemplo, la del cliente HTTP) falla, y el equipo se reinicia de madrugada (ver [B.8](/conceptos/b-8)).

Las cadenas de C tienen sus propios peligros. Si copiás un texto más largo que el arreglo, escribís sobre otra variable sin ningún aviso, y si comparás con `==`, comparás direcciones de memoria. Esta lección muestra cómo usarlas bien y cuándo vale la pena `String`.

## Paso a paso

### 1. Una cadena de C es un arreglo de `char` con un `\0` al final

```cpp
char nodo[10] = "norte";
```

En memoria queda así: `n`, `o`, `r`, `t`, `e`, `\0`, y cuatro bytes más sin usar. El `\0` (un byte con valor cero) marca dónde termina el texto. Todas las funciones de cadenas de C recorren el arreglo hasta encontrar ese `\0`.

```cpp
sizeof(nodo);   // 10: el tamaño del arreglo
strlen(nodo);   // 5: los caracteres antes del \0
```

Para guardar un texto de N caracteres, el arreglo necesita al menos N + 1 bytes.

### 2. Las funciones que vas a usar

```cpp
char destino[16];

strlcpy(destino, "invernadero 2", sizeof(destino));   // copiar, sin pasarse del tamaño
size_t largo = strlen(destino);                        // 13

if (strcmp(destino, "invernadero 2") == 0) {           // comparar: 0 si son iguales
  // ...
}

if (strncmp(destino, "invernadero", 11) == 0) {        // comparar el comienzo
  // ...
}

snprintf(destino, sizeof(destino), "nodo %d", 3);      // armar texto con formato
```

- `strlcpy(destino, origen, tamaño)` copia y siempre deja el `\0`, cortando si no entra. Existe en el ESP32. Evitá `strcpy`, que no recibe el tamaño y escribe lo que haga falta, aunque se pase.
- `strcmp(a, b)` devuelve 0 si los textos son iguales. Nunca compares cadenas de C con `==`.
- `snprintf(destino, tamaño, formato, ...)` funciona como `printf` pero escribe en el arreglo, nunca más de `tamaño` bytes contando el `\0`.

### 3. Cómo funciona `String`

```cpp
String linea = "temp: ";
linea += String(24.5f, 1);   // "temp: 24.5"
linea += " C";               // "temp: 24.5 C"
```

Una `String` guarda un puntero a un bloque del heap con el texto. Cuando el texto crece y no entra en el bloque, pide uno más grande, copia el texto y libera el viejo. Una expresión como `"temp: " + String(t, 1) + " C"` crea objetos temporales para cada paso intermedio, cada uno con su propio bloque.

Es muy cómoda: no hay que pensar en tamaños, no se desborda, y tiene métodos útiles (`indexOf`, `substring`, `toInt`). El costo es la actividad en el heap.

### 4. El costo y cómo reducirlo

Si vas a usar `String` en código que se ejecuta seguido, `reserve()` pide el bloque una sola vez con el tamaño que va a necesitar:

```cpp
String linea;
linea.reserve(64);           // un bloque de 64 bytes desde el principio
linea = "temp: ";
linea += String(24.5f, 1);   // String(24.5f, 1) sigue siendo un temporal
linea += " C";
```

Ayuda, pero cada `String(numero)` sigue creando un temporal. Para texto que se arma muchas veces por minuto, un buffer fijo con `snprintf` no toca el heap en absoluto:

```cpp
char linea[64];
snprintf(linea, sizeof(linea), "temp: %.1f C", 24.5f);
```

### 5. Cuándo usar cada una

| Situación | Usá |
|---|---|
| Texto que se arma muchas veces (cada segundo, cada lectura) | `char[]` con `snprintf` |
| Parsear datos que llegan de afuera (serie, BLE, red) | `char[]` de tamaño fijo, con límites |
| Texto que se arma pocas veces (al arrancar, al cambiar la configuración) | `String` está bien |
| Una librería que pide o devuelve `String` | `String`, pero sin concatenar en bucles |

Muchas librerías de Arduino trabajan con `String` (`WiFi.SSID()`, `HTTPClient::getString()`). Usarlas está bien; el problema es el patrón de crear y concatenar `String` temporales en código que se repite.

### 6. Pasar de una a otra

```cpp
String ssid = WiFi.SSID();
char copia[33];
strlcpy(copia, ssid.c_str(), sizeof(copia));   // de String a char[]

char nombre[16] = "norte";
String s = nombre;                             // de char[] a String
```

`c_str()` devuelve un `const char*` al texto de la `String`. Ese puntero es válido mientras la `String` exista y no se modifique: no lo guardes para después.

## Ejemplos

### Ejemplo 1. Lo básico de las cadenas de C

```cpp cadenas.ino
void setup() {
  Serial.begin(115200);

  char nodo[12] = "norte";
  Serial.printf("'%s': sizeof %u, strlen %u\n", nodo,
                static_cast<unsigned>(sizeof(nodo)),
                static_cast<unsigned>(strlen(nodo)));   // 'norte': sizeof 12, strlen 5

  strlcpy(nodo, "sur-oeste-lejano", sizeof(nodo));
  Serial.println(nodo);                                 // sur-oeste-l (cortado, con \0)

  char mensaje[32];
  int n = snprintf(mensaje, sizeof(mensaje), "nodo %s: %.1f C", nodo, 26.75f);
  Serial.println(mensaje);                              // nodo sur-oeste-l: 26.8 C
  if (n >= static_cast<int>(sizeof(mensaje))) {
    Serial.println("el mensaje quedó cortado");
  }

  Serial.println(strcmp(nodo, "norte") == 0 ? "es el norte" : "no es el norte");
}

void loop() {}
```

Corré el ejemplo y cambiá los tamaños de los arreglos para ver cómo `strlcpy` y `snprintf` cortan el texto en lugar de pasarse.

### Ejemplo 2. La línea de estado de la pantalla, dos formas

La pantalla del controlador muestra una línea de estado que se actualiza dos veces por segundo. La primera versión usa `String`; la segunda, un buffer fijo.

```cpp linea-estado.ino
float temperatura = 24.5f;
int humedadSuelo = 41;
bool regando = true;

// Con String: varios bloques temporales en el heap en cada llamada
String lineaConString() {
  return "T " + String(temperatura, 1) + " C | suelo " + String(humedadSuelo) +
         "% | " + (regando ? "regando" : "en espera");
}

// Con buffer fijo: cero reservas
void lineaConBuffer(char* destino, size_t tam) {
  snprintf(destino, tam, "T %.1f C | suelo %d%% | %s",
           temperatura, humedadSuelo, regando ? "regando" : "en espera");
}

void setup() {
  Serial.begin(115200);
}

void loop() {
  static uint32_t ultimo = 0;
  if (millis() - ultimo >= 500) {
    ultimo = millis();

    String a = lineaConString();
    char b[48];
    lineaConBuffer(b, sizeof(b));

    Serial.println(a);
    Serial.println(b);
  }
}
```

Las dos líneas son idénticas. La diferencia está en el heap: la versión con `String` crea seis o siete bloques temporales por llamada, unas 170.000 veces por día. La versión con buffer usa 48 bytes del stack que se liberan solos. Fijate en `%%`: en el formato de `printf`, así se escribe un `%` literal.

### Ejemplo 3. Leer comandos del monitor serie sin `String`

Para probar el controlador sin la pantalla, se le pueden mandar comandos por el monitor serie: `REGAR 120` riega 120 segundos, `VENTILAR` abre las ventanas. Los caracteres llegan de a uno; hay que juntarlos en un buffer hasta el fin de línea, sin pasarse del tamaño.

```cpp comandos.ino
constexpr size_t LARGO_MAXIMO = 32;

char buffer[LARGO_MAXIMO];
size_t largo = 0;
bool descartando = false;   // la línea actual era demasiado larga

void ejecutar(const char* linea) {
  if (strncmp(linea, "REGAR ", 6) == 0) {
    char* fin;
    long segundos = strtol(linea + 6, &fin, 10);   // número después de "REGAR "
    if (fin == linea + 6 || *fin != '\0' || segundos <= 0 || segundos > 600) {
      Serial.println("uso: REGAR <segundos 1-600>");
      return;
    }
    Serial.printf("regando %ld s\n", segundos);
  } else if (strcmp(linea, "VENTILAR") == 0) {
    Serial.println("abriendo ventanas");
  } else {
    Serial.printf("comando desconocido: %s\n", linea);
  }
}

void leerSerie() {
  while (Serial.available() > 0) {
    char c = static_cast<char>(Serial.read());

    if (c == '\r') continue;                  // ignorar el retorno de carro
    if (c == '\n') {
      if (!descartando && largo > 0) {
        buffer[largo] = '\0';
        ejecutar(buffer);
      }
      largo = 0;
      descartando = false;
      continue;
    }
    if (largo < LARGO_MAXIMO - 1) {           // dejar lugar para el \0
      buffer[largo++] = c;
    } else {
      descartando = true;                     // línea demasiado larga: se ignora entera
    }
  }
}

void setup() {
  Serial.begin(115200);
}

void loop() {
  leerSerie();
}
```

`leerSerie` nunca escribe fuera del buffer: si una línea es demasiado larga, la descarta entera en lugar de ejecutar un pedazo. `strtol` convierte el número y deja en `fin` dónde terminó de leer, lo que permite rechazar `REGAR abc` o `REGAR 12x`. Todo lo que llega de afuera se valida antes de usarlo, igual que los enums de [B.10](/conceptos/b-10) y, en el backend, en [6.3](/conceptos/6-3). El mismo patrón sirve para comandos que llegan por BLE.

## Errores comunes

### Comparar cadenas de C con `==`

```cpp
// Mal
if (comando == "VENTILAR") { /* nunca entra */ }

// Bien
if (strcmp(comando, "VENTILAR") == 0) { /* ... */ }
```

Con `String` sí se puede usar `==`, porque la clase lo redefine para comparar texto. Con `char*` y `char[]`, `==` compara direcciones.

### Copiar sin límite

```cpp
// Mal
char nombre[8];
strcpy(nombre, nombreRecibidoPorBle);   // si es más largo, pisa otras variables

// Bien
strlcpy(nombre, nombreRecibidoPorBle, sizeof(nombre));
```

Un desborde así no da error: corrompe la variable que está al lado en la memoria, y el síntoma aparece en otro lugar.

### Olvidar el lugar del `\0`

```cpp
// Mal: "VENTILAR" tiene 8 caracteres y necesita 9 bytes
char comando[8];

// Bien
char comando[9];
// o mejor: un tamaño con margen
char comando[16];
```

### Guardar el `c_str()` de una `String` temporal

```cpp
// Mal
const char* ssid = WiFi.SSID().c_str();   // la String temporal se destruye en el ;
Serial.println(ssid);                     // apunta a memoria liberada

// Bien
String ssid = WiFi.SSID();
Serial.println(ssid.c_str());
```

`c_str()` es válido mientras exista la `String` de la que salió. Una `String` devuelta por una función y no guardada se destruye al terminar la línea.

## Ejercicio

Esta función arma el mensaje que el controlador envía al backend cada 30 segundos, y otra procesa la respuesta. Después de unos días el controlador empieza a reiniciarse, y además nunca reconoce la respuesta `"OK"`. Reescribí `armarMensaje` para que use un buffer fijo y avise si el mensaje quedó cortado, y corregí la comparación.

```cpp backend.ino
String armarMensaje(int invernadero, float temperatura, int humedad) {
  String m = "{\"invernadero\":";
  m += invernadero;
  m += ",\"temperatura\":";
  m += String(temperatura, 1);
  m += ",\"humedad\":";
  m += humedad;
  m += "}";
  return m;
}

void procesarRespuesta(const char* respuesta) {
  if (respuesta == "OK") {
    marcarEnviado();
  }
}
```

```cpp backend.ino
bool armarMensaje(char* destino, size_t tam, int invernadero, float temperatura, int humedad) {
  int n = snprintf(destino, tam,
                   "{\"invernadero\":%d,\"temperatura\":%.1f,\"humedad\":%d}",
                   invernadero, temperatura, humedad);
  return n > 0 && static_cast<size_t>(n) < tam;   // false si hubo error o se cortó
}

void procesarRespuesta(const char* respuesta) {
  if (strcmp(respuesta, "OK") == 0) {
    marcarEnviado();
  }
}

// Uso
void enviarEstado() {
  char mensaje[96];
  if (!armarMensaje(mensaje, sizeof(mensaje), 2, 24.5f, 41)) {
    Serial.println("mensaje demasiado largo");
    return;
  }
  // enviar(mensaje);

```

La versión con `String` hacía siete concatenaciones y un `String(temperatura, 1)` temporal cada 30 segundos, unas 3000 veces por día, todas en el heap. La nueva arma el mensaje en un arreglo del stack, sin reservas. Devolver `bool` obliga a quien llama a decidir qué hacer si el mensaje no entró, en lugar de enviar un JSON cortado que el backend rechazaría.

La comparación con `==` comparaba la dirección de `respuesta` con la del literal `"OK"`, que nunca coinciden. `strcmp` compara el texto.

## Resumen

- Una cadena de C es un arreglo de `char` terminado en `\0`. Necesita un byte más que la cantidad de caracteres.
- `strlcpy` para copiar, `strcmp` para comparar, `snprintf` para armar texto. Todas reciben el tamaño o se detienen en el `\0`; `strcpy` y `==` no sirven.
- `snprintf` devuelve cuánto habría ocupado el texto: si es mayor o igual al tamaño del buffer, se cortó.
- `String` es cómoda pero reserva memoria en el heap en cada crecimiento. En código que se repite seguido, fragmenta el heap con el tiempo.
- Regla práctica: `char[]` para lo que se repite y para lo que llega de afuera; `String` para lo que se arma pocas veces.
