`::` es el **operador de resolución de ámbito**. Se escribe entre un ámbito y un nombre para decir "este nombre, el que pertenece a este ámbito". El ámbito puede ser una clase (`Bomba::encender`), un `namespace` (`riego::actualizar`), un `enum class` (`Estado::Regando`) o el ámbito global (`::limite`). A un nombre escrito con su ámbito adelante se lo llama **nombre calificado**. Ya lo usaste muchas veces en las lecciones anteriores; esta lección junta todos sus usos y muestra cómo aprovecharlo para organizar mejor los nombres.

## Por qué te importa

A medida que el firmware del invernadero crece, hay muchos nombres que se repiten: varias clases con un método `actualizar`, varios módulos con un `Estado`, una variable global y una local que se llaman igual. `::` es lo que permite que todos convivan y que el código diga exactamente a cuál se refiere.

Además hay un caso donde `::` es indispensable y su ausencia produce un bug grave: cuando un método redefinido quiere llamar a la versión de la clase base. Sin `Base::`, el método se llama a sí mismo hasta reiniciar el ESP32.

## Paso a paso

### 1. Definir los miembros de una clase fuera de ella

```cpp Bomba.cpp
#include "Bomba.h"

Bomba::Bomba(uint8_t pin) : _pin(pin) {}

void Bomba::encender() {
  digitalWrite(_pin, LOW);
}
```

En el `.cpp`, `Bomba::` indica que estás definiendo el constructor y el método **de la clase** `Bomba` (ver [B.3](/conceptos/b-3)). Dentro de esa definición, los miembros de la clase (`_pin`) se usan sin calificar.

### 2. Miembros `static` y valores de `enum class`

```cpp
uint8_t cantidad = Nodo::cantidad;          // miembro static: pertenece a la clase (ver B.7)
bool valido = Nodo::idValido(3);            // método static
ModoRiego modo = ModoRiego::Automatico;     // valor de un enum class (ver B.10)
```

Lo que pertenece a la clase y no a un objeto, y los valores de un `enum class`, se nombran siempre con el ámbito adelante.

### 3. Namespaces

```cpp
riego::actualizar();
invernadero::protocolo::codificar(lectura, trama);   // namespaces anidados
std::min(a, b);                                       // la librería estándar vive en std
```

Cada `::` baja un nivel. Para no escribir nombres largos, se pueden usar alias o `using` en los `.cpp`, como se vio en [1.4](/conceptos/1-4).

### 4. Tipos anidados

Una clase puede declarar tipos dentro de ella: enums, structs, otras clases. Así esos tipos quedan asociados a la clase y no ocupan nombres globales:

```cpp
class ZonaRiego {
public:
  enum class Estado : uint8_t { Quieta, Regando, Bloqueada };
  struct Config {
    float humedadMinima;
    float humedadMaxima;
  };

  explicit ZonaRiego(const Config& config);
  Estado estado() const;
};

ZonaRiego::Config configTomates = {35.0f, 55.0f};
ZonaRiego tomates(configTomates);
if (tomates.estado() == ZonaRiego::Estado::Regando) { /* ... */ }
```

`ZonaRiego::Estado` y `Bomba::Estado` pueden existir a la vez sin chocar. Quien lee `ZonaRiego::Config` sabe enseguida de qué es esa configuración.

### 5. Llamar a la versión de la clase base

Cuando una clase derivada redefine un método, a veces quiere hacer algo **además** de lo que hace la base. Para llamar a la versión de la base se califica con su nombre:

```cpp
class BombaConContador : public Bomba {
public:
  using Bomba::Bomba;          // reutiliza los constructores de Bomba
  void encender() override {
    Bomba::encender();         // la versión de la base
    _arranques++;              // y lo propio
  }
private:
  uint32_t _arranques = 0;
};
```

Sin `Bomba::`, `encender()` se llamaría a sí mismo, una y otra vez, hasta agotar el stack.

### 6. El ámbito global: `::nombre`

```cpp
int limite = 100;

void probar() {
  int limite = 5;              // tapa a la global
  Serial.println(limite);      // 5
  Serial.println(::limite);    // 100: la global
}
```

`::` sin nada adelante significa "el ámbito global". Sirve cuando un nombre local tapa uno global, o para dejar claro que se llama a una función global y no a un método con el mismo nombre. Si lo necesitás seguido, probablemente conviene cambiar algún nombre.

## Ejemplos

### Ejemplo 1. Todos los usos en un sketch

```cpp usos-de-dos-puntos.ino
namespace riego {
  constexpr float HUMEDAD_MINIMA = 35.0f;
}

enum class Modo : uint8_t { Manual, Automatico };

class Nodo {
public:
  explicit Nodo(uint8_t id);
  uint8_t id() const;
  static bool idValido(uint8_t id) { return id >= 1 && id <= 8; }
  static uint8_t creados;
private:
  uint8_t _id;
};

uint8_t Nodo::creados = 0;                       // miembro static definido fuera
Nodo::Nodo(uint8_t id) : _id(id) { creados++; }  // constructor definido fuera
uint8_t Nodo::id() const { return _id; }         // método definido fuera

float umbral = 50.0f;                            // global

void setup() {
  Serial.begin(115200);
  Nodo norte(1);
  Nodo sur(2);

  float umbral = riego::HUMEDAD_MINIMA;          // local: namespace
  Modo modo = Modo::Automatico;                  // valor de enum class

  Serial.printf("nodos creados: %u\n", Nodo::creados);                 // static
  Serial.printf("id 9 válido: %d\n", Nodo::idValido(9));               // método static
  Serial.printf("umbral local %.0f, global %.0f\n", umbral, ::umbral); // 35 y 50
  Serial.printf("modo: %d\n", static_cast<int>(modo));
}

void loop() {}
```

### Ejemplo 2. Tipos anidados en una clase

La zona de riego define su propio estado y su propia configuración. Los nombres quedan agrupados con la clase que los usa.

```cpp zona-anidada.ino
class ZonaRiego {
public:
  enum class Estado : uint8_t { Quieta, Regando, Bloqueada };

  struct Config {
    float humedadMinima;
    float humedadMaxima;
  };

  ZonaRiego(const char* nombre, const Config& config) : _nombre(nombre), _config(config) {}

  void actualizar(float humedad, bool tanqueConAgua) {
    if (!tanqueConAgua) { _estado = Estado::Bloqueada; return; }
    switch (_estado) {
      case Estado::Bloqueada:
      case Estado::Quieta:
        _estado = humedad < _config.humedadMinima ? Estado::Regando : Estado::Quieta;
        break;
      case Estado::Regando:
        if (humedad > _config.humedadMaxima) _estado = Estado::Quieta;
        break;
    }
  }

  Estado estado() const { return _estado; }
  const char* nombre() const { return _nombre; }

  static const char* texto(Estado e) {
    switch (e) {
      case Estado::Quieta:    return "quieta";
      case Estado::Regando:   return "regando";
      case Estado::Bloqueada: return "bloqueada (tanque vacío)";
    }
    return "?";
  }

private:
  const char* _nombre;
  Config _config;
  Estado _estado = Estado::Quieta;
};

ZonaRiego tomates("tomates", ZonaRiego::Config{35.0f, 55.0f});

void setup() {
  Serial.begin(115200);
  tomates.actualizar(30.0f, true);
  ZonaRiego::Estado e = tomates.estado();               // desde afuera: con el ámbito
  Serial.printf("%s: %s\n", tomates.nombre(), ZonaRiego::texto(e));
}

void loop() {}
```

Dentro de la clase, `Estado` y `Config` se usan sin calificar. Desde afuera se escriben `ZonaRiego::Estado` y `ZonaRiego::Config`. Los dos `case` seguidos (`Bloqueada` y `Quieta`) sin nada en el medio comparten el mismo código: es un fallthrough intencional y explícito (ver [B.10](/conceptos/b-10)).

### Ejemplo 3. Extender un método de la base

Para diagnosticar un problema, se necesita registrar cada vez que se enciende o apaga una bomba, sin modificar la clase `Bomba`, que se usa en otros lugares. Una clase derivada agrega el registro y llama a la base para el trabajo real.

```cpp bomba-con-registro.ino
class Bomba {
public:
  explicit Bomba(uint8_t pin) : _pin(pin) {}
  virtual ~Bomba() = default;
  void begin() { pinMode(_pin, OUTPUT); apagar(); }
  virtual void encender() { digitalWrite(_pin, LOW); _encendida = true; }
  virtual void apagar()   { digitalWrite(_pin, HIGH); _encendida = false; }
  bool encendida() const { return _encendida; }
protected:
  uint8_t _pin;
private:
  bool _encendida = false;
};

class BombaConRegistro : public Bomba {
public:
  using Bomba::Bomba;                 // los mismos constructores que Bomba

  void encender() override {
    if (!encendida()) _inicioMs = millis();
    Bomba::encender();                // el trabajo real, en la base
    Serial.printf("bomba %u: ON\n", _pin);
  }

  void apagar() override {
    bool estabaEncendida = encendida();
    Bomba::apagar();
    if (estabaEncendida) {
      Serial.printf("bomba %u: OFF tras %lu s\n", _pin,
                    static_cast<unsigned long>((millis() - _inicioMs) / 1000));
    }
  }

private:
  uint32_t _inicioMs = 0;
};

BombaConRegistro bomba(26);

void setup() {
  Serial.begin(115200);
  bomba.begin();
  bomba.encender();
}

void loop() {
  static bool apagada = false;
  if (!apagada && millis() > 3000) {
    bomba.apagar();
    apagada = true;
  }
}
```

`Bomba::encender()` y `Bomba::apagar()` ejecutan la lógica de la base; la derivada solo agrega el registro alrededor. `using Bomba::Bomba;` hereda los constructores, así `BombaConRegistro bomba(26);` funciona sin escribir uno nuevo. Fijate en `begin()`: llama a `apagar()`, que es virtual, así que en una `BombaConRegistro` se ejecuta la versión con registro.

## Errores comunes

### Llamarse a sí mismo en lugar de a la base

```cpp
// Mal: recursión infinita
void encender() override {
  registrar();
  encender();
}

// Bien
void encender() override {
  registrar();
  Bomba::encender();
}
```

### Olvidar el ámbito al definir fuera de la clase

```cpp
// Mal: define una función global, no el método
void actualizar() { /* usa _estado: no compila */ }

// Bien
void ZonaRiego::actualizar() { /* ... */ }
```

### Tipos anidados usados sin ámbito desde afuera

```cpp
// Mal: fuera de la clase, Estado no existe
Estado e = zona.estado();

// Bien
ZonaRiego::Estado e = zona.estado();
// o, cuando el tipo es obvio:
auto e = zona.estado();
```

`auto` le pide al compilador que deduzca el tipo de la expresión. Es cómodo con tipos de nombre largo, pero no abuses: cuando el tipo ayuda a entender el código, escribilo.

### Tapar nombres sin darte cuenta

```cpp
// Mal: el parámetro tapa al miembro con el mismo nombre
void fijarUmbral(float umbral) { umbral = umbral; }   // se asigna a sí mismo

// Bien: nombres distintos (por eso la convención del guion bajo en los miembros)
void fijarUmbral(float umbral) { _umbral = umbral; }
```

Este caso no se arregla con `::`. Usá nombres distintos para miembros y parámetros.

## Ejercicio

Esta clase quiere agregar a un sensor de temperatura una corrección de calibración (sumar un desvío fijo), sin modificar la clase original. Al probarla, el ESP32 se reinicia apenas se lee la temperatura. Además, desde `setup()` no compila la línea que usa el tipo `Unidad`. Corregí los dos problemas.

```cpp sensor-corregido.ino
class SensorTemperatura {
public:
  enum class Unidad : uint8_t { Celsius, Fahrenheit };
  virtual float leer() { return 24.5f; }   // lectura real simplificada
  virtual ~SensorTemperatura() = default;
};

class SensorCalibrado : public SensorTemperatura {
public:
  explicit SensorCalibrado(float desvio) : _desvio(desvio) {}
  float leer() override { return leer() + _desvio; }
private:
  float _desvio;
};

SensorCalibrado sensor(-0.8f);

void setup() {
  Serial.begin(115200);
  Unidad u = Unidad::Celsius;
  Serial.println(sensor.leer());
}

void loop() {}
```

```cpp sensor-corregido.ino
class SensorCalibrado : public SensorTemperatura {
public:
  explicit SensorCalibrado(float desvio) : _desvio(desvio) {}
  float leer() override { return SensorTemperatura::leer() + _desvio; }
private:
  float _desvio;
};

SensorCalibrado sensor(-0.8f);

void setup() {
  Serial.begin(115200);
  SensorTemperatura::Unidad u = SensorTemperatura::Unidad::Celsius;
  (void)u;   // la variable no se usa en este ejemplo
  Serial.println(sensor.leer());   // 23.70
}

void loop() {}
```

`leer()` sin calificar, dentro de `SensorCalibrado::leer`, es una llamada a sí mismo: recursión infinita hasta desbordar el stack, y el reinicio. Con `SensorTemperatura::leer()` se llama a la lectura de la base y se le suma el desvío. `Unidad` está declarado dentro de `SensorTemperatura`, así que desde afuera se escribe `SensorTemperatura::Unidad`. El `(void)u;` evita la advertencia por una variable sin usar.

## Resumen

- `::` dice a qué ámbito pertenece un nombre: una clase, un namespace, un `enum class` o el ámbito global.
- En los `.cpp`, `Clase::metodo` define los miembros de una clase.
- Los miembros `static`, los valores de `enum class` y los tipos anidados se nombran con su ámbito: `Nodo::cantidad`, `Modo::Manual`, `ZonaRiego::Estado`.
- En un método redefinido, `Base::metodo()` llama a la versión de la base. Sin eso, el método se llama a sí mismo.
- `::nombre` se refiere al ámbito global, cuando un nombre local lo tapa.
