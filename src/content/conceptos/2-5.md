En [0.8](/conceptos/0-8) viste cómo registrar una interrupción y las reglas de una ISR: corta, en IRAM, sin `Serial` ni `delay`. En [B.11](/conceptos/b-11), cómo compartir datos con ella. Esta lección es sobre **diseño**: cómo se conecta una interrupción con el resto del firmware para que el trabajo pesado se haga en el lugar correcto. La idea central es el **procesamiento diferido**: la ISR solo detecta el evento y despierta a una tarea; la tarea hace el trabajo, con todo el tiempo y todas las funciones que necesite.

## Por qué te importa

Con un par de contadores, alcanza con lo que viste en la Parte 0. Pero el controlador del invernadero tiene más: un botón de emergencia que tiene que detener todo en milisegundos, un anemómetro del que interesa la ráfaga máxima, un sensor que avisa por un pin cuando tiene un dato listo, y lecturas periódicas que necesitan un ritmo exacto. Cada caso pide algo distinto: reaccionar ya, medir tiempos con precisión, o muestrear a intervalos fijos.

Hacer todo eso dentro de la ISR es el error más común: el código funciona en las pruebas y falla de forma intermitente en el campo. Hacerlo todo en `loop()` con banderas que se revisan "cuando se pueda" agrega demoras de decenas de milisegundos. El procesamiento diferido con FreeRTOS da lo mejor de los dos: respuesta inmediata y trabajo en un contexto normal.

## Paso a paso

### 1. El patrón: la ISR detecta, la tarea trabaja

```text
hardware ──► ISR (microsegundos)              ──► tarea (todo el tiempo que haga falta)
             anota el momento, despierta           lee el sensor por I2C, decide,
                                                   avisa por la red, escribe en la SD
```

La ISR hace tres cosas como mucho: anotar datos mínimos (un momento, un contador), avisar a la tarea, y volver. La tarea está bloqueada esperando ese aviso, sin consumir procesador, y se despierta apenas llega.

### 2. Despertar a una tarea desde la ISR

FreeRTOS tiene versiones especiales de sus funciones para usar dentro de una interrupción, terminadas en `FromISR`. La más liviana para "avisar que pasó algo" es la **notificación de tarea**:

```cpp
TaskHandle_t tareaEmergencia = nullptr;

void IRAM_ATTR alPresionarEmergencia() {
  BaseType_t hayQueCambiar = pdFALSE;
  vTaskNotifyGiveFromISR(tareaEmergencia, &hayQueCambiar);
  if (hayQueCambiar) portYIELD_FROM_ISR();
}

void tareaDeEmergencia(void*) {
  for (;;) {
    ulTaskNotifyTake(pdTRUE, portMAX_DELAY);   // dormir hasta la notificación
    // detener la bomba, cerrar todo, avisar...
  }
}
```

`hayQueCambiar` vuelve en `pdTRUE` si la tarea despertada tiene más prioridad que la que estaba corriendo. En ese caso, `portYIELD_FROM_ISR()` hace que el sistema cambie a ella apenas termina la ISR, en lugar de esperar al próximo cambio de tarea programado. Para mandar datos, no solo un aviso, se usa `xQueueSendFromISR` con una cola (ver [2.4](/conceptos/2-4)), con el mismo patrón de `hayQueCambiar`.

### 3. Medir tiempos en la ISR

La ISR es el mejor lugar para anotar **cuándo** pasó algo: cualquier demora posterior no cambia el momento anotado. Para medir el tiempo entre pulsos (y de ahí una frecuencia o una velocidad instantánea), la ISR guarda `micros()` y la tarea hace las cuentas:

```cpp
void IRAM_ATTR alPulso() {
  uint32_t ahora = micros();
  uint32_t intervalo = ahora - ultimoPulsoUs;   // solo la ISR toca ultimoPulsoUs
  ultimoPulsoUs = ahora;
  // pasar "intervalo" a la tarea por una cola
}
```

### 4. Temporizadores de hardware

Para hacer algo a intervalos exactos (muestrear cada 10 ms, por ejemplo), un temporizador de hardware genera una interrupción periódica sin que el código tenga que vigilar `millis()`. En el core 3.x de Arduino-ESP32:

```cpp
hw_timer_t* temporizador = timerBegin(1000000);          // contador a 1 MHz (1 tick = 1 µs)
timerAttachInterrupt(temporizador, &alTick);             // ISR a llamar
timerAlarm(temporizador, 10000, true, 0);                // cada 10.000 µs, repetir siempre
```

La ISR del temporizador sigue las mismas reglas: no lee el ADC ni el I2C, solo despierta a la tarea que muestrea. Así el muestreo queda a intervalos exactos aunque `loop()` esté ocupado.

### 5. Lo que nunca va en una ISR

| No | Por qué | En su lugar |
|---|---|---|
| `Serial`, `printf` | pueden bloquear, usan locks | contar o anotar; imprimir en la tarea |
| `delay`, esperas | bloquean el sistema | comparar tiempos (antirrebote) |
| `analogRead`, I2C, SPI | usan drivers que esperan | despertar a una tarea que lea |
| `new`, `String`, `malloc` | el heap usa locks | buffers fijos |
| funciones de FreeRTOS sin `FromISR` | pueden bloquear o corromper el estado | las versiones `FromISR` |
| `float` en el ESP32 clásico | no está garantizado en ISR | enteros, y la cuenta con decimales en la tarea |

### 6. Protegerse de las tormentas de interrupciones

Una línea con ruido puede disparar la interrupción miles de veces por segundo. Cada disparo cuesta poco, pero miles se notan, y los conteos son falsos. Tres defensas:

- **Hardware**: pull-ups firmes (no solo los internos), un capacitor chico para filtrar, cables cortos o blindados.
- **Antirrebote en la ISR**: ignorar disparos demasiado cercanos al anterior, comparando con `micros()`.
- **Vigilancia**: si en un segundo llegan muchos más pulsos que los físicamente posibles, marcar el sensor como sospechoso y avisar.

## Ejemplos

### Ejemplo 1. Botón de emergencia con respuesta inmediata

El botón de emergencia tiene que apagar la bomba en milisegundos, aunque `loop()` esté dibujando la pantalla. La ISR notifica a una tarea de prioridad alta que hace todo lo necesario.

```cpp emergencia-tarea.ino
constexpr uint8_t PIN_EMERGENCIA = 4;
constexpr uint8_t PIN_BOMBA = 26;

TaskHandle_t tareaEmergencia = nullptr;
volatile uint32_t ultimaPulsacionMs = 0;
volatile bool enEmergencia = false;

void IRAM_ATTR alPresionarEmergencia() {
  uint32_t ahora = millis();
  if (ahora - ultimaPulsacionMs < 200) return;           // antirrebote
  ultimaPulsacionMs = ahora;

  BaseType_t hayQueCambiar = pdFALSE;
  vTaskNotifyGiveFromISR(tareaEmergencia, &hayQueCambiar);
  if (hayQueCambiar) portYIELD_FROM_ISR();
}

void tareaDeEmergencia(void*) {
  for (;;) {
    ulTaskNotifyTake(pdTRUE, portMAX_DELAY);              // duerme hasta que se presione
    digitalWrite(PIN_BOMBA, HIGH);                        // relé activo en bajo: apagar
    enEmergencia = true;
    Serial.printf("EMERGENCIA a los %lu ms: bomba apagada\n", millis());
    // acá: cerrar válvulas, encolar el aviso al backend...
  }
}

void setup() {
  Serial.begin(115200);
  digitalWrite(PIN_BOMBA, HIGH);
  pinMode(PIN_BOMBA, OUTPUT);
  pinMode(PIN_EMERGENCIA, INPUT_PULLUP);

  xTaskCreatePinnedToCore(tareaDeEmergencia, "emergencia", 4096, nullptr,
                          configMAX_PRIORITIES - 2, &tareaEmergencia, 1);
  attachInterrupt(digitalPinToInterrupt(PIN_EMERGENCIA), alPresionarEmergencia, FALLING);
}

void loop() {
  if (!enEmergencia) {
    digitalWrite(PIN_BOMBA, LOW);        // riego normal (simplificado)
  }
  delay(30);                             // simula un loop() ocupado dibujando
}
```

Aunque `loop()` esté en medio de su trabajo, la tarea de emergencia tiene prioridad más alta, así que corre apenas la ISR la despierta: la bomba se apaga en microsegundos, no en los 30 ms que tarda una vuelta de `loop()`. La tarea se crea antes de registrar la interrupción, para que `tareaEmergencia` ya tenga un valor cuando la ISR lo use. En el firmware completo, `loop()` consultaría `enEmergencia` a través del ciclo de riego, que pasaría a un estado bloqueado (ver [2.2](/conceptos/2-2)).

### Ejemplo 2. Ráfagas de viento con marcas de tiempo

Para decidir si cerrar las ventanas cenitales, no alcanza con la velocidad media del viento: importa la ráfaga máxima. La ISR mide el tiempo entre pulsos del anemómetro y lo manda por una cola; la tarea calcula la velocidad de cada vuelta y guarda la máxima.

```cpp rafagas.ino
#include <atomic>

constexpr uint8_t PIN_ANEMOMETRO = 27;
constexpr float KMH_POR_HZ = 2.4f;
constexpr uint32_t INTERVALO_MINIMO_US = 5000;   // más rápido que esto es ruido

QueueHandle_t colaIntervalos = nullptr;
volatile uint32_t ultimoPulsoUs = 0;
std::atomic<uint32_t> descartados{0};   // ++ indivisible (ver B.11)

void IRAM_ATTR alPulso() {
  uint32_t ahora = micros();
  uint32_t intervalo = ahora - ultimoPulsoUs;
  if (intervalo < INTERVALO_MINIMO_US) return;   // rebote o ruido
  ultimoPulsoUs = ahora;

  BaseType_t hayQueCambiar = pdFALSE;
  if (xQueueSendFromISR(colaIntervalos, &intervalo, &hayQueCambiar) != pdTRUE) {
    descartados++;
  }
  if (hayQueCambiar) portYIELD_FROM_ISR();
}

void tareaViento(void*) {
  float rafagaMaxima = 0.0f;
  uint32_t inicioVentana = millis();
  uint32_t intervaloUs;

  for (;;) {
    if (xQueueReceive(colaIntervalos, &intervaloUs, pdMS_TO_TICKS(1000)) == pdTRUE) {
      float hz = 1000000.0f / intervaloUs;           // vueltas por segundo en esta vuelta
      float kmh = hz * KMH_POR_HZ;
      if (kmh > rafagaMaxima) rafagaMaxima = kmh;
    }
    if (millis() - inicioVentana >= 60000) {         // cada minuto, informar y reiniciar
      Serial.printf("ráfaga máxima del último minuto: %.1f km/h\n", rafagaMaxima);
      rafagaMaxima = 0.0f;
      inicioVentana = millis();
    }
  }
}

void setup() {
  Serial.begin(115200);
  colaIntervalos = xQueueCreate(64, sizeof(uint32_t));
  xTaskCreatePinnedToCore(tareaViento, "viento", 4096, nullptr, 2, nullptr, 1);
  pinMode(PIN_ANEMOMETRO, INPUT_PULLUP);
  attachInterrupt(digitalPinToInterrupt(PIN_ANEMOMETRO), alPulso, FALLING);
}

void loop() {}
```

La ISR trabaja solo con enteros: mide el intervalo, filtra el ruido y lo encola. La división en `float` y la comparación se hacen en la tarea. Como la cola guarda hasta 64 intervalos, aunque la tarea se atrase un momento, no se pierde ninguno. `xQueueReceive` con un tiempo máximo de un segundo permite que la tarea informe cada minuto aunque no sople viento.

### Ejemplo 3. Muestreo a intervalos exactos con un temporizador

El controlador quiere muestrear el sensor de corriente de la bomba cada 10 ms exactos para detectar si se trabó (una bomba trabada consume de más). Un temporizador de hardware marca el ritmo; la ISR solo notifica, y la tarea lee el ADC.

```cpp muestreo-timer.ino
constexpr uint8_t PIN_CORRIENTE = 35;   // ADC1

hw_timer_t* temporizador = nullptr;
TaskHandle_t tareaMuestreo = nullptr;

void IRAM_ATTR alTick() {
  BaseType_t hayQueCambiar = pdFALSE;
  vTaskNotifyGiveFromISR(tareaMuestreo, &hayQueCambiar);
  if (hayQueCambiar) portYIELD_FROM_ISR();
}

void tareaDeMuestreo(void*) {
  uint32_t suma = 0;
  uint32_t maximo = 0;
  int muestras = 0;

  for (;;) {
    ulTaskNotifyTake(pdTRUE, portMAX_DELAY);           // cada 10 ms exactos
    uint32_t mv = analogReadMilliVolts(PIN_CORRIENTE); // fuera de la ISR: permitido
    suma += mv;
    if (mv > maximo) maximo = mv;

    if (++muestras == 100) {                           // cada segundo
      Serial.printf("corriente: prom %u mV, pico %u mV\n",
                    static_cast<unsigned>(suma / muestras), static_cast<unsigned>(maximo));
      // acá: si el promedio supera el umbral de bomba trabada, avisar al control
      suma = 0;
      maximo = 0;
      muestras = 0;
    }
  }
}

void setup() {
  Serial.begin(115200);
  xTaskCreatePinnedToCore(tareaDeMuestreo, "muestreo", 4096, nullptr, 3, &tareaMuestreo, 1);

  temporizador = timerBegin(1000000);              // 1 MHz: cada tick es 1 µs
  timerAttachInterrupt(temporizador, &alTick);
  timerAlarm(temporizador, 10000, true, 0);        // cada 10.000 µs, repetir siempre
}

void loop() {
  delay(50);   // simula un loop() ocupado: el muestreo no se entera
}
```

El ritmo de 10 ms lo da el hardware, no depende de cuánto tarde `loop()`. La lectura del ADC, que no se puede hacer en una ISR, se hace en la tarea, que se despierta enseguida porque tiene prioridad alta. Las API `timerBegin`, `timerAttachInterrupt` y `timerAlarm` son las del core 3.x; en el 2.x se usaban otras (`timerBegin(0, 80, true)`, `timerAlarmWrite`), como pasa con el PWM (ver [0.13](/conceptos/0-13)).

## Errores comunes

### Trabajo pesado en la ISR

```cpp
// Mal
void IRAM_ATTR alDatoListo() {
  Wire.requestFrom(0x44, 6);       // I2C dentro de la ISR
  procesarLectura();
}

// Bien
void IRAM_ATTR alDatoListo() {
  BaseType_t hayQueCambiar = pdFALSE;
  vTaskNotifyGiveFromISR(tareaSensor, &hayQueCambiar);
  if (hayQueCambiar) portYIELD_FROM_ISR();
}
```

### Funciones de FreeRTOS sin `FromISR`

```cpp
// Mal
void IRAM_ATTR isr() { xQueueSend(cola, &dato, 0); }

// Bien
void IRAM_ATTR isr() {
  BaseType_t hayQueCambiar = pdFALSE;
  xQueueSendFromISR(cola, &dato, &hayQueCambiar);
  if (hayQueCambiar) portYIELD_FROM_ISR();
}
```

### Usar la tarea antes de crearla

Si `attachInterrupt` se llama antes de `xTaskCreatePinnedToCore`, una interrupción temprana usa un `TaskHandle_t` que todavía vale `nullptr`. Primero la tarea, después la interrupción.

### Olvidar `portYIELD_FROM_ISR`

Sin él, la tarea despertada corre recién en el próximo tick. Para la mayoría de los casos no es grave, pero en una emergencia es una demora gratuita.

### Confiar en una línea ruidosa

Un sensor de pulsos con cable largo y sin filtrado puede generar miles de interrupciones falsas. Filtrá en hardware, descartá intervalos imposibles en la ISR y vigilá la frecuencia máxima.

## Ejercicio

Un sensor de luz por I2C tiene un pin que baja cuando termina una medición. El código actual lee el sensor dentro de la ISR, y el ESP32 se reinicia de vez en cuando. Reescribilo con procesamiento diferido: la ISR notifica a una tarea, y la tarea lee el sensor y deja el valor disponible para `loop()`.

```cpp luz-isr.ino
volatile float lux = 0.0f;

void alMedicionLista() {
  Wire.beginTransmission(0x23);
  Wire.requestFrom(0x23, 2);
  uint16_t crudo = (Wire.read() << 8) | Wire.read();
  lux = crudo / 1.2f;
  Serial.println(lux);
}

void setup() {
  Wire.begin(21, 22);
  pinMode(18, INPUT_PULLUP);
  attachInterrupt(digitalPinToInterrupt(18), alMedicionLista, FALLING);
}
```

<summary>Ver solución</summary>

```cpp luz-diferida.ino
#include <Wire.h>

TaskHandle_t tareaLuz = nullptr;
portMUX_TYPE candadoLux = portMUX_INITIALIZER_UNLOCKED;
float lux = 0.0f;

void IRAM_ATTR alMedicionLista() {
  BaseType_t hayQueCambiar = pdFALSE;
  vTaskNotifyGiveFromISR(tareaLuz, &hayQueCambiar);
  if (hayQueCambiar) portYIELD_FROM_ISR();
}

void tareaDeLuz(void*) {
  for (;;) {
    ulTaskNotifyTake(pdTRUE, portMAX_DELAY);
    if (Wire.requestFrom(0x23, 2) != 2) continue;      // el sensor no respondió
    uint16_t crudo = (Wire.read() << 8) | Wire.read();
    float valor = crudo / 1.2f;
    portENTER_CRITICAL(&candadoLux);
    lux = valor;
    portEXIT_CRITICAL(&candadoLux);
  }
}

float leerLux() {
  portENTER_CRITICAL(&candadoLux);
  float copia = lux;
  portEXIT_CRITICAL(&candadoLux);
  return copia;
}

void setup() {
  Serial.begin(115200);
  Wire.begin(21, 22);
  xTaskCreatePinnedToCore(tareaDeLuz, "luz", 4096, nullptr, 2, &tareaLuz, 1);
  pinMode(18, INPUT_PULLUP);
  attachInterrupt(digitalPinToInterrupt(18), alMedicionLista, FALLING);
}

void loop() {
  static uint32_t ultimo = 0;
  if (millis() - ultimo >= 2000) {
    ultimo = millis();
    Serial.printf("luz: %.0f lux\n", leerLux());
  }
}
```

La ISR original hacía una transacción I2C, cuentas con `float` y un `Serial.println`, sin `IRAM_ATTR`: cualquiera de esas cosas puede reiniciar el ESP32. Ahora la ISR solo despierta a la tarea, y la tarea hace todo lo demás en un contexto normal. Además, la tarea chequea que el sensor haya respondido. Si otra tarea también usa el bus I2C, habría que agregar el mutex de [2.4](/conceptos/2-4).

</details>

## Resumen

- Procesamiento diferido: la ISR detecta y despierta; una tarea hace el trabajo.
- Desde una ISR solo se usan funciones `FromISR` (`vTaskNotifyGiveFromISR`, `xQueueSendFromISR`), seguidas de `portYIELD_FROM_ISR()` si corresponde.
- La ISR es el lugar para anotar *cuándo* pasó algo; las cuentas, en la tarea.
- Un temporizador de hardware da un ritmo exacto; su ISR también solo despierta a una tarea.
- Nada de `Serial`, `delay`, I2C, ADC, heap ni `float` dentro de una ISR. Y cuidado con las líneas ruidosas: filtrá y vigilá la frecuencia.
