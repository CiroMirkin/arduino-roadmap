Un `enum` le pone nombre a un conjunto cerrado de valores posibles: los modos de riego, los estados de una conexión, los tipos de error. En lugar de `modo = 2`, escribís `modo = Modo::Automatico`. **`enum class`** es la versión moderna: sus nombres no se mezclan con el resto del código y no se convierte en número sin que lo pidas. Junto con `switch`, es la base de las máquinas de estados que ordenan un firmware.

## Por qué te importa

Sin enums, el código del controlador termina lleno de números con significado secreto: `if (estado == 3)`, `modoRiego = 1`. Nadie recuerda si el 3 era "conectando" o "error", y nada impide escribir `estado = 7` cuando solo existen cinco estados.

El `enum` clásico resuelve los nombres pero trae sus propios problemas. Sus valores se vuelcan al resto del código, así que dos enums con un valor `ERROR` chocan, y el código antiguo agrega prefijos a mano (`ESTADO_ERROR`, `RIEGO_ERROR`). Además, cualquier `enum` se compara con cualquier otro como si fueran números, y `if (estadoWifi == MODO_MANUAL)` compila aunque no tenga sentido. `enum class` elimina los dos problemas.

## Paso a paso

### 1. Del número mágico al `enum`

```cpp
// Sin enum: ¿qué es 2?
int modoRiego = 2;
if (modoRiego == 2) { regarSegunHumedad(); }

// Con enum
enum class ModoRiego { Apagado, Manual, Automatico };
ModoRiego modo = ModoRiego::Automatico;
if (modo == ModoRiego::Automatico) { regarSegunHumedad(); }
```

Un `enum class` define un tipo nuevo con una lista de valores posibles. Por dentro siguen siendo enteros (`Apagado` es 0, `Manual` es 1, `Automatico` es 2), pero el código los trata por nombre.

### 2. El `enum` clásico y sus problemas

```cpp
enum EstadoWifi { DESCONECTADO, CONECTANDO, CONECTADO };
enum ModoRiego  { APAGADO, MANUAL, AUTOMATICO };

EstadoWifi wifi = CONECTADO;    // los nombres se usan sin prefijo
int n = wifi;                   // se convierte a int solo: n = 2
if (wifi == AUTOMATICO) { }     // compila: compara 2 == 2
```

En un `enum` clásico (sin `class`), los nombres de los valores quedan sueltos en el alcance que lo contiene. Si otro enum o una librería usa `CONECTADO` o `ERROR`, chocan. Y los valores se convierten a `int` en silencio, así que se pueden comparar enums que no tienen nada que ver.

### 3. `enum class`: nombres con alcance y sin conversiones

```cpp
enum class EstadoWifi { Desconectado, Conectando, Conectado };
enum class ModoRiego  { Apagado, Manual, Automatico };

EstadoWifi wifi = EstadoWifi::Conectado;   // siempre con el nombre del tipo
// int n = wifi;                           // no compila
int n = static_cast<int>(wifi);            // 2: la conversión se pide
// if (wifi == ModoRiego::Automatico) { }  // no compila: tipos distintos
```

Los valores viven dentro del tipo (`EstadoWifi::Conectado`), así que dos enums pueden tener valores con el mismo nombre sin problema. Ya no hacen falta prefijos. Y convertir a número exige un `static_cast` (ver [B.1](/conceptos/b-1)), que deja la intención a la vista.

### 4. El tipo subyacente

```cpp
enum class ModoRiego : uint8_t { Apagado, Manual, Automatico };
```

Lo que va después de los dos puntos es el tipo entero que usa el enum por dentro. Por defecto es `int` (4 bytes en el ESP32). Con `: uint8_t` ocupa un byte, lo que importa cuando lo guardás en la memoria flash o lo mandás por BLE.

También podés fijar el número de cada valor. Hacelo cuando el número tiene significado afuera del programa, por ejemplo en un protocolo:

```cpp
enum class ErrorNodo : uint8_t {
  Ninguno = 0,
  SensorDesconectado = 1,
  BateriaBaja = 2,
  LecturaFueraDeRango = 3,
};
```

Así, agregar un valor nuevo en el medio no cambia el número de los demás.

### 5. `switch` con `enum class`

```cpp
void aplicarModo(ModoRiego modo) {
  switch (modo) {
    case ModoRiego::Apagado:
      apagarBomba();
      break;
    case ModoRiego::Manual:
      // la bomba la controla el operario desde la pantalla
      break;
    case ModoRiego::Automatico:
      regarSegunHumedad();
      break;
  }
}
```

`switch` salta al `case` que coincide con el valor. Dos detalles importan:

- **`break`**: termina el `switch`. Sin él, la ejecución sigue con el `case` siguiente (*fallthrough*). Casi nunca es lo que querés.
- **Cubrir todos los valores**: si no ponés `default` y te olvidás de un valor, el compilador avisa (`enumeration value 'X' not handled in switch`). Esa advertencia es muy útil: cuando agregás un modo nuevo, te lleva a cada `switch` que hay que actualizar. Un `default` la apaga, así que evitalo con enums salvo que de verdad quieras tratar igual a todos los demás valores.

### 6. Mostrar un enum como texto

Un enum no sabe su propio nombre. Para mostrarlo en la pantalla o en el monitor serie, escribí una función:

```cpp
const char* nombre(ModoRiego modo) {
  switch (modo) {
    case ModoRiego::Apagado:    return "apagado";
    case ModoRiego::Manual:     return "manual";
    case ModoRiego::Automatico: return "automático";
  }
  return "?";   // no debería pasar nunca
}

Serial.println(nombre(modo));
```

Cada `case` devuelve directamente, así que no hace falta `break`. El `return "?"` al final cubre el caso de un valor inválido (ver el tercer error común) y evita una advertencia del compilador.

## Ejemplos

### Ejemplo 1. Los modos de riego

```cpp modos.ino
enum class ModoRiego : uint8_t { Apagado, Manual, Automatico };

const char* nombre(ModoRiego modo) {
  switch (modo) {
    case ModoRiego::Apagado:    return "apagado";
    case ModoRiego::Manual:     return "manual";
    case ModoRiego::Automatico: return "automático";
  }
  return "?";
}

ModoRiego siguiente(ModoRiego modo) {
  switch (modo) {
    case ModoRiego::Apagado:    return ModoRiego::Manual;
    case ModoRiego::Manual:     return ModoRiego::Automatico;
    case ModoRiego::Automatico: return ModoRiego::Apagado;
  }
  return ModoRiego::Apagado;
}

ModoRiego modo = ModoRiego::Apagado;

void setup() {
  Serial.begin(115200);
  for (int i = 0; i < 4; i++) {
    Serial.printf("%s (%d)\n", nombre(modo), static_cast<int>(modo));
    modo = siguiente(modo);
  }
  // apagado (0)
  // manual (1)
  // automático (2)
  // apagado (0)
}

void loop() {}
```

`siguiente` es lo que haría un botón de "cambiar modo" en la pantalla del controlador: recorre los modos en orden y vuelve al principio.

### Ejemplo 2. La conexión WiFi del controlador

El controlador tiene que conectarse al WiFi sin bloquear el resto del programa, y reintentar si la conexión se cae. Un `enum class` con un `switch` modela los estados de la conexión.

```cpp wifi.ino
#include <WiFi.h>

enum class EstadoWifi : uint8_t { Desconectado, Conectando, Conectado, EsperandoReintento };

constexpr uint32_t TIEMPO_MAXIMO_CONEXION_MS = 15000;
constexpr uint32_t ESPERA_REINTENTO_MS = 30000;

EstadoWifi estadoWifi = EstadoWifi::Desconectado;
uint32_t momentoEstado = 0;

void cambiarA(EstadoWifi nuevo) {
  estadoWifi = nuevo;
  momentoEstado = millis();
}

void actualizarWifi() {
  uint32_t enEsteEstado = millis() - momentoEstado;

  switch (estadoWifi) {
    case EstadoWifi::Desconectado:
      WiFi.begin("invernadero", "clave-del-wifi");
      cambiarA(EstadoWifi::Conectando);
      break;

    case EstadoWifi::Conectando:
      if (WiFi.status() == WL_CONNECTED) {
        Serial.println("WiFi conectado");
        cambiarA(EstadoWifi::Conectado);
      } else if (enEsteEstado > TIEMPO_MAXIMO_CONEXION_MS) {
        WiFi.disconnect();
        cambiarA(EstadoWifi::EsperandoReintento);
      }
      break;

    case EstadoWifi::Conectado:
      if (WiFi.status() != WL_CONNECTED) {
        Serial.println("WiFi perdido");
        cambiarA(EstadoWifi::EsperandoReintento);
      }
      break;

    case EstadoWifi::EsperandoReintento:
      if (enEsteEstado > ESPERA_REINTENTO_MS) {
        cambiarA(EstadoWifi::Desconectado);
      }
      break;
  }
}

void setup() {
  Serial.begin(115200);
  WiFi.mode(WIFI_STA);
}

void loop() {
  actualizarWifi();
  // el riego y la ventilación siguen funcionando mientras tanto
}
```

Cada llamada a `actualizarWifi()` mira en qué estado está la conexión, hace lo que corresponde a ese estado y, si hace falta, pasa a otro. Nunca se queda esperando, así que el resto del `loop()` sigue funcionando aunque el WiFi tarde. Las máquinas de estados como esta son el tema de [2.2](/conceptos/2-2); acá lo importante es que cada estado tiene un nombre y el `switch` los cubre a todos. En un firmware real, el nombre de la red y la clave no van escritos en el código, como se explica en [6.1](/conceptos/6-1).

### Ejemplo 3. Códigos de error que viajan por BLE

Cada nodo sensor manda un byte de estado junto con sus lecturas. El controlador lo recibe y tiene que convertirlo en un `ErrorNodo`, pero un byte que llega de afuera puede ser cualquier cosa: un dato corrupto, o un código nuevo de un nodo con firmware más reciente.

```cpp errores-nodo.ino
enum class ErrorNodo : uint8_t {
  Ninguno = 0,
  SensorDesconectado = 1,
  BateriaBaja = 2,
  LecturaFueraDeRango = 3,
  Desconocido = 255,          // para lo que no reconocemos
};

constexpr uint8_t ULTIMO_CODIGO_CONOCIDO = 3;

// En el nodo: el enum se convierte en un byte para enviarlo
uint8_t aByte(ErrorNodo error) {
  return static_cast<uint8_t>(error);
}

// En el controlador: un byte recibido se valida antes de convertirlo
ErrorNodo desdeByte(uint8_t codigo) {
  if (codigo > ULTIMO_CODIGO_CONOCIDO) {
    return ErrorNodo::Desconocido;
  }
  return static_cast<ErrorNodo>(codigo);
}

const char* describir(ErrorNodo error) {
  switch (error) {
    case ErrorNodo::Ninguno:             return "ok";
    case ErrorNodo::SensorDesconectado:  return "sensor desconectado";
    case ErrorNodo::BateriaBaja:         return "batería baja";
    case ErrorNodo::LecturaFueraDeRango: return "lectura fuera de rango";
    case ErrorNodo::Desconocido:         return "código desconocido";
  }
  return "?";
}

void setup() {
  Serial.begin(115200);
  uint8_t recibidos[] = {0, 2, 7};
  for (uint8_t codigo : recibidos) {
    Serial.printf("%d -> %s\n", codigo, describir(desdeByte(codigo)));
  }
  // 0 -> ok
  // 2 -> batería baja
  // 7 -> código desconocido
}

void loop() {}
```

Los números se fijan explícitamente porque son parte del protocolo entre el nodo y el controlador: si se cambian, los dos firmwares dejan de entenderse. `desdeByte` es el único lugar donde un número se convierte en `ErrorNodo`, y valida antes de convertir. Después de ese punto, el resto del código puede confiar en que el valor es uno de los declarados.

## Errores comunes

### Un `default` que esconde un caso nuevo

```cpp
// Mal: al agregar ModoRiego::Programado, este switch lo trata como "apagado" sin avisar
switch (modo) {
  case ModoRiego::Automatico: regarSegunHumedad(); break;
  case ModoRiego::Manual: break;
  default: apagarBomba(); break;
}

// Bien: todos los casos explícitos; un valor nuevo genera una advertencia acá
switch (modo) {
  case ModoRiego::Apagado:    apagarBomba(); break;
  case ModoRiego::Manual:     break;
  case ModoRiego::Automatico: regarSegunHumedad(); break;
}
```

Activá las advertencias en el Arduino IDE (Preferencias, *Compiler warnings: All*) para ver los casos sin cubrir.

### Olvidar el `break`

```cpp
// Mal
case EstadoWifi::Conectando:
  esperarConexion();
case EstadoWifi::Conectado:        // también se ejecuta cuando está conectando
  enviarLecturas();
  break;

// Bien
case EstadoWifi::Conectando:
  esperarConexion();
  break;
case EstadoWifi::Conectado:
  enviarLecturas();
  break;
```

Si alguna vez querés el fallthrough a propósito, marcalo con `[[fallthrough]];` para que el compilador y quien lea sepan que no es un olvido.

### Convertir un número sin validarlo

```cpp
// Mal
ModoRiego modo = static_cast<ModoRiego>(leerByteDeFlash());   // ¿y si vale 9?

// Bien
uint8_t guardado = leerByteDeFlash();
ModoRiego modo = (guardado <= static_cast<uint8_t>(ModoRiego::Automatico))
                     ? static_cast<ModoRiego>(guardado)
                     : ModoRiego::Apagado;                  // valor seguro por defecto
```

Todo lo que viene de afuera (flash, BLE, la red, el monitor serie) puede traer cualquier número. Validá en el punto de entrada, como en el ejemplo 3.

### Enums clásicos con nombres que chocan

```cpp
// Mal
enum EstadoBomba { APAGADO, ENCENDIDO };
enum EstadoLuz   { APAGADO, ENCENDIDO };   // error: redeclaration of 'APAGADO'

// Bien
enum class EstadoBomba { Apagado, Encendido };
enum class EstadoLuz   { Apagado, Encendido };
```

## Resumen

- Un `enum` reemplaza números mágicos por nombres. `enum class` es la versión a usar: los valores van con el nombre del tipo (`Modo::Manual`) y no se convierten a `int` solos.
- `: uint8_t` fija el tamaño, útil para guardar o enviar el valor. Fijá los números explícitamente cuando forman parte de un protocolo.
- Para convertir entre enum y número, `static_cast`. Los números que vienen de afuera se validan antes de convertirlos.
- En un `switch`, cada `case` termina con `break` (o `return`). Sin `default`, el compilador avisa cuando falta un caso.
- Para mostrar un enum como texto, una función con un `switch`.
