Una **interrupción** hace que el hardware detenga por un momento lo que el procesador está haciendo y ejecute una función tuya, llamada **ISR** (*Interrupt Service Routine*), apenas ocurre un evento en un pin. Cuando la ISR termina, el programa sigue desde donde estaba. Sirve para eventos que no te podés perder aunque `loop()` esté ocupado: los pulsos de un caudalímetro, de un anemómetro o de un pluviómetro. La regla de oro: la ISR anota lo que pasó y vuelve; el trabajo lo hace `loop()`.

## Por qué te importa

`loop()` da miles de vueltas por segundo, pero no todas son rápidas: dibujar la pantalla puede tardar 30 ms, y una petición al backend, medio segundo. Un caudalímetro genera cientos de pulsos por segundo, y cada pulso dura unos pocos milisegundos. Si el controlador del invernadero los cuenta con `digitalRead` en `loop()`, pierde todos los que ocurren mientras hace otra cosa, y el registro de riego dice que se usaron 20 litros cuando se usaron 60.

Las interrupciones resuelven eso, pero traen sus propios problemas. Una ISR que hace demasiado bloquea el sistema y hace perder otras interrupciones. Una ISR que llama a `Serial` puede colgar el chip. Y los datos que comparte con `loop()` necesitan la protección que viste en [B.11](/conceptos/b-11).

## Paso a paso

### 1. Registrar una interrupción

```cpp
constexpr uint8_t PIN_CAUDALIMETRO = 33;
volatile uint32_t pulsos = 0;

void IRAM_ATTR alPulso() {
  pulsos++;
}

void setup() {
  pinMode(PIN_CAUDALIMETRO, INPUT_PULLUP);
  attachInterrupt(digitalPinToInterrupt(PIN_CAUDALIMETRO), alPulso, FALLING);
}
```

`attachInterrupt` recibe tres cosas: el número de interrupción del pin (`digitalPinToInterrupt` lo calcula; en el ESP32 es el mismo número de pin), la función a llamar y el **modo**. Desde ese momento, cada vez que el pin cumple la condición, el hardware llama a `alPulso`, sin importar en qué línea esté `loop()`.

`detachInterrupt(digitalPinToInterrupt(pin))` la desactiva.

### 2. Los modos

| Modo | Se dispara cuando | Uso típico |
|---|---|---|
| `FALLING` | la señal pasa de `HIGH` a `LOW` | pulsos con pull-up, botones a GND |
| `RISING` | la señal pasa de `LOW` a `HIGH` | pulsos activos en alto |
| `CHANGE` | cualquiera de los dos cambios | medir la duración de un pulso |
| `LOW` / `HIGH` | mientras la señal está en ese nivel | poco usado: se dispara una y otra vez |

Elegí el flanco que marca el evento que querés contar. Con un pull-up y un sensor que lleva la línea a GND en cada pulso, es `FALLING`.

### 3. Las reglas de una ISR

Una ISR corre en un contexto especial: el resto del programa está detenido y no se puede esperar a nada. Por eso:

- **Corta**: anotar y volver. Contar, guardar un momento, levantar una bandera. Nada de cálculos largos.
- **`IRAM_ATTR`**: la pone en la RAM interna. Mientras el ESP32 escribe la flash (al guardar en NVS, por ejemplo), el código que está en la flash no se puede ejecutar; una ISR guardada ahí que se dispara en ese momento reinicia el equipo.
- **Nada de `Serial`, `delay`, `new`, `String`, WiFi ni HTTP**. Todas esas funciones pueden esperar, bloquearse o usar recursos protegidos.
- **Variables compartidas con `volatile`**, y las operaciones de leer y modificar desde los dos lados, protegidas (ver [B.11](/conceptos/b-11)).

`millis()` y `micros()` sí se pueden leer dentro de una ISR en el ESP32, y son útiles para anotar cuándo ocurrió el evento.

### 4. Cómo se comunica la ISR con `loop()`

Hay tres patrones, de más simple a más completo:

```cpp
// 1. Bandera: "pasó algo"
volatile bool hayEvento = false;
void IRAM_ATTR isr() { hayEvento = true; }

// 2. Contador: "pasó N veces"
volatile uint32_t eventos = 0;
void IRAM_ATTR isr() { eventos++; }

// 3. Momento: "pasó por última vez a tal hora"
volatile uint32_t ultimoEventoUs = 0;
void IRAM_ATTR isr() { ultimoEventoUs = micros(); }
```

`loop()` revisa la bandera, el contador o el momento cuando le toca, y hace el trabajo. Para pasar datos más complejos entre una ISR y una tarea, FreeRTOS tiene colas, que se ven en [2.4](/conceptos/2-4).

### 5. Rebotes en interrupciones

Un contacto mecánico rebota (ver [0.3](/conceptos/0-3)), y una interrupción con `FALLING` se dispara en cada rebote: una sola pulsación puede generar cinco interrupciones. Dentro de una ISR no se puede usar `delay`, pero sí comparar tiempos:

```cpp
volatile uint32_t ultimoValidoMs = 0;

void IRAM_ATTR alPulsoPluviometro() {
  uint32_t ahora = millis();
  if (ahora - ultimoValidoMs < 100) return;   // rebote: ignorar
  ultimoValidoMs = ahora;
  // contar el pulso
}
```

Para sensores electrónicos (caudalímetros de efecto Hall, por ejemplo) no hace falta: su señal es limpia.

### 6. ¿Interrupción o `loop()`?

Las interrupciones agregan complejidad: código que corre en cualquier momento, datos compartidos, reglas especiales. Usalas cuando hacen falta:

- **Interrupción**: eventos rápidos o cortos que `loop()` podría perderse (pulsos de sensores), o que exigen reaccionar en microsegundos.
- **`loop()`**: todo lo que dura lo suficiente para que `loop()` lo vea, como un botón que una persona presiona durante cientos de milisegundos.

## Ejemplos

### Ejemplo 1. Contar pulsaciones con una interrupción

El caso mínimo: la ISR solo cuenta, `loop()` informa cuando el contador cambia.

```cpp contador-isr.ino
constexpr uint8_t PIN_ENTRADA = 4;

volatile uint32_t pulsos = 0;

void IRAM_ATTR alPulso() {
  pulsos++;
}

void setup() {
  Serial.begin(115200);
  pinMode(PIN_ENTRADA, INPUT_PULLUP);
  attachInterrupt(digitalPinToInterrupt(PIN_ENTRADA), alPulso, FALLING);
}

void loop() {
  static uint32_t ultimoInformado = 0;
  uint32_t actual = pulsos;              // leer un uint32_t es atómico en el ESP32
  if (actual != ultimoInformado) {
    ultimoInformado = actual;
    Serial.printf("pulsos: %u\n", static_cast<unsigned>(actual));
  }
}
```

Probalo tocando el pin 4 con un cable a GND: vas a ver que un solo toque suma varios pulsos. Son los rebotes del contacto.

### Ejemplo 2. Velocidad del viento con un anemómetro

Un anemómetro de cazoletas cierra un contacto una vez por vuelta. Según el modelo, una vuelta por segundo equivale a cierta velocidad del viento; en muchos modelos comunes, 2,4 km/h. Cada segundo, el controlador toma los pulsos acumulados y calcula la velocidad.

```cpp anemometro.ino
constexpr uint8_t PIN_ANEMOMETRO = 27;
constexpr float KMH_POR_HZ = 2.4f;          // dato del fabricante
constexpr uint32_t ANTIRREBOTE_US = 5000;   // 5 ms: permite hasta 200 pulsos/s

portMUX_TYPE candado = portMUX_INITIALIZER_UNLOCKED;
volatile uint32_t pulsos = 0;
volatile uint32_t ultimoPulsoUs = 0;

void IRAM_ATTR alPulsoAnemometro() {
  uint32_t ahora = micros();
  if (ahora - ultimoPulsoUs < ANTIRREBOTE_US) return;
  ultimoPulsoUs = ahora;
  portENTER_CRITICAL_ISR(&candado);
  pulsos++;
  portEXIT_CRITICAL_ISR(&candado);
}

void setup() {
  Serial.begin(115200);
  pinMode(PIN_ANEMOMETRO, INPUT_PULLUP);
  attachInterrupt(digitalPinToInterrupt(PIN_ANEMOMETRO), alPulsoAnemometro, FALLING);
}

void loop() {
  static uint32_t ultimo = 0;
  if (millis() - ultimo >= 1000) {
    ultimo += 1000;

    portENTER_CRITICAL(&candado);
    uint32_t n = pulsos;
    pulsos = 0;
    portEXIT_CRITICAL(&candado);

    float kmh = n * KMH_POR_HZ;   // n pulsos en 1 segundo = n Hz
    Serial.printf("viento: %.1f km/h\n", kmh);
  }
}
```

La ISR filtra rebotes comparando con el último pulso válido y cuenta. `loop()` toma el contador y lo pone en cero dentro de una sección crítica, para no perder un pulso que llegue justo en el medio (ver [B.11](/conceptos/b-11)). `ultimo += 1000` mantiene intervalos exactos de un segundo, que importan porque la velocidad se calcula como pulsos por segundo (ver [0.1](/conceptos/0-1)).

### Ejemplo 3. Detectar una bomba que funciona en seco

Si la bomba está encendida pero por el caudalímetro no pasa agua, algo anda mal: el tanque está vacío, la manguera se dobló o la bomba se trabó. Funcionar en seco la quema en minutos. La ISR anota el momento de cada pulso, y `loop()` revisa si hace mucho que no llega ninguno con la bomba encendida.

```cpp bomba-seca.ino
constexpr uint8_t PIN_CAUDALIMETRO = 33;
constexpr uint8_t PIN_BOMBA = 26;
constexpr uint32_t SIN_FLUJO_MAXIMO_MS = 5000;

volatile uint32_t ultimoPulsoMs = 0;

void IRAM_ATTR alPulsoCaudal() {
  ultimoPulsoMs = millis();      // escribir un uint32_t es atómico: no hace falta candado
}

bool bombaEncendida = false;
uint32_t encendidaDesdeMs = 0;
bool alarmaSeco = false;

void encenderBomba() {
  if (alarmaSeco) return;        // no volver a encender hasta que alguien revise
  digitalWrite(PIN_BOMBA, HIGH);
  bombaEncendida = true;
  encendidaDesdeMs = millis();
}

void apagarBomba() {
  digitalWrite(PIN_BOMBA, LOW);
  bombaEncendida = false;
}

void vigilarFlujo() {
  if (!bombaEncendida) return;
  uint32_t ultimo = ultimoPulsoMs;   // primero el pulso, después la hora: así ultimo <= ahora
  uint32_t ahora = millis();
  if (ahora - encendidaDesdeMs < SIN_FLUJO_MAXIMO_MS) return;   // darle tiempo a arrancar

  if (ahora - ultimo > SIN_FLUJO_MAXIMO_MS) {
    apagarBomba();
    alarmaSeco = true;
    Serial.println("ALARMA: bomba encendida sin flujo, apagada");
  }
}

void setup() {
  Serial.begin(115200);
  pinMode(PIN_BOMBA, OUTPUT);
  digitalWrite(PIN_BOMBA, LOW);
  pinMode(PIN_CAUDALIMETRO, INPUT_PULLUP);
  attachInterrupt(digitalPinToInterrupt(PIN_CAUDALIMETRO), alPulsoCaudal, FALLING);
  encenderBomba();               // para probar: encender al arrancar
}

void loop() {
  vigilarFlujo();
}
```

La ISR hace lo mínimo posible: guardar un número. El orden de las dos lecturas en `vigilarFlujo` importa: si se leyera primero la hora y justo después llegara un pulso, `ultimo` quedaría un milisegundo *después* de `ahora`, la resta daría la vuelta a un número enorme (ver [B.1](/conceptos/b-1)) y saltaría una alarma falsa. Toda la lógica (cuánto esperar después de encender, cuándo considerar que no hay flujo, qué hacer) está en `loop()`, donde se puede imprimir, cambiar el estado y, en el firmware completo, avisar al backend. La alarma queda activa hasta que alguien la reconozca: una bomba que falló no debería volver a encenderse sola.

## Errores comunes

### `Serial` o `delay` dentro de la ISR

```cpp
// Mal
void IRAM_ATTR alPulso() {
  Serial.println("pulso");
  delay(10);
}

// Bien
volatile bool huboPulso = false;
void IRAM_ATTR alPulso() { huboPulso = true; }
void loop() {
  if (huboPulso) {
    huboPulso = false;
    Serial.println("pulso");
  }
}
```

### Olvidar `IRAM_ATTR`

```cpp
// Mal: funciona hasta que coincide con una escritura en la flash
void alPulso() { pulsos++; }

// Bien
void IRAM_ATTR alPulso() { pulsos++; }
```

El reinicio aparece de vez en cuando, por ejemplo al guardar la configuración, y es muy difícil relacionarlo con la ISR si no conocés esta regla.

### Variables compartidas sin protección

```cpp
// Mal: sin volatile, y leer y reiniciar sin candado
uint32_t pulsos = 0;
uint32_t n = pulsos; pulsos = 0;

// Bien: ver B.11
```

### Contar rebotes

Un contacto mecánico conectado a una interrupción cuenta varios pulsos por cada cierre. Filtralos en la ISR comparando con el momento del último pulso válido, como en el ejemplo 2, o con un capacitor en el hardware.

## Ejercicio

El pluviómetro del invernadero es de balancín: cada vez que se llena una cazoleta (0,28 mm de lluvia), el balancín se inclina y cierra un contacto. El código actual a veces reinicia el ESP32, y cuando funciona, mide el triple de lluvia que la estación del vecino. Reescribí la ISR y `loop()`.

```cpp pluviometro.ino
constexpr uint8_t PIN_PLUVIOMETRO = 25;
float lluviaMm = 0.0f;

void alBalancin() {
  delay(50);                       // esperar a que deje de rebotar
  lluviaMm += 0.28f;
  Serial.printf("lluvia: %.2f mm\n", lluviaMm);
}

void setup() {
  Serial.begin(115200);
  pinMode(PIN_PLUVIOMETRO, INPUT_PULLUP);
  attachInterrupt(digitalPinToInterrupt(PIN_PLUVIOMETRO), alBalancin, CHANGE);
}

void loop() {}
```

<summary>Pista</summary>

Hay cuatro problemas: lo que hace la ISR (`delay`, `Serial`, cálculos con `float`), dónde está guardada, el modo `CHANGE` y los rebotes.

</details>

<details>
<summary>Ver solución</summary>

```cpp pluviometro.ino
constexpr uint8_t PIN_PLUVIOMETRO = 25;
constexpr float MM_POR_BALANCEO = 0.28f;
constexpr uint32_t ANTIRREBOTE_MS = 100;

volatile uint32_t balanceos = 0;
volatile uint32_t ultimoBalanceoMs = 0;

void IRAM_ATTR alBalancin() {
  uint32_t ahora = millis();
  if (ahora - ultimoBalanceoMs < ANTIRREBOTE_MS) return;
  ultimoBalanceoMs = ahora;
  balanceos++;                     // solo la ISR escribe este contador
}

void setup() {
  Serial.begin(115200);
  pinMode(PIN_PLUVIOMETRO, INPUT_PULLUP);
  attachInterrupt(digitalPinToInterrupt(PIN_PLUVIOMETRO), alBalancin, FALLING);
}

void loop() {
  static uint32_t ultimosInformados = 0;
  uint32_t actual = balanceos;     // lectura atómica de 32 bits
  if (actual != ultimosInformados) {
    ultimosInformados = actual;
    Serial.printf("lluvia: %.2f mm\n", actual * MM_POR_BALANCEO);
  }
}
```

Los reinicios venían del `delay` y el `Serial` dentro de la ISR, más la falta de `IRAM_ATTR`. El triple de lluvia venía de dos cosas: `CHANGE` cuenta el cierre y la apertura del contacto (el doble), y los rebotes sumaban más. Ahora la ISR solo cuenta flancos de bajada separados por al menos 100 ms, y el cálculo en milímetros se hace en `loop()`. Como el contador solo lo escribe la ISR y nunca se reinicia, alcanza con `volatile` sin sección crítica.

</details>

## Resumen

- `attachInterrupt(digitalPinToInterrupt(pin), funcion, modo)` llama a tu función cuando el pin cambia, aunque `loop()` esté ocupado.
- Elegí el modo según el flanco del evento: `FALLING`, `RISING` o `CHANGE`.
- Una ISR es corta, lleva `IRAM_ATTR` y no usa `Serial`, `delay`, `String` ni nada que pueda esperar.
- La ISR anota (bandera, contador, momento) y `loop()` hace el trabajo. Las variables compartidas son `volatile`, y leer y modificar desde los dos lados se protege.
- Usá interrupciones para eventos rápidos que `loop()` podría perderse; lo demás, en `loop()`.
