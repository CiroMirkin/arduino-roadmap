**UART** es la forma más simple de comunicar dos dispositivos: uno transmite bits por un cable (TX) y el otro los recibe por otro (RX), uno tras otro, a una velocidad acordada de antemano. No hay reloj compartido, por eso se llama *asincrónica*. `Serial`, el monitor serie que usás para depurar, es una UART conectada al USB. El ESP32 tiene más UARTs, que se usan con `HardwareSerial` para hablar con módulos y sensores.

## Por qué te importa

Muchos sensores y módulos útiles en un invernadero hablan por UART: los sensores de CO₂ por infrarrojo, los módulos GPS, los módems celulares, los lectores de códigos de barras y RFID, otras placas. El monitor serie, además, es la herramienta de depuración que vas a usar todos los días.

Los problemas de UART tienen síntomas muy característicos: caracteres basura (velocidad equivocada), silencio total (TX y RX invertidos), lecturas que de vez en cuando son absurdas (falta validar el checksum) o un controlador que se traba cuando el módulo no responde (lectura bloqueante). Cada uno tiene una causa concreta.

## Paso a paso

### 1. Cómo viaja un byte

```text
reposo  inicio  bit0 bit1 bit2 bit3 bit4 bit5 bit6 bit7  fin   reposo
 HIGH    LOW    ──────────── 8 bits de datos ─────────── HIGH   HIGH
```

En reposo, la línea está en `HIGH`. Un byte empieza con un bit de inicio en `LOW`, siguen los 8 bits de datos y termina con un bit de parada en `HIGH`. Esta configuración se llama **8N1** (8 bits, sin paridad, 1 bit de parada) y es la más común.

El **baud rate** es cuántos bits por segundo se envían: 9600, 115200, etc. Como no hay reloj, el receptor sabe cuándo leer cada bit solo porque conoce la velocidad. Si los dos lados usan velocidades distintas, el receptor lee los bits en los momentos equivocados y aparece basura.

### 2. La conexión

```text
ESP32 TX ──────► RX módulo
ESP32 RX ◄────── TX módulo
ESP32 GND ────── GND módulo
```

TX de uno a RX del otro, cruzados, y los GND unidos. Los pines del ESP32 trabajan con 3,3 V: si el módulo transmite con 5 V, su TX necesita un divisor o un adaptador de niveles antes de llegar al RX del ESP32.

### 3. `Serial`: la UART del USB

```cpp
void setup() {
  Serial.begin(115200);
  Serial.println("controlador iniciado");
}
```

`Serial` usa la UART0, conectada al chip USB de la placa (en el ESP32 clásico, pines 1 y 3). El número de `Serial.begin()` tiene que coincidir con la velocidad elegida en el monitor serie. En placas con USB nativo, como muchas ESP32-S3, `Serial` puede ir directo por USB; si no ves nada, revisá la opción *USB CDC On Boot* (ver [0.2](/conceptos/0-2)).

### 4. Las otras UARTs

El ESP32 tiene tres UARTs (el S3 también; el C3 tiene dos). La 0 la usa `Serial`; las otras quedan libres para módulos, y sus pines se pueden asignar a casi cualquier GPIO:

```cpp
HardwareSerial sensorCo2(2);   // UART2

constexpr uint8_t PIN_RX_CO2 = 16;   // al TX del sensor
constexpr uint8_t PIN_TX_CO2 = 17;   // al RX del sensor

void setup() {
  Serial.begin(115200);                                      // logs por USB
  sensorCo2.begin(9600, SERIAL_8N1, PIN_RX_CO2, PIN_TX_CO2); // el sensor, aparte
}
```

`Serial1` y `Serial2` ya existen como objetos globales en el core; crear tu propio `HardwareSerial` con un nombre descriptivo deja más claro para qué es cada uno.

### 5. Leer sin bloquear

Los bytes que llegan se guardan en un buffer interno (256 bytes por defecto) hasta que los leés:

```cpp
while (sensorCo2.available() > 0) {   // ¿hay bytes esperando?
  uint8_t b = sensorCo2.read();       // tomar uno
  // procesar b
}
```

`available()` y `read()` vuelven al instante. Funciones como `readStringUntil()`, `readBytes()` o `parseInt()` esperan hasta recibir lo que piden o hasta que pase un tiempo de espera (1 segundo por defecto), y mientras tanto bloquean `loop()`. Para un controlador que hace muchas cosas, conviene leer de a un byte y armar el mensaje por partes, como en el ejemplo 2.

Si leés muy poco seguido y llegan muchos datos, el buffer se llena y los bytes nuevos se pierden. Con `setRxBufferSize()`, llamado antes de `begin()`, se puede agrandar.

### 6. Protocolos de texto y protocolos binarios

UART solo transporta bytes; qué significan lo define cada dispositivo. Hay dos estilos:

- **Texto**: líneas legibles terminadas en `\n`, como `T=24.5;H=68`. Fáciles de depurar mirando el monitor serie.
- **Binario**: *tramas* de bytes con un formato fijo. Suelen tener un byte de **cabecera** que marca el inicio, los datos y un **checksum** para detectar errores. Más compactas y rápidas de procesar, pero hay que leer la hoja de datos del dispositivo.

## Ejemplos

### Ejemplo 1. Un puente entre el USB y otra UART

Para probar un módulo nuevo, es útil que el ESP32 haga de puente: todo lo que escribís en el monitor serie va al módulo, y todo lo que responde el módulo aparece en el monitor.

```cpp puente.ino
HardwareSerial modulo(2);

void setup() {
  Serial.begin(115200);
  modulo.begin(9600, SERIAL_8N1, 16, 17);   // RX, TX
  Serial.println("puente listo");
}

void loop() {
  while (Serial.available() > 0) {
    modulo.write(Serial.read());
  }
  while (modulo.available() > 0) {
    Serial.write(modulo.read());
  }
}
```

`write` envía bytes tal cual, sin convertirlos a texto como haría `print`. Las dos UARTs pueden tener velocidades distintas: el ESP32 recibe a una velocidad y reenvía a la otra.

### Ejemplo 2. Leer líneas de texto sin bloquear

Una estación meteorológica exterior manda por UART una línea cada pocos segundos con el formato `T=18.5;H=72;V=3.4` (temperatura, humedad y viento). El controlador arma cada línea de a un carácter y la interpreta cuando llega el `\n`.

```cpp estacion.ino
HardwareSerial estacion(1);

struct Clima {
  float temperatura;
  float humedad;
  float viento;
};

Clima climaExterior = {};
bool hayClima = false;

bool interpretarLinea(const char* linea, Clima& c) {
  return sscanf(linea, "T=%f;H=%f;V=%f", &c.temperatura, &c.humedad, &c.viento) == 3;
}

void leerEstacion() {
  static char linea[64];
  static size_t largo = 0;

  while (estacion.available() > 0) {
    char ch = static_cast<char>(estacion.read());
    if (ch == '\r') continue;
    if (ch == '\n') {
      linea[largo] = '\0';
      Clima nuevo;
      if (interpretarLinea(linea, nuevo)) {
        climaExterior = nuevo;
        hayClima = true;
      } else {
        Serial.printf("línea inválida: %s\n", linea);
      }
      largo = 0;
    } else if (largo < sizeof(linea) - 1) {
      linea[largo++] = ch;
    }
  }
}

void setup() {
  Serial.begin(115200);
  estacion.begin(9600, SERIAL_8N1, 18, 19);
}

void loop() {
  leerEstacion();

  static uint32_t ultimo = 0;
  if (hayClima && millis() - ultimo >= 10000) {
    ultimo = millis();
    Serial.printf("afuera: %.1f C, %.0f%%, viento %.1f m/s\n",
                  climaExterior.temperatura, climaExterior.humedad, climaExterior.viento);
  }
}
```

`sscanf` es la inversa de `sprintf`: lee valores de un texto según un formato, y devuelve cuántos pudo leer. Si no son 3, la línea está incompleta o corrupta y se descarta. El buffer de la línea tiene tamaño fijo y nunca se escribe fuera de él (ver [B.12](/conceptos/b-12)). Con el viento, el controlador podría, por ejemplo, cerrar las ventanas cenitales si sopla fuerte.

### Ejemplo 3. Un sensor de CO₂ con protocolo binario

Los sensores de CO₂ por infrarrojo de la serie MH-Z19 son comunes en invernaderos (el CO₂ afecta el crecimiento de las plantas). Hablan por UART a 9600 baudios con tramas de 9 bytes. Para pedir una lectura se envía:

```text
FF 01 86 00 00 00 00 00 79
```

y el sensor responde con `FF 86 HH LL ...`, donde `HH LL` es la concentración en ppm (byte alto y bajo) y el último byte es el checksum: 0xFF menos la suma de los bytes 1 a 7, más 1.

El controlador pide una lectura, sigue haciendo otras cosas, y procesa la respuesta cuando llega, con un tiempo máximo de espera.

```cpp co2.ino
HardwareSerial sensorCo2(2);

class LectorCo2 {
public:
  explicit LectorCo2(HardwareSerial& puerto) : _puerto(puerto) {}

  void pedirLectura() {
    static const uint8_t PEDIDO[9] = {0xFF, 0x01, 0x86, 0x00, 0x00, 0x00, 0x00, 0x00, 0x79};
    while (_puerto.available() > 0) _puerto.read();   // descartar restos viejos
    _puerto.write(PEDIDO, sizeof(PEDIDO));
    _recibidos = 0;
    _esperando = true;
    _momentoPedido = millis();
  }

  // Llamar en cada vuelta de loop(). Devuelve true cuando hay una lectura nueva.
  bool actualizar() {
    if (!_esperando) return false;

    while (_puerto.available() > 0 && _recibidos < 9) {
      uint8_t b = _puerto.read();
      if (_recibidos == 0 && b != 0xFF) continue;     // esperar la cabecera
      _respuesta[_recibidos++] = b;
    }

    if (_recibidos == 9) {
      _esperando = false;
      if (_respuesta[1] != 0x86 || !checksumValido()) {
        _errores++;
        return false;
      }
      _ppm = (static_cast<uint16_t>(_respuesta[2]) << 8) | _respuesta[3];
      return true;
    }

    if (millis() - _momentoPedido > 200) {            // el sensor no respondió a tiempo
      _esperando = false;
      _errores++;
    }
    return false;
  }

  uint16_t ppm() const { return _ppm; }
  uint32_t errores() const { return _errores; }

private:
  bool checksumValido() const {
    uint8_t suma = 0;
    for (int i = 1; i < 8; i++) suma += _respuesta[i];
    uint8_t esperado = static_cast<uint8_t>(0xFF - suma + 1);
    return esperado == _respuesta[8];
  }

  HardwareSerial& _puerto;
  uint8_t _respuesta[9] = {};
  uint8_t _recibidos = 0;
  bool _esperando = false;
  uint32_t _momentoPedido = 0;
  uint16_t _ppm = 0;
  uint32_t _errores = 0;
};

LectorCo2 co2(sensorCo2);

void setup() {
  Serial.begin(115200);
  sensorCo2.begin(9600, SERIAL_8N1, 16, 17);
}

void loop() {
  static uint32_t ultimoPedido = 0;
  if (millis() - ultimoPedido >= 5000) {
    ultimoPedido = millis();
    co2.pedirLectura();
  }

  if (co2.actualizar()) {
    Serial.printf("CO2: %u ppm (errores: %u)\n",
                  static_cast<unsigned>(co2.ppm()), static_cast<unsigned>(co2.errores()));
  }
}
```

`pedirLectura` envía el pedido y vuelve enseguida. `actualizar` junta los bytes a medida que llegan, se sincroniza con la cabecera `0xFF` (si se perdió un byte, descarta hasta encontrar el inicio de una trama), valida el tipo de respuesta y el checksum, y abandona si pasan 200 ms sin respuesta. El contador de errores permite detectar un cable flojo: si crece rápido, hay un problema físico. La clase recibe el puerto por referencia (ver [B.5](/conceptos/b-5)), así la misma clase sirve con cualquier UART. Antes de usar un sensor real, revisá su hoja de datos: el formato de las tramas cambia entre fabricantes y modelos.

## Errores comunes

### TX con TX

```text
Mal:   ESP32 TX ── TX módulo,  ESP32 RX ── RX módulo
Bien:  ESP32 TX ── RX módulo,  ESP32 RX ── TX módulo
```

El síntoma es silencio total. Si no recibís nada de un módulo, lo primero es invertir TX y RX.

### Velocidad distinta en cada lado

```cpp
// Mal: el sensor trabaja a 9600
sensorCo2.begin(115200, SERIAL_8N1, 16, 17);

// Bien
sensorCo2.begin(9600, SERIAL_8N1, 16, 17);
```

### Usar `Serial` para un módulo

```cpp
// Mal: los logs van al módulo, y el módulo responde al monitor serie
Serial.begin(9600);
Serial.write(PEDIDO, 9);
Serial.println("pedido enviado");   // ¡esto también le llega al sensor!

// Bien: el módulo en su propia UART
sensorCo2.write(PEDIDO, 9);
Serial.println("pedido enviado");
```

### Confiar en una trama sin validarla

```cpp
// Mal
uint16_t ppm = (respuesta[2] << 8) | respuesta[3];

// Bien: cabecera, tipo y checksum antes de usar los datos
if (respuesta[0] == 0xFF && respuesta[1] == 0x86 && checksumValido(respuesta)) {
  uint16_t ppm = (respuesta[2] << 8) | respuesta[3];
}
```

### Leer con funciones que bloquean

```cpp
// Mal: hasta 1 segundo trabado si el módulo no responde
String linea = estacion.readStringUntil('\n');

// Bien: available() y read(), armando la línea por partes (ejemplo 2)
```

## Ejercicio

Este código lee el sensor de CO₂ cada 5 segundos. A veces el controlador muestra valores absurdos como 25000 ppm, el monitor serie se llena de símbolos raros, y la pantalla se congela un segundo cada tanto. Encontrá los tres problemas y corregilos.

```cpp co2-problemas.ino
uint8_t PEDIDO[9] = {0xFF, 0x01, 0x86, 0x00, 0x00, 0x00, 0x00, 0x00, 0x79};

void setup() {
  Serial.begin(9600);
}

void loop() {
  Serial.write(PEDIDO, 9);
  uint8_t r[9];
  Serial.readBytes(r, 9);
  uint16_t ppm = (r[2] << 8) | r[3];
  Serial.print("CO2: ");
  Serial.println(ppm);
  delay(5000);
}
```

<details>
<summary>Ver solución</summary>

La solución completa es la clase `LectorCo2` del ejemplo 3. Los tres problemas eran:

1. El sensor y los logs compartían `Serial`: el texto `CO2: ...` le llegaba al sensor, y los bytes binarios del sensor aparecían en el monitor serie como símbolos raros. El sensor va en su propia UART (`HardwareSerial sensorCo2(2)`), y `Serial` queda para los logs a 115200.
2. No se validaba la respuesta: si la trama llegaba desfasada (un byte perdido) o con ruido, `r[2]` y `r[3]` eran cualquier cosa. Hay que chequear la cabecera `0xFF`, el tipo `0x86` y el checksum. Además, `readBytes` devuelve cuántos bytes leyó: si son menos de 9, `r` tiene basura.
3. `readBytes` espera hasta 1 segundo si el sensor no responde, y `delay(5000)` congela todo: la pantalla se trababa. La versión no bloqueante pide la lectura, sigue con el resto del `loop()` y procesa la respuesta cuando llega.

</details>

## Resumen

- UART envía bytes por un cable (TX) y los recibe por otro (RX), sin reloj compartido: los dos lados tienen que usar la misma velocidad.
- Se conecta cruzado (TX con RX) y con los GND unidos. Los pines del ESP32 trabajan con 3,3 V.
- `Serial` es para el monitor serie. Los módulos van en otra UART con `HardwareSerial`, en los pines que elijas.
- Leé con `available()` y `read()` para no bloquear. `readStringUntil` y `readBytes` esperan hasta 1 segundo.
- Validá todo lo que llega: cabecera, longitud y checksum en protocolos binarios, formato completo en protocolos de texto.
