La RAM se borra cada vez que el ESP32 se reinicia. Para que la configuración, la calibración de los sensores o las credenciales del WiFi sobrevivan, se guardan en **NVS** (*Non-Volatile Storage*), una partición de la memoria flash pensada para pares **clave-valor**. La librería **`Preferences`** la usa como un diccionario: abrís un espacio con nombre, guardás valores con `put...` y los leés con `get...`, indicando qué valor usar si todavía no existen.

## Por qué te importa

El controlador del invernadero tiene muchos datos que no deberían perderse en un corte de luz: el umbral de humedad para regar, las temperaturas de ventilación, la calibración de cada sensor de suelo (ver [0.4](/conceptos/0-4)), la red WiFi, el identificador del invernadero en el backend. Si todo eso vive en variables, después de cada reinicio el equipo vuelve a los valores del código, y alguien tiene que recalibrar los sensores.

NVS también tiene sus trampas. La flash se desgasta con las escrituras, así que guardar en cada vuelta de `loop()` la arruina. Las claves tienen un largo máximo, y si te pasás, la escritura falla sin hacer ruido. Y si guardás estructuras completas, una actualización de firmware que las cambia hace que se lean mal.

## Paso a paso

### 1. Namespaces y claves

```cpp
#include <Preferences.h>

Preferences prefs;

void setup() {
  prefs.begin("riego", false);   // abrir el namespace "riego" para leer y escribir
  // ...
  prefs.end();                   // cerrarlo
}
```

NVS se organiza en **namespaces** (espacios con nombre) y, dentro de cada uno, **claves**. Distintos módulos pueden usar la misma clave en namespaces distintos sin pisarse: `riego/umbral` y `ventilacion/umbral` son cosas diferentes. Tanto el namespace como la clave tienen como **máximo 15 caracteres**.

`begin(nombre, soloLectura)`: con `true` solo se puede leer, y es más liviano. `end()` cierra el namespace; abrí, usá y cerrá, en lugar de dejarlo abierto todo el programa.

### 2. Guardar y leer

```cpp
prefs.begin("riego", false);
prefs.putFloat("umbral", 38.5f);
prefs.putUInt("duracionMs", 30000);
prefs.putString("nombre", "cantero 1");
prefs.putBool("automatico", true);
prefs.end();

prefs.begin("riego", true);
float umbral = prefs.getFloat("umbral", 35.0f);       // 35 si no existe
uint32_t duracion = prefs.getUInt("duracionMs", 20000);
String nombre = prefs.getString("nombre", "sin nombre");
bool automatico = prefs.getBool("automatico", false);
prefs.end();
```

Hay funciones para cada tipo: `putInt`/`getInt`, `putUInt`/`getUInt`, `putFloat`/`getFloat`, `putBool`/`getBool`, `putString`/`getString`, `putBytes`/`getBytes`, y más. Cada `get` recibe un **valor por defecto**, que es lo que devuelve si la clave no existe todavía. Las funciones `put` devuelven cuántos bytes escribieron: 0 significa que falló.

Otras funciones útiles: `isKey("umbral")` dice si la clave existe, `remove("umbral")` la borra y `clear()` borra todo el namespace.

### 3. El desgaste de la flash

La flash se escribe por sectores, y cada sector soporta del orden de cien mil borrados. NVS no reescribe siempre en el mismo lugar: va agregando valores nuevos y reparte el desgaste entre varios sectores, pero no lo elimina.

La regla: **guardá cuando el valor cambia**, no periódicamente por las dudas. Para algo que cambia todo el tiempo, como un contador de litros, guardá cada tanto (cada cierta cantidad de litros o cada hora), aceptando perder lo último si se corta la luz.

### 4. Guardar una estructura completa

Para una configuración con muchos campos, `putBytes` guarda un `struct` entero de una vez:

```cpp
struct ConfigRiego {
  uint8_t version;
  float umbralSuelo;
  uint32_t duracionMs;
};

ConfigRiego config = {1, 38.5f, 30000};
prefs.putBytes("config", &config, sizeof(config));

ConfigRiego leida;
size_t leidos = prefs.getBytes("config", &leida, sizeof(leida));
```

Es práctico, pero los bytes guardados tienen la forma del `struct` en el momento de guardarlos. Si una versión nueva del firmware agrega o reordena campos, los bytes viejos se interpretan con la forma nueva y salen valores absurdos. Por eso el primer campo es una **versión**: al leer, si la versión o el tamaño no coinciden, se usan los valores por defecto (o se convierte el formato viejo).

### 5. Valores que llegan de NVS también se validan

Lo que se lee de la flash puede estar mal: se guardó con un bug, se corrompió, viene de una versión vieja. Antes de usar un umbral leído, chequeá que esté en un rango razonable, igual que con lo que llega por la red (ver [B.10](/conceptos/b-10) y [6.3](/conceptos/6-3)).

## Ejemplos

### Ejemplo 1. Contar los arranques del equipo

Saber cuántas veces se reinició el controlador ayuda a detectar problemas: si el contador sube solo, algo lo está reiniciando.

```cpp arranques.ino
#include <Preferences.h>

void setup() {
  Serial.begin(115200);

  Preferences prefs;
  prefs.begin("sistema", false);
  uint32_t arranques = prefs.getUInt("arranques", 0) + 1;
  prefs.putUInt("arranques", arranques);
  prefs.end();

  Serial.printf("arranque número %u\n", static_cast<unsigned>(arranques));
}

void loop() {}
```

Reiniciá la placa varias veces con el botón: el número sigue subiendo. Para empezar de nuevo, un sketch que haga `prefs.clear()` en el namespace `sistema`.

### Ejemplo 2. La calibración de un sensor de suelo

La calibración de dos puntos de [0.4](/conceptos/0-4) se mide una vez, al instalar el sensor, y se guarda. El controlador la carga al arrancar; si no hay calibración guardada, usa valores típicos y lo avisa.

```cpp calibracion-suelo.ino
#include <Preferences.h>

struct Calibracion {
  uint32_t mvSeco;
  uint32_t mvMojado;
};

constexpr Calibracion CALIBRACION_TIPICA = {2600, 1150};

bool calibracionValida(const Calibracion& c) {
  return c.mvSeco > c.mvMojado + 500 && c.mvSeco < 3300 && c.mvMojado > 300;
}

Calibracion cargarCalibracion(uint8_t cantero, bool& esGuardada) {
  char ns[16];
  snprintf(ns, sizeof(ns), "suelo%u", cantero);   // "suelo1", "suelo2"...

  Preferences prefs;
  prefs.begin(ns, true);
  Calibracion c;
  c.mvSeco = prefs.getUInt("seco", 0);
  c.mvMojado = prefs.getUInt("mojado", 0);
  prefs.end();

  esGuardada = calibracionValida(c);
  return esGuardada ? c : CALIBRACION_TIPICA;
}

bool guardarCalibracion(uint8_t cantero, const Calibracion& c) {
  if (!calibracionValida(c)) return false;
  char ns[16];
  snprintf(ns, sizeof(ns), "suelo%u", cantero);

  Preferences prefs;
  prefs.begin(ns, false);
  bool ok = prefs.putUInt("seco", c.mvSeco) > 0 && prefs.putUInt("mojado", c.mvMojado) > 0;
  prefs.end();
  return ok;
}

void setup() {
  Serial.begin(115200);

  bool guardada;
  Calibracion c = cargarCalibracion(1, guardada);
  Serial.printf("cantero 1: seco %u mV, mojado %u mV (%s)\n",
                static_cast<unsigned>(c.mvSeco), static_cast<unsigned>(c.mvMojado),
                guardada ? "calibrado" : "SIN CALIBRAR, valores típicos");

  // Así se guardaría después de medir con el sensor al aire y en agua:
  // guardarCalibracion(1, {2610, 1140});
}

void loop() {}
```

Cada cantero usa su propio namespace, así las claves son siempre las mismas (`seco`, `mojado`). La validación sirve en las dos direcciones: no se guarda una calibración absurda, y si lo que hay guardado no tiene sentido, se usa la típica y se avisa. Un sensor "sin calibrar" funciona, aunque con menos precisión, en lugar de dejar al controlador sin lecturas.

### Ejemplo 3. Toda la configuración, con versión

El controlador guarda su configuración completa como un `struct` con número de versión. Solo escribe en la flash si algo cambió.

```cpp configuracion.ino
#include <Preferences.h>

struct Configuracion {
  uint8_t version;
  uint8_t humedadMinima;       // % para empezar a regar
  uint8_t humedadMaxima;       // % para dejar de regar
  float abrirVentanasC;
  float cerrarVentanasC;
  uint32_t riegoMaximoMs;
};

constexpr uint8_t VERSION_CONFIG = 2;

constexpr Configuracion CONFIG_POR_DEFECTO = {
  VERSION_CONFIG, 35, 55, 30.0f, 27.0f, 5UL * 60UL * 1000UL,
};

Configuracion config = CONFIG_POR_DEFECTO;

bool esValida(const Configuracion& c) {
  return c.version == VERSION_CONFIG &&
         c.humedadMinima < c.humedadMaxima && c.humedadMaxima <= 100 &&
         c.cerrarVentanasC < c.abrirVentanasC && c.abrirVentanasC < 50.0f &&
         c.riegoMaximoMs >= 10000 && c.riegoMaximoMs <= 30UL * 60UL * 1000UL;
}

void cargarConfiguracion() {
  Preferences prefs;
  prefs.begin("config", true);
  Configuracion leida;
  size_t n = prefs.getBytes("datos", &leida, sizeof(leida));
  prefs.end();

  if (n == sizeof(leida) && esValida(leida)) {
    config = leida;
    Serial.println("configuración cargada");
  } else {
    config = CONFIG_POR_DEFECTO;
    Serial.println("sin configuración válida guardada: valores por defecto");
  }
}

bool guardarConfiguracion(const Configuracion& nueva) {
  if (!esValida(nueva)) return false;
  if (memcmp(&nueva, &config, sizeof(Configuracion)) == 0) return true;   // nada cambió

  Preferences prefs;
  prefs.begin("config", false);
  bool ok = prefs.putBytes("datos", &nueva, sizeof(nueva)) == sizeof(nueva);
  prefs.end();
  if (ok) config = nueva;
  return ok;
}

void setup() {
  Serial.begin(115200);
  cargarConfiguracion();

  Configuracion cambio = config;
  cambio.humedadMinima = 40;               // por ejemplo, desde la pantalla o el backend
  Serial.println(guardarConfiguracion(cambio) ? "guardada" : "rechazada");
}

void loop() {}
```

`getBytes` devuelve cuántos bytes leyó: si el `struct` cambió de tamaño entre versiones, no coincide y se descarta. Si cambió sin cambiar de tamaño, lo detecta la versión: por eso cada cambio de formato incrementa `VERSION_CONFIG`. `memcmp` compara los bytes de las dos configuraciones para no escribir la flash si no hay cambios. La validación con rangos impide que un valor imposible llegue a guardarse.

## Errores comunes

### Claves de más de 15 caracteres

```cpp
// Mal: 22 caracteres, la escritura falla
prefs.putFloat("temperaturaVentilacion", 30.0f);

// Bien
prefs.putFloat("tVentilar", 30.0f);
```

Revisá lo que devuelven las funciones `put`: 0 significa que no se escribió nada.

### Escribir en cada vuelta de `loop()`

```cpp
// Mal
void loop() {
  litrosHoy += medirLitros();
  prefs.putFloat("litrosHoy", litrosHoy);   // miles de escrituras por segundo
}

// Bien: guardar cada tanto
void loop() {
  litrosHoy += medirLitros();
  static uint32_t ultimoGuardado = 0;
  if (millis() - ultimoGuardado >= 15UL * 60UL * 1000UL) {
    ultimoGuardado = millis();
    prefs.putFloat("litrosHoy", litrosHoy);
  }
}
```

### Guardar un `struct` sin versión

Sin un campo de versión, una actualización que cambia el `struct` hace que la configuración vieja se lea con la forma nueva. Poné siempre la versión como primer campo y compará también el tamaño leído.

### Confiar en lo que se lee

Un umbral de riego leído de la flash, que por un bug quedó en 0 o en 255, controla la bomba si no lo validás. Todo valor que se carga se chequea contra un rango razonable.

## Ejercicio

El controlador permite cambiar el umbral de riego desde la pantalla, con un deslizador. Después de unas semanas la NVS empieza a fallar, y en el primer arranque de un equipo nuevo la bomba no se enciende nunca. Corregí el código.

```cpp umbral.ino
#include <Preferences.h>

Preferences prefs;
float umbralRiego;

void setup() {
  prefs.begin("riego", false);
  umbralRiego = prefs.getFloat("umbralDeHumedad");
}

// La pantalla llama a esta función cada vez que el deslizador se mueve,
// unas 30 veces por segundo mientras el usuario lo arrastra
void alMoverDeslizador(float valor) {
  umbralRiego = valor;
  prefs.putFloat("umbralDeHumedad", umbralRiego);
}
```

<summary>Ver solución</summary>

```cpp umbral.ino
#include <Preferences.h>

constexpr float UMBRAL_POR_DEFECTO = 35.0f;
constexpr uint32_t ESPERA_GUARDADO_MS = 2000;

float umbralRiego = UMBRAL_POR_DEFECTO;
bool hayCambioSinGuardar = false;
uint32_t ultimoCambioMs = 0;

float leerUmbral() {
  Preferences prefs;
  prefs.begin("riego", true);
  float u = prefs.getFloat("umbral", UMBRAL_POR_DEFECTO);
  prefs.end();
  return (u >= 5.0f && u <= 95.0f) ? u : UMBRAL_POR_DEFECTO;
}

void setup() {
  umbralRiego = leerUmbral();
}

void alMoverDeslizador(float valor) {
  umbralRiego = constrain(valor, 5.0f, 95.0f);   // se usa enseguida...
  hayCambioSinGuardar = true;                     // ...pero se guarda después
  ultimoCambioMs = millis();
}

void loop() {
  // guardar cuando el usuario dejó de mover el deslizador hace 2 segundos
  if (hayCambioSinGuardar && millis() - ultimoCambioMs >= ESPERA_GUARDADO_MS) {
    Preferences prefs;
    prefs.begin("riego", false);
    prefs.putFloat("umbral", umbralRiego);
    prefs.end();
    hayCambioSinGuardar = false;
  }
}
```

Arrastrar el deslizador escribía la flash 30 veces por segundo: unos minutos de uso por día la desgastan en semanas. Ahora el valor se aplica de inmediato pero se guarda una sola vez, cuando el deslizador queda quieto. Sin valor por defecto, `getFloat` devuelve `NAN` (*not a number*) en un equipo nuevo, y cualquier comparación con `NAN` da falso, así que la condición para regar nunca se cumplía. Ahora devuelve 35, y además se valida el rango (un `NAN` tampoco pasa la validación). La clave original (`umbralDeHumedad`) tenía exactamente 15 caracteres, el límite; una más corta deja margen y es más fácil de leer.

## Resumen

- NVS guarda pares clave-valor en la flash, organizados en namespaces. `Preferences` la maneja con `begin`, `put...`, `get...` y `end`.
- Namespaces y claves: máximo 15 caracteres. Revisá lo que devuelven las funciones `put`.
- Cada `get` lleva un valor por defecto para el primer arranque.
- La flash se desgasta: guardá cuando el valor cambia, o cada tanto, nunca en cada vuelta de `loop()`.
- Para un `struct` completo, un campo de versión y la comparación del tamaño leído. Y validá todo lo que cargás.
