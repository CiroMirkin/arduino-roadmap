Cada variable ocupa un lugar en la memoria. Una **referencia** es otro nombre para ese mismo lugar, y un **puntero** es una variable que guarda la dirección de ese lugar.

## Por qué te importa

En Python o JavaScript casi nunca pensás si una función recibe el objeto original o una copia, porque el lenguaje lo decide por vos. En C++ lo decidís en cada parámetro, y si no escribís nada especial, la función recibe una copia.

En el controlador del invernadero eso produce dos bugs típicos. El primero es silencioso: una función que tendría que poner en cero el contador de riegos recibe una copia, pone la copia en cero y el contador real sigue igual. Compila, no hay advertencia, y el riego se comporta raro. El segundo es ruidoso: un puntero a la conexión BLE que todavía no se creó se usa sin revisar, y el ESP32 se reinicia con un `Guru Meditation Error`.

## Paso a paso

### 1. Toda variable vive en una dirección

```cpp direccion.ino
float temperatura = 24.5f;

void setup() {
  Serial.begin(115200);
  Serial.printf("valor: %.1f\n", temperatura);
  Serial.printf("dirección: %p\n", &temperatura);
}

void loop() {}
```

`&temperatura` devuelve la dirección de memoria donde está guardado el `24.5`. Vas a ver algo como `0x3ffbdb6c`. El número cambia de un programa a otro y no importa cuál es; lo que importa es que existe y que se puede guardar y pasar de un lado a otro.

### 2. Pasar por valor copia

```cpp
void reiniciar(int litros) {
  litros = 0;
}

int litrosRegados = 120;
reiniciar(litrosRegados);
// litrosRegados sigue valiendo 120
```

Cuando llamás a `reiniciar`, C++ crea una variable nueva llamada `litros` y copia el 120 adentro. La función pone esa variable nueva en cero, y al terminar la variable desaparece. `litrosRegados` nunca se tocó.

Para un `int` copiar es gratis. Para un objeto grande (un `String`, un `struct` con muchos campos) copiar cuesta tiempo y RAM, y en un microcontrolador las dos cosas escasean.

### 3. Una referencia es otro nombre para la misma variable

```cpp
int litrosRegados = 120;
int& alias = litrosRegados;   // alias ES litrosRegados, con otro nombre
alias = 0;                    // ahora litrosRegados vale 0

void reiniciar(int& litros) { // litros será otro nombre para lo que le pasen
  litros = 0;
}

reiniciar(litrosRegados);     // ahora sí: litrosRegados vale 0
```

El `&` pegado al tipo (`int&`) declara una referencia. Dos reglas la definen:

- Se liga a una variable en el momento en que se declara, y no se puede dejar sin ligar.
- Una vez ligada, no se puede cambiar para que apunte a otra variable. `alias = otraVariable;` copia el valor de `otraVariable` dentro de `litrosRegados`, no cambia de variable.

> El símbolo `&` tiene dos usos distintos. En una declaración (`int& x`) significa "x es una referencia". Delante de una variable dentro de una expresión (`&x`) significa "la dirección de x". Con `*` pasa algo parecido, como vas a ver en el paso siguiente.

### 4. Un puntero guarda una dirección

```cpp
int litrosRegados = 120;
int* ptr = &litrosRegados;   // ptr guarda la dirección de litrosRegados

*ptr = 0;                    // *ptr sigue la dirección y modifica lo que hay ahí
Serial.println(litrosRegados);   // 0
```

`int*` se lee "puntero a int". El `*` delante del puntero en una expresión (`*ptr`) significa "lo que hay en esa dirección". Si el puntero apunta a un objeto, para llamar a sus métodos se usa `->`: `ptr->leer()` es lo mismo que `(*ptr).leer()`.

A diferencia de la referencia, un puntero puede cambiar de destino (`ptr = &otraVariable;`) y puede no apuntar a nada.

### 5. `nullptr`: el puntero que no apunta a nada

En firmware es común que un objeto se cree más tarde: el cliente BLE existe recién cuando aparece un nodo sensor, la conexión al backend recién cuando hay WiFi. Mientras tanto, el puntero vale `nullptr`.

```cpp
BLEClient* cliente = nullptr;   // todavía no hay cliente

void conectarNodo(BLEAddress direccion) {
  if (cliente == nullptr) {
    cliente = BLEDevice::createClient();
  }
  cliente->connect(direccion);
}

void loop() {
  if (cliente != nullptr && cliente->isConnected()) {
    // recién acá es seguro usarlo
  }
}
```

Si usás `cliente->` mientras vale `nullptr`, el programa intenta leer la dirección 0, que no es memoria válida, y el ESP32 se reinicia. En código viejo vas a ver `NULL` o `0` en lugar de `nullptr`; significan lo mismo, pero `nullptr` tiene un tipo propio y el compilador detecta mejor los errores.

### 6. `const T&`: leer sin copiar

Queda un caso: una función que necesita leer un objeto grande sin modificarlo. Por valor lo copia; por referencia podría modificarlo sin querer. `const T&` resuelve las dos cosas.

```cpp
struct Lectura {
  float temperatura;
  float humedadAire;
  float humedadSuelo;
  uint32_t momentoMs;
};

void mostrar(const Lectura& l) {
  Serial.printf("%.1f C, aire %.0f%%, suelo %.0f%%\n",
                l.temperatura, l.humedadAire, l.humedadSuelo);
  // l.temperatura = 0;   // no compila: l es const
}
```

Con eso tenés todo para elegir la firma de cualquier función:

| Si la función... | Usá | Ejemplo |
|---|---|---|
| lee un tipo chico (`int`, `float`, `bool`, un puntero) | por valor | `void fijarUmbral(float umbral)` |
| lee un objeto grande (`String`, `struct`, una clase) | `const T&` | `void mostrar(const Lectura& l)` |
| tiene que modificar el original | `T&` | `void reiniciar(Estadisticas& e)` |
| recibe algo que puede no existir | `T*` y chequear `nullptr` | `void asignarNodo(NodoRemoto* nodo)` |

## Ejemplos

### Ejemplo 1. Las tres formas de pasar un parámetro

El caso mínimo: la misma operación hecha por valor, por referencia y por puntero.

```cpp tres-formas.ino
void porValor(int x)       { x = 99; }
void porReferencia(int& x) { x = 99; }
void porPuntero(int* x)    { if (x != nullptr) *x = 99; }

void setup() {
  Serial.begin(115200);
  int a = 1;
  int b = 1;
  int c = 1;

  porValor(a);
  porReferencia(b);
  porPuntero(&c);

  Serial.printf("a=%d b=%d c=%d\n", a, b, c);   // a=1 b=99 c=99
}

void loop() {}
```

Fijate en las llamadas. `porPuntero(&c)` lleva un `&`, así que se nota que `c` puede cambiar. `porReferencia(b)` se ve igual que `porValor(a)`: para saber si `b` puede cambiar hay que mirar la firma de la función.

### Ejemplo 2. Un sensor que se pasa a varias funciones

Lo típico en Arduino: un objeto que representa un sensor y varias funciones que lo usan, algunas para modificarlo y otras solo para leerlo.

> Este ejemplo y el siguiente usan clases, que se explican en la próxima lección, [B.3](/conceptos/b-3). Por ahora alcanza con saber que una clase agrupa datos y las funciones que trabajan sobre ellos (sus *métodos*), y que `sensor.leer()` llama al método `leer` de ese objeto.

```cpp sensor-suelo.ino
class SensorSuelo {
public:
  explicit SensorSuelo(uint8_t pin) : _pin(pin) {}

  void leer() {
    _ultimoMv = analogReadMilliVolts(_pin);
    _lecturas++;
  }
  uint32_t ultimoMv() const { return _ultimoMv; }
  uint32_t lecturas() const { return _lecturas; }

private:
  uint8_t _pin;
  uint32_t _ultimoMv = 0;
  uint32_t _lecturas = 0;
};

void tomarMuestras(SensorSuelo& sensor, int cantidad) {   // modifica: T&
  for (int i = 0; i < cantidad; i++) {
    sensor.leer();
  }
}

void informar(const SensorSuelo& sensor) {                // solo lee: const T&
  Serial.print(sensor.lecturas());
  Serial.print(" lecturas, última: ");
  Serial.print(sensor.ultimoMv());
  Serial.println(" mV");
}

SensorSuelo sensorCantero1(34);

void setup() {
  Serial.begin(115200);
  tomarMuestras(sensorCantero1, 5);
  informar(sensorCantero1);   // 5 lecturas, última: ... mV
}

void loop() {}
```

Si `tomarMuestras` recibiera `SensorSuelo sensor` sin `&`, leería 5 veces sobre una copia, y `informar` mostraría `0 lecturas`. Notá también que `informar` solo puede llamar a `lecturas()` y `ultimoMv()` porque esos métodos terminan en `const`; eso lo vas a ver en [B.4](/conceptos/b-4).

### Ejemplo 3. Una clase que guarda referencias a otros objetos

En el controlador, el control de riego necesita leer un sensor y manejar una bomba. Puede guardar referencias a los dos, porque existen durante todo el programa.

```cpp control-riego.ino
// SensorSuelo es la clase del ejemplo 2

class Rele {
public:
  explicit Rele(uint8_t pin) : _pin(pin) {}
  void begin()    { pinMode(_pin, OUTPUT); apagar(); }
  void encender() { digitalWrite(_pin, HIGH); _encendido = true; }
  void apagar()   { digitalWrite(_pin, LOW);  _encendido = false; }
  bool encendido() const { return _encendido; }

private:
  uint8_t _pin;
  bool _encendido = false;
};

class ControlRiego {
public:
  ControlRiego(const SensorSuelo& sensor, Rele& bomba, uint32_t umbralSecoMv)
    : _sensor(sensor), _bomba(bomba), _umbralSecoMv(umbralSecoMv) {}

  void actualizar() {
    bool seco = _sensor.ultimoMv() > _umbralSecoMv;   // en este sensor, más mV = suelo más seco
    if (seco && !_bomba.encendido()) _bomba.encender();
    if (!seco && _bomba.encendido()) _bomba.apagar();
  }

private:
  const SensorSuelo& _sensor;   // solo lo lee
  Rele& _bomba;                 // lo maneja
  uint32_t _umbralSecoMv;
};

SensorSuelo sensorCantero1(34);
Rele bombaCantero1(26);
ControlRiego riegoCantero1(sensorCantero1, bombaCantero1, 2200);

void setup() {
  bombaCantero1.begin();
}

void loop() {
  sensorCantero1.leer();
  riegoCantero1.actualizar();
}
```

Hay tres cosas para mirar. Los miembros que son referencias se inicializan en la lista de inicialización (`: _sensor(sensor), ...`), porque una referencia no puede quedar sin ligar ni siquiera un instante. El tipo de cada miembro documenta la intención: `const SensorSuelo&` dice que el control de riego nunca va a modificar el sensor. Y la regla que hace que esto sea seguro: el objeto referenciado tiene que vivir al menos tanto como el objeto que guarda la referencia. Acá los tres son globales, así que viven todo el programa.

En un sistema real se agrega un margen alrededor del umbral para que la bomba no se prenda y apague muchas veces seguidas cuando la humedad ronda ese valor. Acá se omite para no desviar el foco de las referencias.

### Ejemplo 4. Punteros para lo que puede faltar

El controlador acepta hasta cuatro nodos sensores, pero no siempre están todos. Un arreglo de punteros representa eso bien: cada posición apunta a un nodo o vale `nullptr`.

```cpp nodos.ino
struct NodoRemoto {
  char nombre[16];
  float temperatura;
  uint32_t ultimoContactoMs;
};

constexpr int MAX_NODOS = 4;
NodoRemoto* nodos[MAX_NODOS] = {};   // {} pone todas las posiciones en nullptr

NodoRemoto nodoNorte = {"norte", 0.0f, 0};

void registrar(int posicion, NodoRemoto* nodo) {
  if (posicion >= 0 && posicion < MAX_NODOS) {
    nodos[posicion] = nodo;
  }
}

void informarNodos() {
  for (int i = 0; i < MAX_NODOS; i++) {
    if (nodos[i] == nullptr) {
      Serial.printf("posición %d: libre\n", i);
      continue;
    }
    Serial.printf("posición %d: %s, %.1f C\n", i, nodos[i]->nombre, nodos[i]->temperatura);
  }
}

void setup() {
  Serial.begin(115200);
  nodoNorte.temperatura = 26.3f;
  registrar(0, &nodoNorte);
  informarNodos();
  // posición 0: norte, 26.3 C
  // posición 1: libre
  // posición 2: libre
  // posición 3: libre
}

void loop() {}
```

Una referencia no serviría acá: no existe una "referencia vacía" para las posiciones libres. Cada vez que el código recorre `nodos`, pregunta por `nullptr` antes de usar `->`.

## Errores comunes

### Devolver una referencia a una variable local

```cpp
// Mal
const String& nombreInvernadero() {
  String nombre = "Invernadero 1";
  return nombre;   // nombre se destruye al salir de la función
}

// Bien
String nombreInvernadero() {
  return "Invernadero 1";   // devuelve el valor; el compilador evita la copia
}
```

La variable local deja de existir cuando la función termina, y la referencia queda apuntando a memoria que otra parte del programa va a reutilizar. A veces funciona en las pruebas y falla después, que es lo peor que puede pasar. Lo mismo vale para devolver un puntero a una variable local. El compilador suele avisarte con `returning reference to local variable`: no ignores esa advertencia.

### Usar un puntero sin chequear `nullptr`

```cpp
// Mal
void mostrarNodo(NodoRemoto* nodo) {
  Serial.println(nodo->temperatura);
}

// Bien
void mostrarNodo(const NodoRemoto* nodo) {
  if (nodo == nullptr) {
    Serial.println("sin datos");
    return;
  }
  Serial.println(nodo->temperatura);
}
```

Si la función recibe un puntero, quien la llama puede pasarle `nullptr`. O lo chequeás, o cambiás la firma a una referencia (`const NodoRemoto&`) para que pasarle "nada" sea imposible.

### Olvidar el `&` y modificar una copia

```cpp
// Mal
void sumarRiego(Estadisticas e) { e.riegosHoy++; }

// Bien
void sumarRiego(Estadisticas& e) { e.riegosHoy++; }
```

Este error no da advertencia ni error de compilación. La única pista es que el valor no cambia. Si una función con nombre de verbo ("sumar", "reiniciar", "actualizar") recibe un objeto sin `&`, desconfiá.

### Declarar dos punteros en una línea

```cpp
// Mal
int* minima, maxima;   // solo minima es un puntero; maxima es un int común

// Bien
int* minima = nullptr;
int* maxima = nullptr;
```

El `*` se aplica solo al nombre que tiene al lado, aunque visualmente parezca parte del tipo. Una declaración por línea evita el problema y de paso te obliga a inicializar cada puntero.

## Ejercicio

En el controlador hay un botón para reiniciar las estadísticas del día. Al apretarlo, la pantalla sigue mostrando los valores viejos. Además, `mostrar` se llama una vez por segundo y copia la estructura completa cada vez.

Corregí las dos funciones cambiando solo sus firmas.

```cpp estadisticas.ino
struct Estadisticas {
  float temperaturaMaxima;
  float temperaturaMinima;
  int riegosHoy;
};

Estadisticas estadisticasHoy = {31.2f, 14.8f, 6};

void reiniciar(Estadisticas e) {
  e.temperaturaMaxima = -100.0f;
  e.temperaturaMinima = 100.0f;
  e.riegosHoy = 0;
}

void mostrar(Estadisticas e) {
  Serial.printf("máx %.1f, mín %.1f, riegos %d\n",
                e.temperaturaMaxima, e.temperaturaMinima, e.riegosHoy);
}
```

<details>
<summary>Pista</summary>

Usá la tabla del paso 6: una de las funciones tiene que modificar el original y la otra solo lo lee.

</details>

<details>
<summary>Ver solución</summary>

```cpp
void reiniciar(Estadisticas& e) {         // modifica el original
  e.temperaturaMaxima = -100.0f;
  e.temperaturaMinima = 100.0f;
  e.riegosHoy = 0;
}

void mostrar(const Estadisticas& e) {     // lee sin copiar ni modificar
  Serial.printf("máx %.1f, mín %.1f, riegos %d\n",
                e.temperaturaMaxima, e.temperaturaMinima, e.riegosHoy);
}
```

`reiniciar` trabajaba sobre una copia, por eso la pantalla no cambiaba. Con `Estadisticas&` modifica `estadisticasHoy`. `mostrar` no necesita modificar nada, así que `const Estadisticas&` evita la copia y además garantiza que una edición futura no pueda cambiar las estadísticas desde ahí por accidente.

Las llamadas (`reiniciar(estadisticasHoy);` y `mostrar(estadisticasHoy);`) quedan exactamente iguales.

## Resumen

- Por defecto, C++ pasa los parámetros por valor: la función recibe una copia.
- `T&` es otro nombre para un objeto existente. No puede ser nula ni cambiar de objeto, y sirve para modificar el original.
- `T*` guarda una dirección. Puede cambiar de destino y puede valer `nullptr`, así que hay que chequearlo antes de usar `->` o `*`.
- `const T&` es la forma estándar de leer un objeto grande sin copiarlo y sin poder modificarlo.
- Nunca devuelvas una referencia ni un puntero a una variable local.
