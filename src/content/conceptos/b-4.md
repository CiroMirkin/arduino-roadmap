`const` le dice al compilador que algo no va a cambiar, y el compilador se encarga de que esa promesa se cumpla. Es la misma palabra en cuatro lugares distintos, con significados relacionados: en una variable, en un parámetro, al final de la firma de un método y en un puntero. Esta lección los recorre uno por uno.

## Por qué te importa

En [B.2](/conceptos/b-2) viste que `const T&` es la forma estándar de pasar un objeto grande sin copiarlo. Apenas lo usás con tus propias clases aparece este error:

```text
error: passing 'const Tanque' as 'this' argument discards qualifiers
```

El mensaje no ayuda mucho, y la tentación es sacar el `const` del parámetro para que compile. La corrección real está en otro lado: falta un `const` en el método.

Además, `const` atrapa bugs reales. La configuración del invernadero (umbrales de riego, temperaturas de ventilación) se pasa a muchas funciones que solo deberían leerla. Si una de ellas la modifica por error, el síntoma aparece lejos de la causa: el riego se comporta distinto horas después. Con `const`, ese error ni siquiera compila.

## Paso a paso

### 1. Variables `const`

```cpp
const float umbralRiego = leerUmbralGuardado();   // se conoce al ejecutar
umbralRiego = 40.0f;                              // no compila

constexpr float TEMPERATURA_MAXIMA = 45.0f;       // se conoce al compilar
```

Una variable `const` recibe su valor al inicializarse y no cambia nunca más. La diferencia con `constexpr` (ver [B.5](/conceptos/b-5)) es cuándo se conoce el valor: `const` admite un valor calculado al ejecutar, como una lectura de la memoria flash.

### 2. Parámetros `const T&`

```cpp
void mostrar(const ConfigInvernadero& config) {
  Serial.println(config.umbralRiego);
  // config.umbralRiego = 0;   // no compila
}
```

Lo viste en B.2: no copia y no deja modificar. La promesa es para quien llama: puede pasar su configuración tranquilo, porque la función no la va a cambiar.

### 3. Métodos `const`

Con un objeto que tiene métodos, aparece una pregunta: si `config` es `const`, ¿qué métodos se le pueden llamar? El compilador no mira el cuerpo de cada método para adivinar si modifica algo. Te pide que lo declares:

```cpp
class Tanque {
public:
  float porcentaje() const { return _porcentaje; }   // solo lee: const
  void actualizar(float p) { _porcentaje = p; }      // modifica: sin const

private:
  float _porcentaje = 0.0f;
};
```

El `const` después de los paréntesis promete que el método no modifica el objeto. Dentro de un método `const`:

- se pueden leer los miembros,
- no se pueden escribir (es un error de compilación),
- solo se pueden llamar otros métodos `const` del mismo objeto.

### 4. Lo que habilita un método `const`

```cpp
void mostrar(const Tanque& t) {
  Serial.println(t.porcentaje());   // compila: porcentaje() es const
  // t.actualizar(50.0f);           // no compila: actualizar() no es const
}
```

Sobre una referencia o un objeto `const` solo se pueden llamar métodos `const`. Por eso el error de la introducción: si `porcentaje()` no tuviera el `const`, no se podría llamar desde `mostrar`, aunque solo lea. La regla práctica es simple: **todo método que no modifica el objeto lleva `const`**. Escribilo desde el principio, porque agregarlo después obliga a revisar todas las clases que usan esa.

### 5. `const` y punteros

Con punteros hay dos cosas que pueden ser constantes: lo que está apuntado y el puntero mismo. La posición del `const` respecto del `*` lo decide:

```cpp
const char* nombre = "norte";   // los caracteres son const; el puntero no
nombre = "sur";                 // compila: apunta a otro texto
// nombre[0] = 'N';             // no compila: no se pueden cambiar los caracteres

char buffer[] = "este";
char* const fijo = buffer;      // el puntero es const; los caracteres no
fijo[0] = 'E';                  // compila
// fijo = otroBuffer;           // no compila: no puede apuntar a otro lado

const char* const ambos = "oeste";   // ni el puntero ni los caracteres cambian
```

Leelo de derecha a izquierda: `const char*` es "puntero a char constante"; `char* const` es "puntero constante a char". En firmware, `const char*` aparece todo el tiempo para recibir textos fijos sin copiarlos.

### 6. `const` en el valor de retorno

```cpp
class Historial {
public:
  const Lectura& ultima() const { return _lecturas[_indice]; }   // útil
  const float promedio() const;                                  // inútil
  // ...
};
```

Devolver `const T&` permite leer un miembro grande sin copiarlo y sin dejar que quien llama lo modifique. Es útil para `struct` y `String` guardados dentro de un objeto. La condición es que el objeto que guarda ese miembro siga existiendo mientras se usa la referencia (la misma regla de B.2).

Poner `const` en un retorno por valor, como `const float promedio()`, no aporta nada: quien llama recibe una copia y puede hacer lo que quiera con ella. Es un `const` mal ubicado que suele aparecer cuando se quería escribir `float promedio() const`.

## Ejemplos

### Ejemplo 1. Un termómetro con métodos `const` y no `const`

```cpp termometro.ino
class Termometro {
public:
  explicit Termometro(uint8_t pin) : _pin(pin) {}

  void leer() {                                   // modifica: sin const
    int mv = analogReadMilliVolts(_pin);
    _celsius = (mv - 500) / 10.0f;                // sensor tipo TMP36
    if (_celsius > _maxima) _maxima = _celsius;
  }

  float celsius() const { return _celsius; }      // solo lee
  float maxima() const { return _maxima; }        // solo lee

private:
  uint8_t _pin;
  float _celsius = 0.0f;
  float _maxima = -100.0f;
};

void informar(const Termometro& t) {
  Serial.printf("ahora %.1f C, máxima %.1f C\n", t.celsius(), t.maxima());
  // t.leer();   // no compila: leer() no es const y t es const
}

Termometro termometro(32);

void setup() {
  Serial.begin(115200);
}

void loop() {
  termometro.leer();
  informar(termometro);
  delay(2000);
}
```

`informar` recibe el termómetro como `const&`: puede consultar todo lo que quiera, pero no puede pedirle una lectura nueva. Si alguien en el futuro agrega un `t.leer()` ahí por error, no compila.

### Ejemplo 2. Una configuración que muchas funciones leen

```cpp programa-riego.ino
struct ProgramaRiego {
  uint8_t horaInicio;      // 0..23
  uint8_t horaFin;
  int humedadMinima;       // porcentaje

  bool enHorario(uint8_t hora) const {
    return hora >= horaInicio && hora < horaFin;
  }
};

bool tocaRegar(const ProgramaRiego& p, uint8_t hora, int humedad) {
  return p.enHorario(hora) && humedad < p.humedadMinima;
}

void mostrarPrograma(const ProgramaRiego& p) {
  Serial.printf("riego de %d a %d h, si la humedad baja de %d%%\n",
                p.horaInicio, p.horaFin, p.humedadMinima);
}

ProgramaRiego programa = {6, 9, 35};

void setup() {
  Serial.begin(115200);
  mostrarPrograma(programa);
  Serial.println(tocaRegar(programa, 7, 30) ? "regar" : "no regar");   // regar
}

void loop() {}
```

Aunque `ProgramaRiego` es un `struct` con datos públicos, su método `enHorario` lleva `const` para que se pueda llamar desde `tocaRegar`, que recibe el programa como `const&`. Las dos funciones declaran en su firma que no lo modifican, y quien lee el código ya sabe que el programa de riego solo cambia en otro lado.

### Ejemplo 3. Un historial de lecturas con accesos de solo lectura

El controlador guarda las últimas 12 lecturas para mostrar un gráfico en la pantalla. Cuando el historial se llena, la lectura nueva reemplaza a la más vieja (un *buffer circular*).

```cpp historial.ino
struct Lectura {
  float temperatura;
  float humedadSuelo;
  uint32_t momentoMs;
};

class Historial {
public:
  static constexpr size_t CAPACIDAD = 12;

  void agregar(const Lectura& l) {
    _lecturas[_siguiente] = l;
    _siguiente = (_siguiente + 1) % CAPACIDAD;
    if (_cantidad < CAPACIDAD) _cantidad++;
  }

  size_t cantidad() const { return _cantidad; }

  // i = 0 es la más vieja guardada; i = cantidad() - 1, la más nueva
  const Lectura& lectura(size_t i) const {
    size_t primera = (_cantidad < CAPACIDAD) ? 0 : _siguiente;
    return _lecturas[(primera + i) % CAPACIDAD];
  }

  float promedioTemperatura() const {
    if (_cantidad == 0) return 0.0f;
    float suma = 0.0f;
    for (size_t i = 0; i < _cantidad; i++) {
      suma += lectura(i).temperatura;   // llama a otro método const: permitido
    }
    return suma / _cantidad;
  }

private:
  Lectura _lecturas[CAPACIDAD] = {};
  size_t _siguiente = 0;
  size_t _cantidad = 0;
};

void dibujarGrafico(const Historial& h) {
  for (size_t i = 0; i < h.cantidad(); i++) {
    const Lectura& l = h.lectura(i);    // sin copiar la lectura
    Serial.printf("%2u: %.1f C\n", static_cast<unsigned>(i), l.temperatura);
  }
  Serial.printf("promedio: %.1f C\n", h.promedioTemperatura());
}

Historial historial;

void setup() {
  Serial.begin(115200);
  for (int i = 0; i < 15; i++) {
    historial.agregar({20.0f + i, 40.0f, millis()});
  }
  dibujarGrafico(historial);   // muestra de 23.0 a 34.0 C: las 3 primeras se pisaron
}

void loop() {}
```

`lectura(i)` devuelve `const Lectura&`: la pantalla puede leer cada lectura sin copiarla y sin poder cambiar el historial. `promedioTemperatura()` es `const` y por eso puede llamar a `lectura(i)`, que también lo es. `dibujarGrafico` recibe el historial como `const&`, y todo lo que necesita está disponible como métodos `const`. La referencia que devuelve `lectura(i)` es segura porque apunta adentro de `historial`, que es global.

## Errores comunes

### Olvidar `const` en un método que solo lee

```cpp
// Mal
class Nodo {
public:
  float bateria() { return _bateria; }
private:
  float _bateria = 0.0f;
};
void mostrar(const Nodo& n) { n.bateria(); }   // discards qualifiers

// Bien
float bateria() const { return _bateria; }
```

Cuando veas `discards qualifiers`, buscá el método que se llama en esa línea y fijate si le falta el `const`.

### "Arreglar" el error sacando el `const` del parámetro

```cpp
// Mal: compila, pero la función ya no promete nada
void mostrar(Nodo& n) { Serial.println(n.bateria()); }

// Bien: la función sigue siendo de solo lectura, y el método también
void mostrar(const Nodo& n) { Serial.println(n.bateria()); }
```

Sacar el `const` del parámetro hace desaparecer el error y la garantía al mismo tiempo. El `const` falta en el método, no sobra en el parámetro.

### `const` antes del tipo cuando se quería después

```cpp
// Mal: el retorno es const (inútil) y el método puede modificar el objeto
const float promedio();

// Bien: el método no modifica el objeto
float promedio() const;
```

### Devolver `const&` a algo que no sobrevive

```cpp
// Mal
const String& nombreNodo() const {
  return String("nodo-") + _id;   // temporal: se destruye al salir
}

// Bien
String nombreNodo() const {
  return String("nodo-") + _id;
}
```

`const T&` en el retorno solo sirve para miembros del objeto o para cosas que viven más que la llamada. Un valor calculado en el momento se devuelve por valor.

## Ejercicio

Esta clase representa el tanque de agua de riego. `mostrarTanque` no compila. Agregá `const` en todos los lugares donde corresponda, y encontrá el método que dice ser un "getter" pero modifica el objeto. ¿Qué harías con él?

```cpp tanque.ino
class Tanque {
public:
  void actualizar(float porcentaje) { _porcentaje = porcentaje; }

  float porcentaje() { return _porcentaje; }

  bool bajo() { return _porcentaje < 20.0f; }

  int consultas() {
    _consultas++;
    return _consultas;
  }

private:
  float _porcentaje = 100.0f;
  int _consultas = 0;
};

void mostrarTanque(const Tanque& t) {
  Serial.printf("%.0f%%%s\n", t.porcentaje(), t.bajo() ? " (bajo)" : "");
}
```

Recorré los métodos uno por uno y preguntate si escriben algún miembro. Los que no escriben nada llevan `const`.

<summary>Ver solución</summary>

```cpp tanque.ino
class Tanque {
public:
  void actualizar(float porcentaje) { _porcentaje = porcentaje; }

  float porcentaje() const { return _porcentaje; }

  bool bajo() const { return _porcentaje < 20.0f; }

  int registrarConsulta() {      // modifica: sin const y con un nombre que lo dice
    _consultas++;
    return _consultas;
  }

private:
  float _porcentaje = 100.0f;
  int _consultas = 0;
};
```

`porcentaje()` y `bajo()` solo leen: con el `const`, `mostrarTanque` compila. `consultas()` parecía un getter pero incrementa un contador, así que no puede ser `const`. Lo más honesto es renombrarlo para que se note que hace algo (`registrarConsulta`), y si hace falta leer el contador sin modificarlo, agregar aparte `int consultas() const { return _consultas; }`.

## Resumen

- `const` en una variable: no cambia después de inicializarse. Si el valor se conoce al compilar, usá `constexpr`.
- `const T&` en un parámetro: la función lee el objeto sin copiarlo y sin poder modificarlo.
- `const` al final de un método: el método no modifica el objeto. Solo esos métodos se pueden llamar sobre un objeto o una referencia `const`.
- Con punteros, `const char*` protege lo apuntado y `char* const` protege el puntero. Se lee de derecha a izquierda.
- `discards qualifiers` casi siempre significa que a un método le falta el `const`.
