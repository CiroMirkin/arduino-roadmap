En C++, el tipo de una variable define cuántos bytes ocupa en memoria y, por lo tanto, qué valores puede guardar. Los tipos de `<cstdint>` (`uint8_t`, `int16_t`, `uint32_t`, etc.) ocupan siempre lo mismo en cualquier placa, y `static_cast` es la forma explícita y controlada de convertir un valor de un tipo a otro.

## Por qué te importa

En JavaScript todos los números son de punto flotante, y en Python un entero puede crecer sin límite. En C++ cada número tiene un tamaño fijo y, si se pasa del máximo, el valor da la vuelta sin ningún aviso.

En el invernadero eso aparece en lugares concretos. Un contador de pulsos del caudalímetro declarado como `uint16_t` llega a 65535, vuelve a 0, y el registro de litros regados queda mal. El cálculo del porcentaje de humedad hecho con enteros da siempre 0 o 100. Y una conversión mal hecha al armar el mensaje que el nodo envía por BLE hace que el controlador lea 6553 °C en lugar de 24.5 °C.

## Paso a paso

### 1. Cada tipo ocupa una cantidad de bytes

```cpp tamanos.ino
void setup() {
  Serial.begin(115200);
  Serial.print("char: ");   Serial.println(sizeof(char));
  Serial.print("short: ");  Serial.println(sizeof(short));
  Serial.print("int: ");    Serial.println(sizeof(int));
  Serial.print("unsigned int: ");  Serial.println(sizeof(unsigned int));
  Serial.print("long: ");   Serial.println(sizeof(long));
  Serial.print("unsigned long: "); Serial.println(sizeof(unsigned long));
  Serial.print("float: ");  Serial.println(sizeof(float));
  Serial.print("double: "); Serial.println(sizeof(double));
}

void loop() {}
```

`sizeof` devuelve el tamaño en bytes. Estos son los resultados en un ESP32 y en un Arduino Uno:

| Tipo | ESP32 | Arduino Uno |
|---|---|---|
| `char` | 1 | 1 |
| `short` | 2 | 2 |
| `int` | 4 | **2** |
| `unsigned int` | 4 | **2** |
| `long` | 4 | 4 |
| `unsigned long` | 4 | 4 |
| `float` | 4 | 4 |
| `double` | 8 | **4** |

El estándar de C++ solo pone mínimos: `int` tiene que tener al menos 16 bits. Cada plataforma elige el resto. Un `int` que en el ESP32 llega a 2.147.483.647, en un Uno se queda en 32.767.

Cada tipo entero tiene una versión **sin signo**, con `unsigned` adelante: `unsigned char`, `unsigned short`, `unsigned int`, `unsigned long`. Ocupa los mismos bytes que su versión con signo, pero no tiene negativos, así que llega al doble de alto: un `long` va de -2.147.483.648 a 2.147.483.647, y un `unsigned long`, de 0 a 4.294.967.295. `unsigned` solo, sin nada más, es `unsigned int`.

Vas a ver `unsigned long` todo el tiempo en código de Arduino, porque es el tipo que devuelven `millis()` y `micros()`.

### 2. Los tipos de ancho fijo

`<cstdint>` (que `Arduino.h` ya incluye) define tipos cuyo tamaño está en el nombre:

| Tipo | Bytes | Rango |
|---|---|---|
| `uint8_t` | 1 | 0 a 255 |
| `int8_t` | 1 | -128 a 127 |
| `uint16_t` | 2 | 0 a 65.535 |
| `int16_t` | 2 | -32.768 a 32.767 |
| `uint32_t` | 4 | 0 a 4.294.967.295 |
| `int32_t` | 4 | -2.147.483.648 a 2.147.483.647 |
| `int64_t` | 8 | aproximadamente ±9,2 × 10¹⁸ |

La `u` significa *unsigned*, sin signo. Usalos cuando el tamaño importa: bytes de un mensaje o de un registro de un sensor, o contadores que tienen que aguantar mucho tiempo. Para un índice de un bucle chico o un número que nunca va a ser grande, `int` está bien.

¿Y `millis()`? Su firma real es `unsigned long millis()`. Tanto en las placas de Arduino como en el ESP32, `unsigned long` tiene 32 bits, el mismo tamaño y rango que `uint32_t`, así que guardar el resultado en cualquiera de los dos es equivalente:

```cpp
unsigned long inicio = millis();   // lo que vas a ver en la mayoría de los ejemplos de Arduino
uint32_t inicio2 = millis();       // lo mismo, con el tamaño escrito en el nombre
```

En estas lecciones se usa `uint32_t` porque deja explícito que son 32 bits, pero cuando leas `unsigned long` en un ejemplo, es el mismo número.

### 3. Con signo, sin signo y el desborde

```cpp
uint8_t contador = 255;
contador++;              // ahora vale 0

uint8_t nivel = 0;
nivel--;                 // ahora vale 255
```

En los tipos sin signo, pasarse del máximo es un comportamiento definido: el valor da la vuelta, como un cuentakilómetros. En los tipos con signo (`int`, `int16_t`…), pasarse del máximo es *comportamiento indefinido*: el estándar no dice qué pasa, y el compilador puede generar código que haga cualquier cosa. En los dos casos C++ no te avisa en tiempo de ejecución.

### 4. Conversiones automáticas

C++ convierte tipos por su cuenta en muchas situaciones, y algunas pierden información:

```cpp
int litros = 7;
float f = litros;          // 7.0: int a float, sin pérdida en este caso

float temperatura = 24.9f;
int t = temperatura;       // 24: float a int trunca los decimales

int a = 7 / 2;             // 3: división entre enteros, descarta el resto
float b = 7 / 2;           // 3.0: la división se hace entre enteros ANTES de guardar
float c = 7 / 2.0f;        // 3.5: si un operando es float, la división es con decimales
```

La línea de `b` es la que más confunde. C++ mira los tipos de `7` y de `2`, ve dos enteros, hace la división entera y recién después convierte el 3 a `float`. El tipo de la variable donde lo guardás no cambia cómo se hace la cuenta.

### 5. Convertir a propósito: `static_cast`

Cuando querés una conversión, escribila. C++ heredó de C la sintaxis `(tipo)valor`, pero tiene una versión más segura:

```cpp
int suma = 75;
int cantidad = 2;
float promedio = static_cast<float>(suma) / cantidad;   // 37.5
```

`static_cast<float>(suma)` convierte `suma` a `float` antes de dividir, así que la división se hace con decimales.

¿Por qué no `(float)suma`? En este caso harían lo mismo. La diferencia aparece cuando la conversión es peligrosa. El cast de C prueba varias conversiones hasta que alguna compile, incluidas las que quitan `const` o reinterpretan bytes como otro tipo. `static_cast` solo acepta conversiones entre tipos compatibles:

```cpp
const char* nombre = "invernadero";

char* a = (char*)nombre;                // compila: quita el const sin avisar
// char* b = static_cast<char*>(nombre); // no compila: static_cast no quita const
```

Hay otros tres casts con nombre para casos especiales: `const_cast` (quitar `const`, casi nunca hace falta), `reinterpret_cast` (ver los bytes de un tipo como si fueran de otro) y `dynamic_cast` (para herencia, poco usado en firmware). Si necesitás alguno de esos, la palabra en el código avisa a quien lo lea que ahí pasa algo delicado.

### 6. Redondear

`static_cast<int>` trunca: `static_cast<int>(24.9f)` es 24. Para redondear al entero más cercano, usá `lroundf`, que devuelve un `long`:

```cpp
float temperatura = 24.86f;
int16_t decimas = static_cast<int16_t>(lroundf(temperatura * 10.0f));   // 249
```

## Ejemplos

### Ejemplo 1. Tamaños y desborde en el monitor serie

```cpp desborde.ino
void setup() {
  Serial.begin(115200);

  uint8_t aperturas = 254;
  for (int i = 0; i < 4; i++) {
    Serial.println(aperturas);   // 254, 255, 0, 1
    aperturas++;
  }

  uint16_t pulsos = 65535;
  pulsos++;
  Serial.println(pulsos);        // 0

  uint32_t pulsosGrandes = 65535;
  pulsosGrandes++;
  Serial.println(pulsosGrandes); // 65536
}

void loop() {}
```

Corré este sketch y mirá la salida. Ver el 0 después del 255 una vez es la mejor forma de no olvidarlo.

### Ejemplo 2. Porcentaje de humedad del suelo

El sensor de humedad capacitivo entrega un voltaje que el ESP32 lee como un número de 0 a 4095. Hay que convertirlo a un porcentaje entre la lectura en suelo seco y la lectura en suelo empapado.

```cpp humedad.ino
constexpr uint8_t PIN_SUELO = 34;
constexpr int LECTURA_SECO = 3200;     // medido con el sensor al aire
constexpr int LECTURA_MOJADO = 1400;   // medido con el sensor en agua

// Mal: todo en enteros
int porcentajeMal(int lectura) {
  return (LECTURA_SECO - lectura) / (LECTURA_SECO - LECTURA_MOJADO) * 100;
}

// Bien: la división se hace con decimales y se limita al rango 0..100
int porcentajeHumedad(int lectura) {
  float fraccion = static_cast<float>(LECTURA_SECO - lectura) /
                   (LECTURA_SECO - LECTURA_MOJADO);
  int porcentaje = static_cast<int>(lroundf(fraccion * 100.0f));
  return constrain(porcentaje, 0, 100);
}

void setup() {
  Serial.begin(115200);
}

void loop() {
  int lectura = analogRead(PIN_SUELO);
  Serial.print("mal: ");
  Serial.print(porcentajeMal(lectura));       // 0 casi siempre
  Serial.print("  bien: ");
  Serial.println(porcentajeHumedad(lectura)); // por ejemplo, 62
  delay(1000);
}
```

En `porcentajeMal`, con una lectura de 2100 la cuenta es `1100 / 1800`, que entre enteros da 0, y 0 × 100 sigue siendo 0. Multiplicar antes de dividir (`... * 100 / 1800`) también funciona con enteros, pero el `static_cast<float>` deja la intención más clara. `constrain` evita que un sensor un poco fuera de calibración devuelva 104 % o -3 %. El `delay(1000)` está solo para no inundar el monitor serie; en el controlador real se usa `millis()`, como se ve en [0.1](/conceptos/0-1).

### Ejemplo 3. Empaquetar una lectura en bytes

El nodo sensor envía sus lecturas al controlador como bytes por BLE. Mandar texto (`"24.5"`) ocupa más y obliga a parsear. Lo habitual es mandar enteros de tamaño fijo: la temperatura en décimas de grado como `int16_t` (24.5 °C → 245) y la humedad como `uint8_t`.

```cpp trama.ino
// Lado del nodo sensor: armar 3 bytes
void armarTrama(float temperatura, float humedadSuelo, uint8_t trama[3]) {
  int16_t decimas = static_cast<int16_t>(lroundf(temperatura * 10.0f));
  uint16_t bits = static_cast<uint16_t>(decimas);    // mismos bits, sin signo, para desplazar

  trama[0] = static_cast<uint8_t>(bits & 0xFF);      // byte bajo
  trama[1] = static_cast<uint8_t>(bits >> 8);        // byte alto
  trama[2] = static_cast<uint8_t>(constrain(lroundf(humedadSuelo), 0L, 100L));
}

// Lado del controlador: reconstruir los valores
void leerTrama(const uint8_t trama[3], float& temperatura, uint8_t& humedadSuelo) {
  uint16_t bits = static_cast<uint16_t>(trama[0] | (trama[1] << 8));
  int16_t decimas = static_cast<int16_t>(bits);      // vuelve a tener signo
  temperatura = decimas / 10.0f;
  humedadSuelo = trama[2];
}

void setup() {
  Serial.begin(115200);
  uint8_t trama[3];
  armarTrama(-3.2f, 71.6f, trama);    // una helada de madrugada

  float temperatura;
  uint8_t humedad;
  leerTrama(trama, temperatura, humedad);
  Serial.printf("%.1f C, %d %%\n", temperatura, humedad);   // -3.2 C, 72 %
}

void loop() {}
```

Fijate en la temperatura negativa. `-32` como `int16_t` se guarda en dos bytes; al reconstruirlo, si en lugar de `int16_t` se usara `uint16_t`, el controlador leería 65504 décimas, o sea 6550.4 °C. Los dos lados tienen que acordar el tipo exacto de cada campo, y por eso acá se usan tipos de ancho fijo. La función recibe los resultados por referencia, como se explica en [B.5](/conceptos/b-5).

## Errores comunes

### Dividir enteros esperando decimales

```cpp
// Mal
float litrosPorMinuto = litrosRegados / minutos;           // si los dos son int, trunca

// Bien
float litrosPorMinuto = static_cast<float>(litrosRegados) / minutos;
```

Basta con que uno de los dos operandos sea `float` para que la división sea con decimales.

### Restar sin signo y quedar "negativo"

```cpp
// Mal
uint16_t distancia = sensorDistanciaMm();       // distancia al agua desde arriba del tanque
uint16_t alturaAgua = ALTO_TANQUE_MM - distancia;   // si distancia > ALTO_TANQUE_MM, da un número enorme

// Bien
uint16_t distancia = sensorDistanciaMm();
uint16_t alturaAgua = (distancia >= ALTO_TANQUE_MM) ? 0 : ALTO_TANQUE_MM - distancia;
```

Un sin signo nunca es negativo: si la resta "debería" dar -12, da 65524. Antes de restar valores sin signo, chequeá cuál es mayor.

### Comparar con signo contra sin signo

```cpp
// Mal
int diferencia = leerDiferencia();     // puede ser negativa
uint32_t limite = 10;
if (diferencia < limite) { /* ... */ } // -5 < 10 da falso

// Bien
int32_t limite = 10;
if (diferencia < limite) { /* ... */ }
```

Al comparar un `int` con un `uint32_t`, el `int` se convierte a sin signo. Activá las advertencias del compilador (en Arduino IDE: Preferencias, *Compiler warnings: All*) y prestá atención a `comparison of integer expressions of different signedness`.

### Elegir un contador demasiado chico

```cpp
// Mal
uint16_t pulsosCaudalimetro = 0;   // con 450 pulsos por litro, desborda a los 145 litros

// Bien
uint32_t pulsosCaudalimetro = 0;   // aguanta más de 9 millones de litros
```

Antes de elegir el tipo de un contador, hacé la cuenta del peor caso: cuánto puede crecer antes de que se reinicie.

## Ejercicio

El controlador tiene un sensor ultrasónico arriba del tanque de agua para riego. Mide la distancia hasta el agua en milímetros. El tanque mide 1200 mm de alto. La pantalla debería mostrar el porcentaje de llenado, pero siempre muestra 0 % o 100 %, y una vez mostró 5400 %.

Encontrá los dos problemas y corregí la función.

```cpp tanque.ino
constexpr uint16_t ALTO_TANQUE_MM = 1200;

int porcentajeTanque(uint16_t distanciaMm) {
  uint16_t alturaAgua = ALTO_TANQUE_MM - distanciaMm;
  return alturaAgua / ALTO_TANQUE_MM * 100;
}
```

<details>
<summary>Pista</summary>

Uno de los problemas es una división. El otro aparece cuando el sensor mide una distancia mayor que el alto del tanque, cosa que pasa con lecturas ruidosas o cuando el tanque está vacío.

</details>

<details>
<summary>Ver solución</summary>

```cpp
int porcentajeTanque(uint16_t distanciaMm) {
  if (distanciaMm >= ALTO_TANQUE_MM) {
    return 0;                                  // tanque vacío o lectura fuera de rango
  }
  uint16_t alturaAgua = ALTO_TANQUE_MM - distanciaMm;
  float fraccion = static_cast<float>(alturaAgua) / ALTO_TANQUE_MM;
  return static_cast<int>(lroundf(fraccion * 100.0f));
}
```

El primer problema es la división entera: `alturaAgua / ALTO_TANQUE_MM` da 0 salvo que el tanque esté exactamente lleno, y en ese caso da 1. Por eso solo aparecían 0 % y 100 %.

El segundo es la resta sin signo. Si el sensor mide 1250 mm, `1200 - 1250` en `uint16_t` da 65486, y 65486 / 1200 entre enteros es 54, que multiplicado por 100 da el 5400 % de la pantalla. Chequear el rango antes de restar lo evita.

</details>

## Resumen

- El tamaño de `int`, `long` y `double` depende de la placa. Los tipos de `<cstdint>` (`uint8_t`, `int16_t`, `uint32_t`…) tienen siempre el mismo tamaño.
- Un sin signo que se pasa del máximo da la vuelta a 0, y uno que baja de 0 da la vuelta al máximo. En los tipos con signo, pasarse es comportamiento indefinido.
- La división entre dos enteros descarta los decimales, aunque el resultado se guarde en un `float`.
- Comparar un tipo con signo contra uno sin signo convierte el negativo en un número enorme.
- Para convertir, usá `static_cast<T>(x)`. Trunca; para redondear, `lroundf`.
