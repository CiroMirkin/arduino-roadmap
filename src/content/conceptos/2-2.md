En [B.10](/conceptos/b-10) viste cómo se escribe una máquina de estados con `enum class` y `switch`, y en [1.6](/conceptos/1-6) la presentaste como patrón. Esta lección es sobre **diseñarlas**: identificar los estados de un proceso, decidir qué eventos producen cada cambio, dónde van las acciones, cómo poner tiempos máximos y cómo probarlas. Una **máquina de estados** describe un proceso como un conjunto de **estados** (en cada momento el sistema está en exactamente uno), **eventos** (cosas que pasan) y **transiciones** (qué evento, en qué estado, lleva a qué otro estado).

## Por qué te importa

Casi todo lo que hace el controlador del invernadero es un proceso con etapas: el ciclo de riego, la cortina de sombra (un motor que tarda en recorrer), la conexión al WiFi, la calibración de un sensor paso a paso, el modo de alarma. Escritos con `if` y variables `bool` sueltas, estos procesos terminan llenos de combinaciones imposibles (`desplegando && recogiendo`), de condiciones repetidas y de casos que nadie pensó.

Con una máquina de estados, cada estado es explícito y tiene sus reglas en un solo lugar. Las preguntas difíciles aparecen al diseñar, no en el campo: ¿qué pasa si se corta la luz mientras la cortina se despliega? ¿Y si el fin de carrera nunca avisa? ¿Qué hace el riego si se vacía el tanque a la mitad?

## Paso a paso

### 1. Reconocer el problema: banderas que se combinan

```cpp
bool desplegando = false;
bool recogiendo = false;
bool desplegada = false;
bool error = false;

void loop() {
  if (temperatura > 30 && !desplegada && !desplegando && !error) { desplegando = true; motorDesplegar(); }
  if (desplegando && finCarreraDesplegada()) { desplegando = false; desplegada = true; motorParar(); }
  if (temperatura < 27 && desplegada && !recogiendo) { recogiendo = true; motorRecoger(); }
  // ¿y si desplegando y recogiendo quedan los dos en true?
}
```

Cuatro `bool` son 16 combinaciones, y solo 5 tienen sentido. Cada `if` intenta excluir las que no, y basta con olvidarse una condición para que el motor reciba dos órdenes a la vez.

### 2. Identificar los estados

Un estado es una situación en la que el sistema se comporta de una manera definida. Para la cortina de sombra, que se despliega sobre el cultivo cuando hace calor:

| Estado | Qué está pasando |
|---|---|
| `Recogida` | quieta, recogida |
| `Desplegando` | motor encendido, desplegando |
| `Desplegada` | quieta, dando sombra |
| `Recogiendo` | motor encendido, recogiendo |
| `Falla` | algo salió mal: motor apagado, esperando que alguien revise |

Con `enum class EstadoCortina { Recogida, Desplegando, Desplegada, Recogiendo, Falla }` el sistema está siempre en exactamente uno. Las combinaciones imposibles ya no se pueden escribir.

### 3. Eventos y transiciones

Los **eventos** son lo que puede pasar: la temperatura cruzó un umbral, el fin de carrera avisó, se agotó un tiempo, el operario pidió algo. Una **transición** dice: "estando en tal estado, si pasa tal evento, ir a tal otro". Una tabla las hace explícitas:

| Estado | Evento | Siguiente |
|---|---|---|
| Recogida | hace calor | Desplegando |
| Desplegando | fin de carrera "desplegada" | Desplegada |
| Desplegando | pasaron 40 s | Falla |
| Desplegada | refrescó | Recogiendo |
| Recogiendo | fin de carrera "recogida" | Recogida |
| Recogiendo | pasaron 40 s | Falla |
| Falla | el operario reconoce | Recogiendo |

Lo que no está en la tabla, no pasa: en `Falla`, que haga calor no despliega nada. Escribir la tabla antes que el código obliga a pensar cada caso.

### 4. Acciones de entrada

Muchas cosas tienen que pasar una sola vez, al entrar a un estado: encender el motor al entrar en `Desplegando`, apagarlo al entrar en `Desplegada` o en `Falla`. Si se ponen en un único lugar, la función que cambia de estado, se ejecutan siempre:

```cpp
void cambiarA(EstadoCortina nuevo) {
  estado = nuevo;
  desdeMs = millis();
  switch (nuevo) {                 // acciones de entrada
    case EstadoCortina::Desplegando: motorDesplegar(); break;
    case EstadoCortina::Recogiendo:  motorRecoger();   break;
    default:                         motorParar();     break;   // los estados quietos paran el motor
  }
}
```

No importa desde qué estado se llegue a `Falla`: el motor se apaga, porque eso es parte de entrar a `Falla`.

### 5. Tiempo en el estado y tiempos máximos

Guardar cuándo se entró al estado (`desdeMs`) permite dos cosas: estados que duran un tiempo (regar 3 minutos, esperar 5 a que el agua se absorba) y **tiempos máximos** para todo estado que espera algo del mundo físico. Un fin de carrera roto, un caudalímetro que no da pulsos, un nodo que no responde: sin tiempo máximo, la máquina queda trabada para siempre en un estado con un motor o una bomba encendidos.

### 6. Separar la decisión de las acciones

La parte que decide a qué estado ir se puede escribir como una **función pura**:

```cpp
EstadoCortina siguiente(EstadoCortina actual, Evento evento);
```

Recibe el estado y lo que pasó, y devuelve el estado nuevo. No toca el motor ni lee el reloj. Las acciones quedan en `cambiarA`. Así la tabla del paso 3 se puede probar caso por caso, sin hardware y sin esperar 40 segundos (ver [2.8](/conceptos/2-8)).

## Ejemplos

### Ejemplo 1. La cortina de sombra, de banderas a máquina de estados

Los fines de carrera de la cortina están en el expansor PCF8574 (P0 desplegada, P1 recogida; ver [0.7](/conceptos/0-7)), así que se leen por I2C. Si el expansor no responde, la máquina no puede saber dónde está la cortina, y eso también lleva a `Falla`.

```cpp cortina-fsm.ino
#include <Wire.h>

enum class EstadoCortina : uint8_t { Recogida, Desplegando, Desplegada, Recogiendo, Falla };

constexpr uint8_t PIN_MOTOR_DESPLEGAR = 42;
constexpr uint8_t PIN_MOTOR_RECOGER = 47;
constexpr uint8_t DIRECCION_EXPANSOR = 0x20;
constexpr uint8_t BIT_DESPLEGADA = 0x01;   // P0, fin de carrera a GND
constexpr uint8_t BIT_RECOGIDA = 0x02;     // P1
constexpr uint32_t RECORRIDO_MAXIMO_MS = 40000;

EstadoCortina estado = EstadoCortina::Recogida;
uint32_t desdeMs = 0;

const char* nombre(EstadoCortina e) {
  switch (e) {
    case EstadoCortina::Recogida:    return "recogida";
    case EstadoCortina::Desplegando: return "desplegando";
    case EstadoCortina::Desplegada:  return "desplegada";
    case EstadoCortina::Recogiendo:  return "recogiendo";
    case EstadoCortina::Falla:       return "FALLA";
  }
  return "?";
}

void motor(bool desplegar, bool recoger) {
  digitalWrite(PIN_MOTOR_DESPLEGAR, desplegar ? HIGH : LOW);
  digitalWrite(PIN_MOTOR_RECOGER, recoger ? HIGH : LOW);
}

void cambiarA(EstadoCortina nuevo) {
  Serial.printf("cortina: %s -> %s\n", nombre(estado), nombre(nuevo));
  estado = nuevo;
  desdeMs = millis();
  switch (nuevo) {                                   // acciones de entrada
    case EstadoCortina::Desplegando: motor(true, false); break;
    case EstadoCortina::Recogiendo:  motor(false, true); break;
    default:                         motor(false, false); break;
  }
}

// Lee los dos fines de carrera del expansor. Devuelve false si no respondió.
bool leerFines(bool& desplegada, bool& recogida) {
  if (Wire.requestFrom(DIRECCION_EXPANSOR, static_cast<uint8_t>(1)) != 1) return false;
  uint8_t entradas = Wire.read();
  desplegada = (entradas & BIT_DESPLEGADA) == 0;
  recogida = (entradas & BIT_RECOGIDA) == 0;
  return true;
}

void actualizarCortina(float temperatura) {
  uint32_t enEstado = millis() - desdeMs;
  bool finDesplegada = false;
  bool finRecogida = false;
  if (!leerFines(finDesplegada, finRecogida)) {
    if (estado != EstadoCortina::Falla) cambiarA(EstadoCortina::Falla);
    return;
  }

  switch (estado) {
    case EstadoCortina::Recogida:
      if (temperatura > 30.0f) cambiarA(EstadoCortina::Desplegando);
      break;
    case EstadoCortina::Desplegando:
      if (finDesplegada) cambiarA(EstadoCortina::Desplegada);
      else if (enEstado > RECORRIDO_MAXIMO_MS) cambiarA(EstadoCortina::Falla);
      break;
    case EstadoCortina::Desplegada:
      if (temperatura < 27.0f) cambiarA(EstadoCortina::Recogiendo);
      break;
    case EstadoCortina::Recogiendo:
      if (finRecogida) cambiarA(EstadoCortina::Recogida);
      else if (enEstado > RECORRIDO_MAXIMO_MS) cambiarA(EstadoCortina::Falla);
      break;
    case EstadoCortina::Falla:
      break;   // solo sale con una acción del operario (no incluida en este ejemplo)
  }
}

void setup() {
  Serial.begin(115200);
  pinMode(PIN_MOTOR_DESPLEGAR, OUTPUT);
  pinMode(PIN_MOTOR_RECOGER, OUTPUT);
  motor(false, false);
  Wire.begin(8, 9);
  Wire.beginTransmission(DIRECCION_EXPANSOR);
  Wire.write(0xFF);   // los 8 pines del expansor como entradas
  Wire.endTransmission();
}

void loop() {
  static uint32_t ultimo = 0;
  if (millis() - ultimo >= 100) {   // la cortina es lenta: 10 lecturas por segundo sobran
    ultimo = millis();
    float temperatura = 31.0f;      // acá iría la lectura real
    actualizarCortina(temperatura);
  }
}
```

Es imposible que el motor reciba "desplegar" y "recoger" a la vez: solo `cambiarA` lo toca, y cada estado define un único comando. Cada estado de movimiento tiene su tiempo máximo. Los fines de carrera conviene filtrarlos con antirrebote como en [0.3](/conceptos/0-3); acá se omitió para no alargar el ejemplo.

### Ejemplo 2. La tabla de transiciones como función pura

La decisión de a qué estado ir se separa de las acciones. Los eventos se modelan con su propio `enum class`, y la función se prueba con una tabla de casos al arrancar.

```cpp transiciones.ino
enum class EstadoCortina : uint8_t { Recogida, Desplegando, Desplegada, Recogiendo, Falla };
enum class Evento : uint8_t { HaceCalor, Refresco, FinDesplegada, FinRecogida, TiempoAgotado, Reconocer };

EstadoCortina siguiente(EstadoCortina e, Evento ev) {
  using E = EstadoCortina;
  switch (e) {
    case E::Recogida:
      if (ev == Evento::HaceCalor) return E::Desplegando;
      break;
    case E::Desplegando:
      if (ev == Evento::FinDesplegada) return E::Desplegada;
      if (ev == Evento::TiempoAgotado) return E::Falla;
      break;
    case E::Desplegada:
      if (ev == Evento::Refresco) return E::Recogiendo;
      break;
    case E::Recogiendo:
      if (ev == Evento::FinRecogida) return E::Recogida;
      if (ev == Evento::TiempoAgotado) return E::Falla;
      break;
    case E::Falla:
      if (ev == Evento::Reconocer) return E::Recogiendo;   // al reconocer, recoger para quedar en un estado conocido
      break;
  }
  return e;   // cualquier otro evento: quedarse
}

struct Caso {
  EstadoCortina desde;
  Evento evento;
  EstadoCortina esperado;
};

const Caso CASOS[] = {
  {EstadoCortina::Recogida, Evento::HaceCalor,     EstadoCortina::Desplegando},
  {EstadoCortina::Recogida, Evento::Refresco,      EstadoCortina::Recogida},
  {EstadoCortina::Desplegando, Evento::FinDesplegada,    EstadoCortina::Desplegada},
  {EstadoCortina::Desplegando, Evento::TiempoAgotado, EstadoCortina::Falla},
  {EstadoCortina::Desplegando, Evento::Refresco,      EstadoCortina::Desplegando},   // termina de desplegar antes
  {EstadoCortina::Falla,    Evento::HaceCalor,     EstadoCortina::Falla},      // en falla no se mueve sola
  {EstadoCortina::Falla,    Evento::Reconocer,     EstadoCortina::Recogiendo},
};

void setup() {
  Serial.begin(115200);
  delay(500);
  int fallos = 0;
  for (size_t i = 0; i < sizeof(CASOS) / sizeof(CASOS[0]); i++) {
    const Caso& c = CASOS[i];
    bool ok = siguiente(c.desde, c.evento) == c.esperado;
    if (!ok) fallos++;
    Serial.printf("caso %u: %s\n", static_cast<unsigned>(i), ok ? "ok" : "FALLA");
  }
  Serial.printf("%d fallos\n", fallos);
}

void loop() {}
```

Cada fila de `CASOS` es una fila de la tabla del paso 3, más algunos casos de "no debería pasar nada", que son los que más bugs encuentran. `using E = EstadoCortina;` crea un alias corto dentro de la función. En el firmware real, `actualizarCortina` convierte lo que lee (temperatura, fines de carrera, reloj) en eventos, llama a `siguiente` y, si el estado cambió, llama a `cambiarA`.

### Ejemplo 3. El ciclo de riego completo

El riego tiene más estados que los de [1.6](/conceptos/1-6): un estado de bloqueo cuando no hay agua o la bomba funciona en seco, y una orden manual del operario que tiene prioridad.

```cpp riego-fsm.ino
enum class EstadoRiego : uint8_t { Esperando, Regando, Absorbiendo, Bloqueado };

struct EntradasRiego {
  float humedadSuelo;
  bool tanqueConAgua;
  bool hayFlujo;           // caudalímetro
  bool pedidoManual;       // OK en la vista Riego manual de la pantalla
};

class CicloRiego {
public:
  static constexpr uint32_t RIEGO_MS = 3UL * 60UL * 1000UL;
  static constexpr uint32_t ABSORCION_MS = 5UL * 60UL * 1000UL;
  static constexpr uint32_t ARRANQUE_FLUJO_MS = 5000;

  void actualizar(const EntradasRiego& in) {
    uint32_t t = millis() - _desdeMs;
    switch (_estado) {
      case EstadoRiego::Esperando:
        if (!in.tanqueConAgua) cambiarA(EstadoRiego::Bloqueado);
        else if (in.pedidoManual || in.humedadSuelo < 35.0f) cambiarA(EstadoRiego::Regando);
        break;

      case EstadoRiego::Regando:
        if (!in.tanqueConAgua) cambiarA(EstadoRiego::Bloqueado);
        else if (t > ARRANQUE_FLUJO_MS && !in.hayFlujo) cambiarA(EstadoRiego::Bloqueado);   // en seco
        else if (t >= RIEGO_MS) cambiarA(EstadoRiego::Absorbiendo);
        break;

      case EstadoRiego::Absorbiendo:
        if (t >= ABSORCION_MS) cambiarA(EstadoRiego::Esperando);   // recién ahora la lectura es confiable
        break;

      case EstadoRiego::Bloqueado:
        if (in.tanqueConAgua && in.pedidoManual) cambiarA(EstadoRiego::Esperando);   // el operario revisó
        break;
    }
  }

  EstadoRiego estado() const { return _estado; }

private:
  void cambiarA(EstadoRiego nuevo) {
    _estado = nuevo;
    _desdeMs = millis();
    bool bomba = (nuevo == EstadoRiego::Regando);   // acción de entrada: un solo lugar decide la bomba
    digitalWrite(4, bomba ? LOW : HIGH);            // relé activo en bajo
    Serial.printf("riego -> %d\n", static_cast<int>(nuevo));
  }

  EstadoRiego _estado = EstadoRiego::Esperando;
  uint32_t _desdeMs = 0;
};

CicloRiego riego;

void setup() {
  Serial.begin(115200);
  digitalWrite(4, HIGH);
  pinMode(4, OUTPUT);
}

void loop() {
  EntradasRiego in{30.0f, true, true, false};   // acá irían las lecturas reales
  riego.actualizar(in);
}
```

Todas las entradas llegan juntas en un `struct`, así la máquina no lee el hardware: solo decide. El estado `Bloqueado` protege la bomba en dos situaciones (tanque vacío y funcionamiento en seco) y no se sale solo: hace falta que el operario lo reconozca. `Absorbiendo` evita volver a regar antes de que el agua llegue al sensor. La bomba solo se enciende en un lugar, según el estado nuevo, así que no hay forma de dejarla encendida al pasar a otro estado.

## Errores comunes

### Estados implícitos en banderas

```cpp
// Mal
bool regando, esperandoAbsorcion, bloqueado;

// Bien
enum class EstadoRiego : uint8_t { Esperando, Regando, Absorbiendo, Bloqueado };
```

### Acciones repartidas en las transiciones

```cpp
// Mal: cada transición que sale de Regando tiene que acordarse de apagar la bomba
if (tanqueVacio) { apagarBomba(); estado = Bloqueado; }
if (t >= RIEGO_MS) { estado = Absorbiendo; }   // se olvidó de apagarla

// Bien: la acción depende del estado al que se entra, en un único lugar
void cambiarA(EstadoRiego nuevo) { /* la bomba se decide según el estado nuevo */ }
```

### Estados sin salida o sin tiempo máximo

Un estado que espera un evento externo (un fin de carrera, un pulso, una respuesta) sin tiempo máximo puede quedar trabado para siempre. Revisá cada estado: ¿qué pasa si el evento esperado nunca llega?

### Estado que no sobrevive a un reinicio

Si el equipo se reinicia en medio de `Desplegando`, arranca en `Recogida` aunque la cortina esté a medio desplegar. Al arrancar, la máquina debería averiguar el estado real (leer los fines de carrera) o ir a un estado conocido (recoger del todo).

## Ejercicio

La alarma de temperatura del controlador está escrita con banderas, y a veces la sirena queda sonando aunque la temperatura ya se normalizó. Escribí la tabla de estados y transiciones y reescribila como máquina de estados. Requisitos: si la temperatura supera 40 °C por más de 2 minutos, sonar; la sirena se puede silenciar con el botón OK; si la temperatura baja de 35 °C, todo vuelve a la normalidad.

```cpp alarma-banderas.ino
bool sobreTemperatura = false;
bool sonando = false;
bool silenciada = false;
uint32_t inicio = 0;

void actualizarAlarma(float t, bool botonSilenciar) {
  if (t > 40.0f && !sobreTemperatura) { sobreTemperatura = true; inicio = millis(); }
  if (sobreTemperatura && millis() - inicio > 120000 && !silenciada) { sonando = true; sirena(true); }
  if (botonSilenciar) { silenciada = true; sirena(false); }
  if (t < 35.0f) { sobreTemperatura = false; silenciada = false; }
}
```

```cpp alarma-fsm.ino
enum class EstadoAlarma : uint8_t { Normal, Alta, Sonando, Silenciada };

EstadoAlarma estadoAlarma = EstadoAlarma::Normal;
uint32_t desdeMs = 0;

void cambiarA(EstadoAlarma nuevo) {
  estadoAlarma = nuevo;
  desdeMs = millis();
  sirena(nuevo == EstadoAlarma::Sonando);   // la sirena suena solo en Sonando
}

void actualizarAlarma(float t, bool botonSilenciar) {
  switch (estadoAlarma) {
    case EstadoAlarma::Normal:
      if (t > 40.0f) cambiarA(EstadoAlarma::Alta);
      break;
    case EstadoAlarma::Alta:
      if (t < 35.0f) cambiarA(EstadoAlarma::Normal);
      else if (millis() - desdeMs > 120000) cambiarA(EstadoAlarma::Sonando);
      break;
    case EstadoAlarma::Sonando:
      if (t < 35.0f) cambiarA(EstadoAlarma::Normal);
      else if (botonSilenciar) cambiarA(EstadoAlarma::Silenciada);
      break;
    case EstadoAlarma::Silenciada:
      if (t < 35.0f) cambiarA(EstadoAlarma::Normal);
      break;
  }
}
```

El bug original: cuando la temperatura bajaba de 35 °C, las banderas se reiniciaban pero nadie apagaba la sirena, porque `sirena(false)` solo se llamaba al silenciar. En la máquina de estados, la sirena depende únicamente del estado al que se entra, así que volver a `Normal` la apaga siempre.

## Resumen

- Una máquina de estados reemplaza combinaciones de banderas por un estado explícito: el sistema está siempre en exactamente uno.
- Diseñala con una tabla de estado, evento y siguiente antes de escribir código. Lo que no está en la tabla, no pasa.
- Las acciones de entrada van en un único lugar (`cambiarA`), así se ejecutan siempre, sin importar de dónde se llegue.
- Guardá cuándo se entró a cada estado: permite duraciones y tiempos máximos para todo lo que espera al mundo físico.
- Separá la función de transiciones (pura, se prueba con casos) de las acciones sobre el hardware.
