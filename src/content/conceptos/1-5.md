En [B.6](/conceptos/b-6) viste qué hace `const` en cada lugar. Esta lección es sobre usarlo como **herramienta de diseño**: decidir desde el principio qué partes del sistema pueden modificar qué cosas, y dejar que el compilador lo haga cumplir. Un firmware *const-correct* es uno donde todo lo que no necesita modificar algo lo recibe o lo declara como `const`. El resultado es un sistema donde las responsabilidades de [1.1](/conceptos/1-1) están protegidas por el compilador, no solo por la buena voluntad.

## Por qué te importa

En el controlador del invernadero, solo algunos módulos deberían poder **accionar**: el control decide y los actuadores aplican. La pantalla, el reporte al backend y el registro en la tarjeta SD solo deberían **leer** el estado. Si cualquiera puede encender la bomba, tarde o temprano alguien lo hace desde un lugar inesperado ("agrego un botón de prueba en la pantalla que la encienda directo...") y la bomba queda encendida sin pasar por el tiempo máximo de riego.

`const` convierte esa regla de diseño en algo que el compilador verifica: si la pantalla recibe el estado como `const`, no puede llamar a nada que lo modifique, y el intento no compila. Además, en el ESP32 los datos `const` globales no ocupan RAM, y eso importa cuando hay tablas grandes.

## Paso a paso

### 1. Consultas y órdenes

Una forma simple de diseñar los métodos de una clase es separarlos en dos grupos:

- **Consultas**: responden una pregunta y no cambian nada. Llevan `const`. `porcentaje()`, `bajo()`, `regando()`.
- **Órdenes**: cambian el estado y, en general, no devuelven datos (o solo si la orden salió bien). `regar()`, `detener()`, `fijarUmbral()`.

Un método que hace las dos cosas a la vez (consulta y, de paso, modifica algo) sorprende a quien lo llama: pregunta si el tanque está bajo y, sin saberlo, reinicia un contador. Con la separación, el `const` en una consulta es una garantía para quien la usa.

### 2. Diseñar empezando por las consultas

Al diseñar una clase nueva, conviene escribir primero qué se le puede preguntar, y después qué se le puede ordenar:

```cpp
class Tanque {
public:
  // Consultas
  float porcentaje() const;
  bool bajo() const;
  bool vacio() const;
  uint32_t minutosHastaVacio(float litrosPorMinuto) const;

  // Órdenes
  void actualizar(uint16_t distanciaMm);
  void fijarAlarmaBajo(float porcentaje);
};
```

La mayoría de las clases tienen muchas más consultas que órdenes, y las consultas son las que usan más módulos. Si todas son `const`, el objeto se puede pasar como `const Tanque&` a casi todo el sistema.

### 3. Vistas de solo lectura

Con las consultas marcadas como `const`, un mismo objeto se puede entregar con distintos permisos:

```cpp
void dibujarEstado(const Tanque& tanque, const ZonaRiego& zona);   // solo lee
void controlarRiego(Tanque& tanque, ZonaRiego& zona);              // puede ordenar
```

La firma de cada función dice qué puede hacer. Revisar quién puede accionar la bomba es buscar quién recibe una `ZonaRiego&` sin `const`, en lugar de leer todo el proyecto.

### 4. No devolver referencias modificables al interior

```cpp
class Controlador {
public:
  const Configuracion& config() const { return _config; }   // leer: sí
  bool fijarConfig(const Configuracion& nueva);              // modificar: con validación
private:
  Configuracion _config;
};
```

Un getter que devuelve `Configuracion&` (sin `const`) le da a cualquiera acceso de escritura al interior del objeto, salteando toda validación. Devolver `const&` permite leer sin copiar y sin abrir esa puerta.

### 5. Datos constantes en la flash

En el ESP32, los datos globales `const` o `constexpr` se guardan en una sección de solo lectura de la flash, que el chip lee directamente. **No ocupan RAM.**

```cpp
constexpr float CURVA_SENSOR[] = {0.0f, 2.1f, 4.5f, /* ... 200 valores ... */};   // en la flash

float curvaEnRam[] = {0.0f, 2.1f, 4.5f, /* ... */};   // sin const: ocupa RAM
```

Una tabla de 200 `float` son 800 bytes. Marcar como `const` las tablas, los textos y las configuraciones por defecto que no cambian ahorra RAM sin ningún costo. (En los Arduino AVR esto requería `PROGMEM`; en el ESP32 alcanza con `const`.)

### 6. `mutable` y otras excepciones

A veces un método es una consulta desde afuera, pero necesita modificar algo interno que no forma parte del estado visible: una caché, un contador de diagnóstico, un mutex. Para eso existe `mutable`:

```cpp
class SensorSuelo {
public:
  float porcentaje() const {
    _consultas++;          // diagnóstico: no cambia lo que el sensor "es"
    return _porcentaje;
  }
private:
  float _porcentaje = 0.0f;
  mutable uint32_t _consultas = 0;
};
```

Usalo con mucha moderación: si lo que modifica cambia el resultado de otras consultas, no es una consulta. `const_cast` para quitar el `const` y modificar algo casi nunca es la respuesta: si hace falta, la firma está mal diseñada.

## Ejemplos

### Ejemplo 1. Una clase diseñada con consultas y órdenes

```cpp tanque.ino
class Tanque {
public:
  Tanque(uint16_t altoMm, float litrosTotales) : _altoMm(altoMm), _litrosTotales(litrosTotales) {}

  // Órdenes
  void actualizar(uint16_t distanciaMm) {
    uint16_t agua = (distanciaMm >= _altoMm) ? 0 : _altoMm - distanciaMm;
    _porcentaje = 100.0f * agua / _altoMm;
  }
  bool fijarAlarmaBajo(float porcentaje) {
    if (porcentaje < 5.0f || porcentaje > 50.0f) return false;
    _alarmaBajo = porcentaje;
    return true;
  }

  // Consultas
  float porcentaje() const { return _porcentaje; }
  float litros() const { return _litrosTotales * _porcentaje / 100.0f; }
  bool bajo() const { return _porcentaje < _alarmaBajo; }
  uint32_t minutosHastaVacio(float litrosPorMinuto) const {
    if (litrosPorMinuto <= 0.0f) return UINT32_MAX;
    return static_cast<uint32_t>(litros() / litrosPorMinuto);
  }

private:
  uint16_t _altoMm;
  float _litrosTotales;
  float _porcentaje = 0.0f;
  float _alarmaBajo = 20.0f;
};

void informar(const Tanque& t) {            // solo puede consultar
  Serial.printf("tanque %.0f%% (%.0f L)%s, %u min de riego\n",
                t.porcentaje(), t.litros(), t.bajo() ? " BAJO" : "",
                static_cast<unsigned>(t.minutosHastaVacio(12.0f)));
  // t.actualizar(500);                     // no compila: t es const
}

Tanque tanque(1200, 1000.0f);

void setup() {
  Serial.begin(115200);
  tanque.actualizar(900);                   // agua a 900 mm del borde: 25 %
  informar(tanque);                         // tanque 25% (250 L), 20 min de riego
}

void loop() {}
```

Todas las consultas son `const` y ninguna modifica nada. `minutosHastaVacio` usa otra consulta (`litros()`), lo que solo es posible porque las dos son `const`. La orden de configuración valida y devuelve si se aplicó.

### Ejemplo 2. La pantalla no puede accionar

El estado completo del invernadero se agrupa en un objeto. El control lo recibe modificable; la pantalla y el reporte, como `const`.

```cpp vistas.ino
class EstadoInvernadero {
public:
  // Consultas
  float temperatura() const { return _temperatura; }
  bool regando() const { return _regando; }
  bool ventanasAbiertas() const { return _ventanas; }

  // Órdenes (solo para el control)
  void registrarLectura(float t) { _temperatura = t; }
  void fijarRiego(bool r) { _regando = r; }
  void fijarVentanas(bool v) { _ventanas = v; }

private:
  float _temperatura = 0.0f;
  bool _regando = false;
  bool _ventanas = false;
};

void controlar(EstadoInvernadero& e) {          // el único que puede cambiar el estado
  e.fijarVentanas(e.temperatura() > 30.0f);
}

void dibujar(const EstadoInvernadero& e) {      // solo lectura
  Serial.printf("[pantalla] %.1f C | riego %s | ventanas %s\n", e.temperatura(),
                e.regando() ? "sí" : "no", e.ventanasAbiertas() ? "abiertas" : "cerradas");
  // e.fijarRiego(true);                        // no compila
}

void reportar(const EstadoInvernadero& e) {     // solo lectura
  Serial.printf("[backend] {\"t\":%.1f,\"riego\":%d}\n", e.temperatura(), e.regando());
}

EstadoInvernadero estado;

void setup() {
  Serial.begin(115200);
  estado.registrarLectura(31.5f);
  controlar(estado);
  dibujar(estado);
  reportar(estado);
}

void loop() {}
```

La regla "solo el control acciona" ya no depende de que todos la recuerden: está en las firmas. Si dentro de seis meses alguien quiere un botón en la pantalla para regar, va a tener que pasar por el control, que es donde están las reglas de seguridad del riego.

### Ejemplo 3. Una curva de calibración en la flash

Algunos sensores no son lineales y el fabricante da una tabla de valores. La tabla es constante: va en la flash, y una función `const`-correcta la usa para convertir.

```cpp curva.ino
struct PuntoCurva {
  uint16_t mv;
  float valor;
};

// Tabla del fabricante (ejemplo): milivoltios -> humedad relativa del suelo
constexpr PuntoCurva CURVA_HUMEDAD[] = {
  {1100, 100.0f}, {1300, 85.0f}, {1600, 65.0f}, {1900, 48.0f},
  {2200, 32.0f},  {2450, 18.0f}, {2650, 6.0f},  {2800, 0.0f},
};
constexpr size_t PUNTOS = sizeof(CURVA_HUMEDAD) / sizeof(CURVA_HUMEDAD[0]);

// Interpolación lineal entre los dos puntos de la tabla que rodean al valor
float interpolar(const PuntoCurva* curva, size_t n, uint16_t mv) {
  if (mv <= curva[0].mv) return curva[0].valor;
  if (mv >= curva[n - 1].mv) return curva[n - 1].valor;
  for (size_t i = 1; i < n; i++) {
    if (mv <= curva[i].mv) {
      const PuntoCurva& a = curva[i - 1];
      const PuntoCurva& b = curva[i];
      float t = static_cast<float>(mv - a.mv) / (b.mv - a.mv);
      return a.valor + t * (b.valor - a.valor);
    }
  }
  return curva[n - 1].valor;
}

void setup() {
  Serial.begin(115200);
  for (uint16_t mv : {1000, 1450, 2000, 2700, 3000}) {
    Serial.printf("%u mV -> %.1f%%\n", mv, interpolar(CURVA_HUMEDAD, PUNTOS, mv));
  }
}

void loop() {}
```

`CURVA_HUMEDAD` es `constexpr`: queda en la flash, no ocupa RAM y nada puede modificarla por error. `interpolar` recibe la tabla como `const PuntoCurva*`, así que sirve para cualquier tabla del mismo tipo, y promete no tocarla. Las referencias `const PuntoCurva&` dentro del bucle evitan copias y dejan clara la intención.

## Errores comunes

### Escribir las consultas sin `const` "y agregarlo después"

```cpp
// Mal: el día que alguien necesite un const Tanque&, nada compila
float porcentaje() { return _porcentaje; }

// Bien: desde el primer día
float porcentaje() const { return _porcentaje; }
```

Agregar `const` después obliga a revisar todas las consultas que llama cada consulta. Es más barato escribirlo bien al principio.

### Devolver el interior modificable

```cpp
// Mal
Configuracion& config() { return _config; }
controlador.config().humedadMinima = -5;   // sin validación

// Bien
const Configuracion& config() const { return _config; }
bool fijarHumedadMinima(float valor);      // valida
```

### Usar `const_cast` para "arreglar" un error de compilación

```cpp
// Mal
void dibujar(const Tanque& t) {
  const_cast<Tanque&>(t).actualizar(leerSensor());   // la pantalla actualizando el tanque
}
```

Si una función que recibe algo `const` necesita modificarlo, el problema es de diseño: o la función tiene una responsabilidad que no le corresponde, o la firma está mal.

### Tablas fijas sin `const`

```cpp
// Mal: 800 bytes de RAM para datos que nunca cambian
float curva[200] = { /* ... */ };

// Bien: en la flash
constexpr float CURVA[200] = { /* ... */ };
```

## Ejercicio

Esta clase controla una zona de riego. La pantalla necesita mostrar su estado recibiéndola como `const ZonaRiego&`, pero no compila. Además, la configuración se puede modificar desde afuera sin validar. Rediseñá la interfaz pública.

```cpp zona.ino
struct ConfigZona {
  float humedadMinima;
  float humedadMaxima;
};

class ZonaRiego {
public:
  bool regando() { return _regando; }
  float humedad() { return _humedad; }
  ConfigZona& config() { return _config; }
  bool necesitaAgua() {
    _ultimaConsulta = millis();
    return _humedad < _config.humedadMinima;
  }
  void actualizar(float humedad) { _humedad = humedad; }

private:
  ConfigZona _config = {35.0f, 55.0f};
  float _humedad = 0.0f;
  bool _regando = false;
  uint32_t _ultimaConsulta = 0;
};
```

```cpp zona.ino
class ZonaRiego {
public:
  // Consultas
  bool regando() const { return _regando; }
  float humedad() const { return _humedad; }
  const ConfigZona& config() const { return _config; }
  bool necesitaAgua() const { return _humedad < _config.humedadMinima; }

  // Órdenes
  void actualizar(float humedad) { _humedad = humedad; }
  bool fijarConfig(const ConfigZona& nueva) {
    if (nueva.humedadMinima < 5.0f || nueva.humedadMaxima > 95.0f ||
        nueva.humedadMinima >= nueva.humedadMaxima) {
      return false;
    }
    _config = nueva;
    return true;
  }

private:
  ConfigZona _config = {35.0f, 55.0f};
  float _humedad = 0.0f;
  bool _regando = false;
};
```

Las tres consultas simples ganaron `const`. `necesitaAgua()` modificaba `_ultimaConsulta`, un dato que nadie leía: se eliminó, y la consulta pasó a ser `const`. Si ese dato hiciera falta para diagnóstico, podría ser `mutable`, pero solo si no cambia ningún resultado de la clase. `config()` devuelve `const ConfigZona&`, y modificar la configuración pasa por `fijarConfig`, que valida que la mínima sea menor que la máxima y que las dos estén en un rango razonable. Ahora `dibujar(const ZonaRiego&)` compila.

## Resumen

- Separá consultas (`const`, no cambian nada) de órdenes (cambian el estado). Un método no debería hacer las dos cosas.
- Diseñá cada clase empezando por sus consultas, y marcalas `const` desde el primer día.
- Pasá `const T&` a todo módulo que solo lee: la firma documenta y el compilador verifica quién puede accionar.
- No devuelvas referencias modificables al interior de un objeto; para cambiar algo, una orden que valide.
- En el ESP32, los datos globales `const`/`constexpr` quedan en la flash y no ocupan RAM.
