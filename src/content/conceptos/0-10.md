El ESP32 tiene WiFi integrado. Con la librería `WiFi.h` se conecta a una red como cualquier celular (modo **estación**), y con `HTTPClient` hace peticiones HTTP a un servidor: un `GET` para pedir datos, un `POST` para enviarlos. Así es como el controlador del invernadero manda las lecturas al backend y recibe la configuración. Dos detalles importan desde el principio: `WiFi.begin()` no espera a estar conectado, y una petición HTTP sí espera la respuesta, así que necesita un tiempo máximo.

## Por qué te importa

El WiFi de un invernadero no es el de una oficina: el router está lejos, el agua de las plantas y las estructuras metálicas atenúan la señal, y la conexión a internet se corta. El controlador tiene que seguir regando y ventilando sin red, reconectarse solo cuando vuelve, y no perder las lecturas del rato en que no hubo conexión.

Los ejemplos básicos de internet no hacen nada de eso. Esperan la conexión en `setup()` con un bucle que no termina nunca si el router está apagado, hacen peticiones sin límite de tiempo, y si el envío falla, la lectura se pierde. Esta lección muestra las piezas de base; los reintentos con espera creciente y la idempotencia se ven en [3.5](/conceptos/3-5).

## Paso a paso

### 1. Conectarse sin bloquear

```cpp
#include <WiFi.h>

void setup() {
  WiFi.mode(WIFI_STA);                  // estación: se conecta a un router
  WiFi.begin("invernadero", "clave");   // vuelve enseguida
}

void loop() {
  if (WiFi.status() == WL_CONNECTED) {
    // hay red
  }
}
```

`WiFi.begin` inicia la conexión en segundo plano (la maneja una tarea del sistema) y vuelve al instante. `WiFi.status()` dice en qué estado está:

| Estado | Significado |
|---|---|
| `WL_CONNECTED` | conectado, con IP |
| `WL_DISCONNECTED` | desconectado o intentando |
| `WL_NO_SSID_AVAIL` | no encuentra la red |
| `WL_CONNECT_FAILED` | falló (por ejemplo, clave incorrecta) |

Por defecto, el ESP32 intenta reconectarse solo cuando pierde la red. Igual conviene vigilar el estado, para saber si se puede enviar y para reintentar si queda trabado (el ejemplo 2 de [B.10](/conceptos/b-10) es una máquina de estados para esto).

### 2. Datos útiles de la conexión

```cpp
Serial.println(WiFi.localIP());   // la IP que le dio el router
Serial.println(WiFi.RSSI());      // intensidad de la señal en dBm
```

El **RSSI** es negativo: -50 dBm es una señal excelente, -70 aceptable, por debajo de -80 la conexión va a fallar seguido. Enviarlo al backend junto con las lecturas ayuda a diagnosticar problemas de cobertura.

### 3. Una petición HTTP

```cpp
#include <HTTPClient.h>

HTTPClient http;
http.begin("http://192.168.0.10:3000/api/lecturas");
http.setConnectTimeout(3000);           // máximo para conectar
http.setTimeout(5000);                  // máximo para la respuesta
http.addHeader("Content-Type", "application/json");

int codigo = http.POST("{\"temperatura\":24.5}");
if (codigo >= 200 && codigo < 300) {
  String respuesta = http.getString();  // el cuerpo de la respuesta
}
http.end();                             // liberar la conexión
```

- `begin(url)` prepara la petición.
- `addHeader` agrega encabezados: el tipo de contenido, una clave de autenticación (ver [3.4](/conceptos/3-4)).
- `GET()` o `POST(cuerpo)` envían la petición y **esperan** la respuesta. Devuelven el código HTTP, o un número negativo si no hubo respuesta.
- `getString()` lee el cuerpo de la respuesta.
- `end()` cierra la conexión y libera memoria. Siempre, también cuando hubo error.

### 4. Los códigos de respuesta

| Código | Significado | Qué hacer |
|---|---|---|
| 200 a 299 | éxito | listo |
| 400 a 499 | error del pedido: datos inválidos, sin autorización, no existe | reintentar no sirve: revisar qué se envía |
| 500 a 599 | error del servidor | reintentar más tarde |
| negativo | no hubo respuesta: sin conexión, tiempo agotado | reintentar más tarde |

Distinguir estos casos importa: reintentar un 400 una y otra vez no lo arregla, y descartar una lectura por un -1 la pierde.

### 5. HTTPS

Si el backend está en internet, la comunicación tiene que ir cifrada (HTTPS). En el ESP32 se usa `WiFiClientSecure` con el certificado raíz de la autoridad que firmó el certificado del servidor:

```cpp
#include <WiFiClientSecure.h>

WiFiClientSecure clienteSeguro;
clienteSeguro.setCACert(CERTIFICADO_RAIZ);   // texto PEM del certificado raíz

HTTPClient http;
http.begin(clienteSeguro, "https://api.ejemplo.com/lecturas");
```

`setCACert` hace que el ESP32 verifique que realmente habla con tu servidor. `setInsecure()` saltea esa verificación: sirve para una prueba rápida, no para un equipo instalado. La gestión de certificados y claves se ve en [6.1](/conceptos/6-1).

### 6. Una petición HTTP bloquea

Mientras `POST` espera la respuesta, `loop()` está detenido: con una red lenta, pueden ser segundos. Tres formas de convivir con eso:

- Pedir poco seguido (una vez por minuto, no por segundo) y con tiempos máximos cortos.
- Agrupar varias lecturas en un solo envío.
- Mover la comunicación a una tarea de FreeRTOS propia, para que el control no se detenga nunca (ver [2.4](/conceptos/2-4)).

## Ejemplos

### Ejemplo 1. Conectarse y vigilar la señal

```cpp wifi-estado.ino
#include <WiFi.h>

void setup() {
  Serial.begin(115200);
  WiFi.mode(WIFI_STA);
  WiFi.begin("invernadero", "clave-del-wifi");
}

void loop() {
  static wl_status_t anterior = WL_IDLE_STATUS;
  wl_status_t actual = WiFi.status();

  if (actual != anterior) {
    anterior = actual;
    if (actual == WL_CONNECTED) {
      Serial.printf("conectado: IP %s, señal %d dBm\n",
                    WiFi.localIP().toString().c_str(), WiFi.RSSI());
    } else {
      Serial.printf("estado WiFi: %d\n", static_cast<int>(actual));
    }
  }
  // el resto del controlador sigue funcionando con o sin WiFi
}
```

Solo se imprime cuando el estado cambia, así el monitor serie muestra cada conexión y desconexión una vez.

### Ejemplo 2. Enviar lecturas y recibir la configuración

El controlador envía sus lecturas con un `POST` cada minuto, y cada 10 minutos pide la configuración (el umbral de riego) con un `GET`. La respuesta de la configuración es un número en texto plano, para no necesitar todavía una librería de JSON.

```cpp backend-basico.ino
#include <WiFi.h>
#include <HTTPClient.h>

constexpr const char* URL_LECTURAS = "http://192.168.0.10:3000/api/invernaderos/2/lecturas";
constexpr const char* URL_UMBRAL = "http://192.168.0.10:3000/api/invernaderos/2/umbral-riego";

int umbralRiego = 35;   // valor por defecto hasta recibir uno del backend

int enviarLectura(float temperatura, int humedad) {
  char cuerpo[64];
  snprintf(cuerpo, sizeof(cuerpo), "{\"temperatura\":%.1f,\"humedadSuelo\":%d}",
           temperatura, humedad);

  HTTPClient http;
  http.begin(URL_LECTURAS);
  http.setConnectTimeout(3000);
  http.setTimeout(5000);
  http.addHeader("Content-Type", "application/json");
  int codigo = http.POST(cuerpo);
  http.end();
  return codigo;
}

bool actualizarUmbral() {
  HTTPClient http;
  http.begin(URL_UMBRAL);
  http.setConnectTimeout(3000);
  http.setTimeout(5000);
  int codigo = http.GET();
  bool ok = false;
  if (codigo == 200) {
    int valor = http.getString().toInt();
    if (valor >= 5 && valor <= 95) {         // validar lo que llega de afuera
      umbralRiego = valor;
      ok = true;
    }
  }
  http.end();
  return ok;
}

void setup() {
  Serial.begin(115200);
  WiFi.mode(WIFI_STA);
  WiFi.begin("invernadero", "clave-del-wifi");
}

void loop() {
  static uint32_t ultimoEnvio = 0;
  static uint32_t ultimaConfig = 0;
  if (WiFi.status() != WL_CONNECTED) return;   // sin red: el resto del control sigue igual

  if (millis() - ultimoEnvio >= 60000) {
    ultimoEnvio = millis();
    int codigo = enviarLectura(24.5f, 41);
    if (codigo < 200 || codigo >= 300) {
      Serial.printf("envío fallido: %d\n", codigo);
    }
  }
  if (millis() - ultimaConfig >= 600000) {
    ultimaConfig = millis();
    Serial.printf("umbral: %d%%%s\n", umbralRiego, actualizarUmbral() ? "" : " (sin actualizar)");
  }
}
```

Cada función crea su `HTTPClient`, configura los tiempos máximos, hace la petición y llama a `end()` en todos los caminos. La configuración recibida se valida antes de usarla: un error en el backend no debería poder poner el umbral de riego en 0 o en 5000. El `return` cuando no hay WiFi es solo para este ejemplo; en el controlador completo, el riego y la ventilación siguen fuera de ese bloque.

### Ejemplo 3. No perder lecturas cuando no hay conexión

Si el envío falla, la lectura se guarda en una cola de pendientes en memoria, y se reenvía cuando vuelve la conexión, en orden. Si la cola se llena (un corte largo), se descartan las más viejas.

```cpp cola-envios.ino
#include <WiFi.h>
#include <HTTPClient.h>

struct Lectura {
  uint32_t momentoS;       // segundos desde el arranque (en el firmware real, hora real)
  float temperatura;
  uint8_t humedadSuelo;
};

class ColaPendientes {
public:
  static constexpr size_t CAPACIDAD = 120;   // dos horas de lecturas de un minuto

  void agregar(const Lectura& l) {
    if (_cantidad == CAPACIDAD) {             // llena: descartar la más vieja
      _inicio = (_inicio + 1) % CAPACIDAD;
      _cantidad--;
      _descartadas++;
    }
    _datos[(_inicio + _cantidad) % CAPACIDAD] = l;
    _cantidad++;
  }

  bool vacia() const { return _cantidad == 0; }
  const Lectura& primera() const { return _datos[_inicio]; }
  void quitarPrimera() {
    if (_cantidad == 0) return;
    _inicio = (_inicio + 1) % CAPACIDAD;
    _cantidad--;
  }
  size_t cantidad() const { return _cantidad; }
  uint32_t descartadas() const { return _descartadas; }

private:
  Lectura _datos[CAPACIDAD] = {};
  size_t _inicio = 0;
  size_t _cantidad = 0;
  uint32_t _descartadas = 0;
};

ColaPendientes pendientes;

int enviar(const Lectura& l) {
  char cuerpo[96];
  snprintf(cuerpo, sizeof(cuerpo),
           "{\"momento\":%lu,\"temperatura\":%.1f,\"humedadSuelo\":%d}",
           static_cast<unsigned long>(l.momentoS), l.temperatura, l.humedadSuelo);
  HTTPClient http;
  http.begin("http://192.168.0.10:3000/api/invernaderos/2/lecturas");
  http.setConnectTimeout(3000);
  http.setTimeout(5000);
  http.addHeader("Content-Type", "application/json");
  int codigo = http.POST(cuerpo);
  http.end();
  return codigo;
}

void vaciarPendientes() {
  int enviadas = 0;
  while (!pendientes.vacia() && enviadas < 5) {   // como mucho 5 por vuelta, para no bloquear mucho
    int codigo = enviar(pendientes.primera());
    if (codigo >= 200 && codigo < 300) {
      pendientes.quitarPrimera();
    } else if (codigo >= 400 && codigo < 500) {
      Serial.printf("lectura rechazada (%d), se descarta\n", codigo);
      pendientes.quitarPrimera();                 // reintentarla no la va a arreglar
    } else {
      return;                                     // sin red o error del servidor: más tarde
    }
    enviadas++;
  }
}

void setup() {
  Serial.begin(115200);
  WiFi.mode(WIFI_STA);
  WiFi.begin("invernadero", "clave-del-wifi");
}

void loop() {
  static uint32_t ultimaLectura = 0;
  static uint32_t ultimoIntento = 0;

  if (millis() - ultimaLectura >= 60000) {
    ultimaLectura = millis();
    pendientes.agregar({millis() / 1000, 24.5f, 41});   // acá irían las lecturas reales
  }

  if (WiFi.status() == WL_CONNECTED && !pendientes.vacia() &&
      millis() - ultimoIntento >= 10000) {
    ultimoIntento = millis();
    vaciarPendientes();
    Serial.printf("pendientes: %u, descartadas: %u\n",
                  static_cast<unsigned>(pendientes.cantidad()),
                  static_cast<unsigned>(pendientes.descartadas()));
  }
}
```

Toda lectura pasa por la cola, haya red o no: así hay un solo camino de envío. La cola es un buffer circular de tamaño fijo, sin memoria dinámica (ver [B.8](/conceptos/b-8)). Los errores se tratan según su tipo: un 4xx se descarta porque reenviarlo no lo arregla, y un error de red o un 5xx deja la lectura en la cola para el próximo intento. Si el envío se cortara justo después de que el backend guardó la lectura pero antes de recibir la respuesta, el controlador la reenviaría y el backend la guardaría dos veces: la solución es la idempotencia, que se ve en [3.5](/conceptos/3-5) y [4.3](/conceptos/4-3).

## Errores comunes

### Esperar la conexión en `setup()` para siempre

```cpp
// Mal: si el router está apagado, el controlador nunca llega a loop() ni riega
WiFi.begin(ssid, clave);
while (WiFi.status() != WL_CONNECTED) delay(500);

// Bien: conectar en segundo plano y consultar el estado en loop()
WiFi.begin(ssid, clave);
```

### Peticiones sin tiempo máximo

```cpp
// Mal: con una red lenta, el POST puede tardar muchos segundos
http.begin(url);
http.POST(cuerpo);

// Bien
http.begin(url);
http.setConnectTimeout(3000);
http.setTimeout(5000);
http.POST(cuerpo);
```

### Olvidar `end()` en un camino de error

```cpp
// Mal
int codigo = http.GET();
if (codigo != 200) return false;   // la conexión queda abierta
http.end();

// Bien
int codigo = http.GET();
bool ok = (codigo == 200);
http.end();
return ok;
```

### Tratar solo el 200 como éxito

```cpp
// Mal
if (codigo == 200) { /* éxito */ }

// Bien
if (codigo >= 200 && codigo < 300) { /* éxito */ }
```

### Credenciales en el código

La red y la clave escritas en el código quedan en el repositorio y en cada copia del firmware. En [6.1](/conceptos/6-1) se ve cómo guardarlas aparte, por ejemplo en NVS (ver [0.11](/conceptos/0-11)).

## Ejercicio

Esta función envía la lectura cada minuto. El controlador se congela por largos ratos cuando la red anda mal, se reinicia después de unos días con errores de memoria, y a veces registra como "enviada" una lectura que el backend nunca recibió. Encontrá los problemas y corregilos.

    delay(1000);

  HTTPClient http;

  int codigo = http.POST(cuerpo);
  if (codigo == -1) {
    Serial.println("falló");
    return;
  }
  Serial.println("enviada");
  http.end();
}
```

// Devuelve true solo si el backend confirmó la recepción
bool enviarLectura(float temperatura) {
  if (WiFi.status() != WL_CONNECTED) return false;   // no esperar: reintentar más tarde

  char cuerpo[48];
  snprintf(cuerpo, sizeof(cuerpo), "{\"temperatura\":%.1f}", temperatura);

  HTTPClient http;
  http.begin("http://192.168.0.10:3000/api/invernaderos/2/lecturas");
  http.setConnectTimeout(3000);
  http.setTimeout(5000);
  http.addHeader("Content-Type", "application/json");
  int codigo = http.POST(cuerpo);
  http.end();                                          // en todos los caminos

  if (codigo < 200 || codigo >= 300) {
    Serial.printf("envío fallido: %d (%s)\n", codigo,
                  codigo < 0 ? HTTPClient::errorToString(codigo).c_str() : "respuesta HTTP");
    return false;
  }
  return true;
}
```

El `while` con `delay` congelaba todo mientras no hubiera WiFi; ahora la función vuelve enseguida y quien la llama decide reintentar (por ejemplo, con la cola del ejemplo 3). Sin tiempos máximos, una red lenta trababa el `POST` varios segundos. Cada error devolvía antes de `http.end()`, y la conexión abierta perdía memoria cada vez: de ahí los reinicios después de días. Y el código solo trataba el -1 como error, así que un 500 del servidor o cualquier otro error negativo se registraba como "enviada". El `String` del cuerpo también se reemplazó por un buffer fijo (ver [B.12](/conceptos/b-12)).

## Resumen

- `WiFi.begin` conecta en segundo plano: consultá `WiFi.status()` en `loop()` en lugar de esperar con un bucle.
- El RSSI dice qué tan buena es la señal: por debajo de -80 dBm, esperá cortes.
- `HTTPClient`: `begin`, tiempos máximos, encabezados, `GET`/`POST`, y `end()` siempre.
- 2xx es éxito; 4xx es un error del pedido que reintentar no arregla; 5xx y negativos se reintentan más tarde.
- Para HTTPS, `WiFiClientSecure` con `setCACert`. Las peticiones bloquean: hacelas poco seguido, con tiempos máximos, o en su propia tarea.
