**JSON** es el formato de texto que usan casi todos los backends web para intercambiar datos: `{"temperatura":24.5,"humedad":41}`. Armarlo y leerlo a mano con `snprintf` y búsquedas de texto funciona para un par de campos, pero se vuelve frágil enseguida. **ArduinoJson** es la librería estándar para hacerlo en microcontroladores: arma y lee JSON con poca memoria, informa los errores y permite leer con valores por defecto. Esta lección usa la **versión 7** (ver [0.13](/conceptos/0-13) para las diferencias con la 6).

## Por qué te importa

El controlador del invernadero envía lecturas al backend y recibe configuración: umbrales de riego, horarios, la versión de firmware disponible. Todo en JSON. Los riesgos son los de siempre en firmware: memoria (un JSON grande puede no entrar), datos que llegan de afuera (incompletos, con un campo de otro tipo, con valores absurdos) y punteros que apuntan a memoria que ya no existe.

Una respuesta cortada por una conexión inestable que se interpreta sin chequear errores puede dejar el umbral de riego en 0. Un campo nuevo que el backend agregó sin avisar puede hacer que el JSON ya no entre en la memoria reservada. ArduinoJson da las herramientas para manejar todo eso; esta lección muestra cómo usarlas.

## Paso a paso

### 1. Armar un JSON (serializar)

```cpp
#include <ArduinoJson.h>

JsonDocument doc;
doc["invernadero"] = 2;
doc["temperatura"] = 24.5;
doc["humedadSuelo"] = 41;
doc["regando"] = true;

char salida[128];
size_t n = serializeJson(doc, salida, sizeof(salida));   // {"invernadero":2,"temperatura":24.5,...}
```

Un `JsonDocument` funciona como un diccionario: se le asignan valores por nombre. `serializeJson` escribe el texto en un buffer y devuelve cuántos caracteres escribió. `measureJson(doc)` dice cuántos va a necesitar, sin escribir, útil para chequear que el buffer alcanza.

### 2. Leer un JSON (deserializar)

```cpp
const char* texto = "{\"umbral\":38,\"modo\":\"automatico\"}";

JsonDocument doc;
DeserializationError error = deserializeJson(doc, texto);
if (error) {
  Serial.printf("JSON inválido: %s\n", error.c_str());
  return;
}

int umbral = doc["umbral"] | 35;              // 35 si no está o no es un número
const char* modo = doc["modo"] | "manual";
```

`deserializeJson` devuelve un `DeserializationError` que hay que revisar **siempre**: puede indicar JSON mal formado, texto cortado (`IncompleteInput`) o falta de memoria (`NoMemory`). Si hubo error, no se usa el documento.

El operador `|` de ArduinoJson es la forma de leer con un **valor por defecto**: si el campo falta o es de otro tipo, se usa el de la derecha.

### 3. Comprobar tipos y validar valores

```cpp
if (!doc["umbral"].is<int>()) { /* el campo falta o no es un entero */ }

int umbral = doc["umbral"] | 35;
if (umbral < 5 || umbral > 95) umbral = 35;   // fuera de rango: valor seguro
```

`is<T>()` dice si el campo existe y es del tipo indicado. Que un JSON esté bien formado no significa que tenga sentido: un umbral de -10 o de 500 es JSON válido. Todo lo que llega de afuera se valida antes de usarlo (ver [6.3](/conceptos/6-3)).

### 4. Arreglos y objetos anidados

```cpp
JsonDocument doc;
doc["invernadero"] = 2;
JsonArray lecturas = doc["lecturas"].to<JsonArray>();
for (int i = 0; i < 3; i++) {
  JsonObject l = lecturas.add<JsonObject>();
  l["t"] = 1000 + i * 60;
  l["temp"] = 24.0 + i;
}
// {"invernadero":2,"lecturas":[{"t":1000,"temp":24},{"t":1060,"temp":25},{"t":1120,"temp":26}]}

for (JsonObject l : doc["lecturas"].as<JsonArray>()) {
  float temp = l["temp"] | 0.0f;
}
```

`to<JsonArray>()` crea un arreglo en ese campo; `add<JsonObject>()` agrega un objeto al arreglo. Para leer, `as<JsonArray>()` permite recorrerlo con un `for`.

### 5. La memoria

En la versión 7, el `JsonDocument` pide memoria al heap a medida que la necesita, y la libera al destruirse. Algunas consecuencias:

- Un documento local en una función que se llama seguido reserva y libera memoria cada vez. Para algo que se repite cada minuto está bien; para algo muy frecuente, conviene reutilizar un documento (`doc.clear()`).
- Si no hay memoria suficiente, el documento queda incompleto: al armar, `doc.overflowed()` devuelve `true`; al leer, el error es `NoMemory`.
- Para respuestas con muchos campos que no se usan, un **filtro** le dice a `deserializeJson` qué campos guardar, y el resto se descarta mientras se lee:

```cpp
JsonDocument filtro;
filtro["umbral"] = true;
filtro["modo"] = true;
deserializeJson(doc, texto, DeserializationOption::Filter(filtro));
```

### 6. Cuidado con a qué apuntan los textos

Cuando se lee un texto con `doc["nombre"]` como `const char*`, el puntero apunta a memoria del documento, o incluso del buffer de entrada: si la entrada es un `char*` modificable, ArduinoJson no copia los textos, apunta directamente adentro de ese buffer (modo *zero-copy*). En los dos casos, ese puntero deja de ser válido cuando el documento o el buffer desaparecen. Si un texto tiene que durar más, se copia a un buffer propio:

```cpp
char nombre[32];
strlcpy(nombre, doc["nombre"] | "", sizeof(nombre));
```

Es el mismo problema de vida de los objetos que viste en [B.2](/conceptos/b-2) y [1.3](/conceptos/1-3).

## Ejemplos

### Ejemplo 1. Armar una lectura y leer una respuesta

El controlador envía su estado y el backend responde con el umbral de riego vigente.

```cpp json-basico.ino
#include <ArduinoJson.h>

int umbralRiego = 35;

size_t armarEstado(char* salida, size_t tam, float temperatura, int humedad, bool regando) {
  JsonDocument doc;
  doc["invernadero"] = 2;
  doc["temperatura"] = temperatura;
  doc["humedadSuelo"] = humedad;
  doc["regando"] = regando;
  if (measureJson(doc) >= tam) return 0;          // no entra en el buffer
  return serializeJson(doc, salida, tam);
}

bool aplicarRespuesta(const char* respuesta) {
  JsonDocument doc;
  DeserializationError error = deserializeJson(doc, respuesta);
  if (error) {
    Serial.printf("respuesta inválida: %s\n", error.c_str());
    return false;
  }
  if (!doc["umbralRiego"].is<int>()) return false;
  int nuevo = doc["umbralRiego"];
  if (nuevo < 5 || nuevo > 95) return false;      // valor absurdo: no se aplica
  umbralRiego = nuevo;
  return true;
}

void setup() {
  Serial.begin(115200);

  char cuerpo[128];
  if (armarEstado(cuerpo, sizeof(cuerpo), 24.5f, 41, false) > 0) {
    Serial.println(cuerpo);
  }

  aplicarRespuesta("{\"umbralRiego\":38}");
  aplicarRespuesta("{\"umbralRiego\":\"mucho\"}");   // tipo incorrecto: se ignora
  aplicarRespuesta("{\"umbralRiego\":38");           // cortado: IncompleteInput
  Serial.printf("umbral vigente: %d\n", umbralRiego);  // 38
}

void loop() {}
```

Las tres respuestas muestran los tres casos que hay que manejar: válida, con un tipo incorrecto y cortada. Solo la primera cambia el umbral. `measureJson` evita escribir un JSON cortado si el buffer no alcanza.

### Ejemplo 2. Un lote de lecturas, chequeando el tamaño

Cuando vuelve la conexión, el controlador envía las lecturas pendientes en un solo JSON (ver [3.1](/conceptos/3-1)). Antes de enviarlo, verifica que el documento se armó completo y que el texto entra en el buffer.

```cpp json-lote.ino
#include <ArduinoJson.h>

struct Lectura {
  uint32_t momentoS;
  float temperatura;
  uint8_t humedadSuelo;
};

// Devuelve la cantidad de bytes escritos, o 0 si no se pudo armar completo
size_t armarLote(const Lectura* lecturas, size_t n, char* salida, size_t tam) {
  JsonDocument doc;
  doc["invernadero"] = 2;
  doc["firmware"] = "1.5.0";
  JsonArray arreglo = doc["lecturas"].to<JsonArray>();
  for (size_t i = 0; i < n; i++) {
    JsonObject l = arreglo.add<JsonObject>();
    l["t"] = lecturas[i].momentoS;
    l["temp"] = serialized(String(lecturas[i].temperatura, 1));   // un decimal, no 24.500000
    l["suelo"] = lecturas[i].humedadSuelo;
  }

  if (doc.overflowed()) return 0;                 // no hubo memoria para armarlo entero
  if (measureJson(doc) >= tam) return 0;          // no entra en el buffer de salida
  return serializeJson(doc, salida, tam);
}

void setup() {
  Serial.begin(115200);
  Lectura pendientes[] = {
    {3600, 24.5f, 41}, {3660, 24.7f, 40}, {3720, 25.1f, 40},
  };

  char cuerpo[256];
  size_t n = armarLote(pendientes, 3, cuerpo, sizeof(cuerpo));
  if (n == 0) {
    Serial.println("el lote no entra: enviar en partes");
  } else {
    Serial.printf("%u bytes: %s\n", static_cast<unsigned>(n), cuerpo);
  }
}

void loop() {}
```

`serialized(...)` le dice a ArduinoJson que inserte ese texto tal cual, sin comillas: es una forma de controlar cuántos decimales salen. (Crea una `String` temporal por lectura, aceptable para un envío por minuto; para algo más frecuente, conviene redondear el `float` antes de asignarlo.) Si el lote no entra, quien llama puede enviarlo en partes más chicas.

### Ejemplo 3. Recibir la configuración con filtro y validación

El backend responde con un JSON grande (información del invernadero, del cultivo, de los usuarios) y el controlador solo necesita la sección de riego. Un filtro guarda solo lo necesario, y cada valor se valida antes de aplicarse.

```cpp json-config.ino
#include <ArduinoJson.h>

struct ConfigRiego {
  float humedadMinima;
  float humedadMaxima;
  uint32_t riegoMaximoS;
  char cultivo[24];
};

constexpr ConfigRiego CONFIG_POR_DEFECTO = {35.0f, 55.0f, 300, "sin nombre"};

bool leerConfig(const char* json, ConfigRiego& salida) {
  JsonDocument filtro;
  filtro["riego"]["humedadMinima"] = true;
  filtro["riego"]["humedadMaxima"] = true;
  filtro["riego"]["riegoMaximoS"] = true;
  filtro["cultivo"]["nombre"] = true;

  JsonDocument doc;
  DeserializationError error = deserializeJson(doc, json, DeserializationOption::Filter(filtro));
  if (error) {
    Serial.printf("config inválida: %s\n", error.c_str());
    return false;
  }

  ConfigRiego c = CONFIG_POR_DEFECTO;
  c.humedadMinima = doc["riego"]["humedadMinima"] | c.humedadMinima;
  c.humedadMaxima = doc["riego"]["humedadMaxima"] | c.humedadMaxima;
  c.riegoMaximoS = doc["riego"]["riegoMaximoS"] | c.riegoMaximoS;
  strlcpy(c.cultivo, doc["cultivo"]["nombre"] | CONFIG_POR_DEFECTO.cultivo, sizeof(c.cultivo));   // copia propia

  bool valida = c.humedadMinima >= 5.0f && c.humedadMaxima <= 95.0f &&
                c.humedadMinima < c.humedadMaxima &&
                c.riegoMaximoS >= 10 && c.riegoMaximoS <= 1800;
  if (!valida) {
    Serial.println("config fuera de rango: se descarta");
    return false;
  }
  salida = c;
  return true;
}

void setup() {
  Serial.begin(115200);
  const char* respuesta =
      "{\"invernadero\":{\"id\":2,\"nombre\":\"Norte\",\"superficie\":400},"
      "\"usuarios\":[{\"id\":7,\"rol\":\"admin\"},{\"id\":9,\"rol\":\"operario\"}],"
      "\"cultivo\":{\"nombre\":\"tomate perita\",\"variedad\":\"x\"},"
      "\"riego\":{\"humedadMinima\":38,\"humedadMaxima\":60,\"riegoMaximoS\":240}}";

  ConfigRiego config = CONFIG_POR_DEFECTO;
  if (leerConfig(respuesta, config)) {
    Serial.printf("%s: regar entre %.0f%% y %.0f%%, máximo %u s\n", config.cultivo,
                  config.humedadMinima, config.humedadMaxima,
                  static_cast<unsigned>(config.riegoMaximoS));
  }
}

void loop() {}
```

Los usuarios y los datos del invernadero se leen pero no se guardan: el documento solo ocupa lo que dice el filtro. La configuración se arma en una variable temporal, se valida completa y recién entonces se aplica: nunca queda a medio actualizar. El nombre del cultivo se copia a un arreglo propio, así sigue siendo válido después de que el documento desaparece. Con `HTTPClient`, en lugar de leer la respuesta en un buffer, se puede pasar `http.getStream()` directamente a `deserializeJson` para no guardar el texto completo; para eso conviene llamar antes a `http.useHTTP10(true)`, así la respuesta no llega en partes (*chunked*).

## Errores comunes

### No revisar el error de deserialización

```cpp
// Mal: con una respuesta cortada, umbral queda en 0
deserializeJson(doc, respuesta);
int umbral = doc["umbral"];

// Bien
if (deserializeJson(doc, respuesta)) return false;   // DeserializationError es verdadero si hubo error
int umbral = doc["umbral"] | 35;
```

### Guardar un puntero a un texto del documento

```cpp
// Mal: apunta a memoria que deja de existir
const char* ssid = doc["ssid"];

// Bien
char ssid[33];
strlcpy(ssid, doc["ssid"] | "", sizeof(ssid));
```

### Armar el JSON concatenando `String`

```cpp
// Mal: frágil (comillas, comas) y con muchas reservas en el heap
String json = "{\"temp\":" + String(t) + ",\"nombre\":\"" + nombre + "\"}";   // ¿y si el nombre tiene comillas?

// Bien
JsonDocument doc;
doc["temp"] = t;
doc["nombre"] = nombre;   // ArduinoJson escapa los caracteres especiales
serializeJson(doc, salida, sizeof(salida));
```

### Usar código de la versión 6 con la 7

`StaticJsonDocument<N>`, `DynamicJsonDocument` y `createNestedArray` son de la versión 6. Con la 7 dan errores o advertencias de obsoleto. Ver [0.13](/conceptos/0-13).

### Confiar en los tipos

Un campo que en las pruebas siempre fue número puede llegar como texto (`"38"`) si cambia el backend. `is<int>()` o el operador `|` con un valor por defecto evitan que eso se convierta en un 0 silencioso.

## Ejercicio

El controlador recibe comandos del backend como `{"accion":"regar","segundos":120}` o `{"accion":"ventanas","abrir":true}`. Escribí una función `interpretarComando(const char* json)` que valide el JSON, reconozca las dos acciones, valide los valores (riego entre 10 y 600 segundos) y devuelva un `struct Comando` con un campo que indique si el comando es válido. Cualquier otra cosa tiene que ser rechazada.

Un `enum class TipoComando { Invalido, Regar, Ventanas }` y un `struct` con el tipo, los segundos y si abrir. Usá `is<>()` para chequear los tipos de cada campo según la acción.

</details>

<details>
<summary>Ver solución</summary>

```cpp comando.ino
#include <ArduinoJson.h>

enum class TipoComando : uint8_t { Invalido, Regar, Ventanas };

struct Comando {
  TipoComando tipo = TipoComando::Invalido;
  uint16_t segundos = 0;
  bool abrir = false;
};

Comando interpretarComando(const char* json) {
  Comando c;
  JsonDocument doc;
  if (deserializeJson(doc, json)) return c;                 // JSON inválido

  const char* accion = doc["accion"] | "";
  if (strcmp(accion, "regar") == 0) {
    if (!doc["segundos"].is<int>()) return c;
    int s = doc["segundos"];
    if (s < 10 || s > 600) return c;                        // fuera de rango
    c.tipo = TipoComando::Regar;
    c.segundos = static_cast<uint16_t>(s);
  } else if (strcmp(accion, "ventanas") == 0) {
    if (!doc["abrir"].is<bool>()) return c;
    c.tipo = TipoComando::Ventanas;
    c.abrir = doc["abrir"];
  }
  return c;                                                  // acción desconocida: Invalido
}

void setup() {
  Serial.begin(115200);
  const char* pruebas[] = {
    "{\"accion\":\"regar\",\"segundos\":120}",
    "{\"accion\":\"regar\",\"segundos\":5000}",
    "{\"accion\":\"regar\",\"segundos\":\"120\"}",
    "{\"accion\":\"ventanas\",\"abrir\":true}",
    "{\"accion\":\"bailar\"}",
    "{\"accion\":\"regar\"",
  };
  for (const char* p : pruebas) {
    Comando c = interpretarComando(p);
    Serial.printf("%-40s -> tipo %d\n", p, static_cast<int>(c.tipo));
  }
}

void loop() {}
```

Solo dos de las seis pruebas son válidas: la primera (riego de 120 segundos) y la cuarta (abrir ventanas). El riego de 5000 segundos está fuera de rango, los `"120"` entre comillas son un texto y no un número, `bailar` no es una acción conocida, y la última está cortada. Todas devuelven `Invalido`, y el control simplemente no hace nada con ellas. Esta función es lógica pura, así que se puede probar en la PC como en [2.8](/conceptos/2-8).

</details>

## Resumen

- ArduinoJson arma JSON con `JsonDocument` y `serializeJson`, y lo lee con `deserializeJson`. Esta lección usa la versión 7.
- Después de `deserializeJson`, revisá siempre el error. Leé con `|` para tener valores por defecto, y `is<T>()` para chequear tipos.
- Validá los valores después de leerlos, y aplicá una configuración recién cuando está completa y es válida.
- Chequeá `overflowed()` y `measureJson()` al armar; usá filtros para respuestas grandes.
- Los textos leídos apuntan a memoria del documento o de la entrada: copialos si tienen que durar.
