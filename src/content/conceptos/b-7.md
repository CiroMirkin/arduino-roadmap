`static` es una de las palabras más confusas de C++ porque significa cosas distintas según dónde la escribas. Dentro de una función, una variable `static` conserva su valor entre llamadas. Fuera de una clase, en un archivo, `static` hace que una función o variable sea invisible para los demás archivos. Y dentro de una clase, `static` hace que un miembro pertenezca a la clase y no a cada objeto. Los tres usos tienen algo en común: la variable vive durante todo el programa, o el nombre queda restringido a un lugar.

## Por qué te importa

Los tres usos aparecen en el firmware del invernadero. Dentro de una función, `static uint32_t ultimo = 0;` hace que la variable conserve su valor entre llamadas; es el patrón de casi todo sketch que mide tiempo con `millis()`. Fuera de una función, `static` deja una función o variable visible solo en su archivo: si `riego.cpp` y `pantalla.cpp` tienen cada uno su `promedio()`, sin `static` el linker da `multiple definition`. Dentro de una clase, un método `static` no necesita un objeto, y por eso se puede pasar como callback a `attachInterrupt()`, que pide una función común y no sabe nada de objetos.

Si los confundís, aparecen bugs raros: un contador que vive en un header como `static` y cada archivo ve un valor distinto, o una variable que debía recalcularse y se calcula una sola vez.

## Paso a paso

### 1. Variables locales `static`: memoria entre llamadas

```cpp
void parpadearLed() {
  static uint32_t ultimoCambio = 0;   // se inicializa una sola vez
  static bool encendido = false;

  if (millis() - ultimoCambio >= 500) {
    ultimoCambio = millis();
    encendido = !encendido;
    digitalWrite(2, encendido);
  }
}
```

Una variable local común se crea al entrar a la función y desaparece al salir. Con `static`, se crea la primera vez que la ejecución pasa por la declaración y vive hasta que se apaga el equipo. La inicialización (`= 0`) ocurre esa única vez; las siguientes llamadas encuentran el valor que quedó.

Es como una variable global, con una diferencia útil: solo se puede usar dentro de esa función, así que nadie más la puede modificar por error.

### 2. `static` en un archivo: enlace interno

```cpp riego.cpp
#include "riego.h"

static uint32_t inicioRiegoMs = 0;     // solo visible en riego.cpp

static bool superoTiempoMaximo() {     // solo visible en riego.cpp
  return millis() - inicioRiegoMs > RIEGO_MAXIMO_MS;
}

void actualizarRiego() {               // sin static: la declara riego.h
  if (superoTiempoMaximo()) {
    detenerRiego();
  }
}
```

En [B.6](/conceptos/b-6) viste que el linker une todos los archivos y que cada nombre global puede definirse una sola vez. Una función o variable `static` fuera de una clase tiene *enlace interno*: el linker no la ve desde otros archivos. Dos archivos pueden tener su propia `static bool superoTiempoMaximo()` sin chocar.

Usalo para todo lo que es un detalle interno del archivo: funciones auxiliares y estado que nadie más debería tocar. Lo que no tiene `static` es parte de la interfaz pública y va declarado en el `.h`. (En C++ moderno también se usa un `namespace` sin nombre, `namespace { ... }`, que hace lo mismo para todo lo que tiene adentro.)

### 3. Miembros `static`: uno para toda la clase

```cpp
class Nodo {
public:
  Nodo() { cantidad++; }
  static uint8_t cantidad;    // una sola variable para todos los Nodo
private:
  float _temperatura = 0.0f;  // una por cada Nodo
};

uint8_t Nodo::cantidad = 0;   // definición: en un .cpp, una sola vez

Nodo norte;
Nodo sur;
// Nodo::cantidad vale 2
```

Cada objeto tiene su propia copia de los miembros comunes, pero un miembro `static` existe una sola vez, compartido por todos. Se accede con el nombre de la clase: `Nodo::cantidad`.

Un miembro `static` necesita una definición fuera de la clase, en un `.cpp` (`uint8_t Nodo::cantidad = 0;`). Desde C++17 se puede evitar escribiéndolo como `inline static uint8_t cantidad = 0;` dentro de la clase. Las constantes de clase se escriben `static constexpr` y no necesitan nada más:

```cpp
class Historial {
  static constexpr size_t CAPACIDAD = 12;   // constante de la clase
};
```

### 4. Métodos `static`: funciones de la clase sin objeto

```cpp
class Nodo {
public:
  static bool idValido(uint8_t id) { return id >= 1 && id <= 4; }
  // ...
};

if (Nodo::idValido(5)) { /* ... */ }   // no hace falta ningún Nodo
```

Un método `static` es una función que vive dentro de la clase pero no trabaja con ningún objeto en particular. No tiene `this`, así que no puede usar miembros comunes (`_temperatura`), solo miembros `static` y sus parámetros. Se llama con `Clase::metodo()`.

### 5. El puente con las funciones de C

Muchas APIs que vienen de C, como `attachInterrupt` para las interrupciones, piden un *puntero a función*: una función común, sin objeto. Un método común no sirve, porque necesita saber sobre qué objeto trabajar. Un método `static` sí sirve, porque es una función común con otro nombre.

El problema es que, dentro del método `static`, no hay objeto. La solución clásica es guardar un puntero `static` al objeto:

```cpp
class Caudalimetro {
public:
  explicit Caudalimetro(uint8_t pin) : _pin(pin) { instancia = this; }

  void begin() {
    pinMode(_pin, INPUT_PULLUP);
    attachInterrupt(digitalPinToInterrupt(_pin), alPulso, FALLING);
  }

private:
  static void IRAM_ATTR alPulso() {   // función común: attachInterrupt la acepta
    if (instancia) instancia->_pulsos++;
  }

  static Caudalimetro* instancia;     // apunta al único caudalímetro
  uint8_t _pin;
  volatile uint32_t _pulsos = 0;
};

Caudalimetro* Caudalimetro::instancia = nullptr;
```

Esto funciona mientras haya un solo objeto de esa clase: si creás dos, `instancia` apunta al último. Los detalles de las interrupciones (`IRAM_ATTR`, `volatile`) se ven en [B.11](/conceptos/b-11) y [0.8](/conceptos/0-8); acá lo importante es el mecanismo.

## Ejemplos

### Ejemplo 1. Variable local común y `static`, lado a lado

```cpp static-local.ino
int contarNormal() {
  int veces = 0;
  veces++;
  return veces;
}

int contarStatic() {
  static int veces = 0;
  veces++;
  return veces;
}

void setup() {
  Serial.begin(115200);
  for (int i = 0; i < 3; i++) {
    Serial.printf("normal: %d  static: %d\n", contarNormal(), contarStatic());
  }
  // normal: 1  static: 1
  // normal: 1  static: 2
  // normal: 1  static: 3
}

void loop() {}
```

### Ejemplo 2. Un módulo con su parte privada

El módulo de ventilación expone tres funciones en su header. Todo lo demás es `static` en el `.cpp`.

```cpp ventilacion.h
#pragma once

void iniciarVentilacion();
void actualizarVentilacion(float temperatura);
bool ventanasAbiertas();
```

```cpp ventilacion.cpp
#include <Arduino.h>
#include "ventilacion.h"

static constexpr uint8_t PIN_MOTOR = 7;
static constexpr float ABRIR_SOBRE_C = 30.0f;
static constexpr float CERRAR_BAJO_C = 27.0f;

static bool abiertas = false;

static void moverVentanas(bool abrir) {
  digitalWrite(PIN_MOTOR, abrir ? HIGH : LOW);
  abiertas = abrir;
}

void iniciarVentilacion() {
  pinMode(PIN_MOTOR, OUTPUT);
  moverVentanas(false);
}

void actualizarVentilacion(float temperatura) {
  if (!abiertas && temperatura > ABRIR_SOBRE_C) moverVentanas(true);
  if (abiertas && temperatura < CERRAR_BAJO_C) moverVentanas(false);
}

bool ventanasAbiertas() {
  return abiertas;
}
```

Desde otro archivo solo se puede llamar a las tres funciones del header. Nadie puede escribir `abiertas = true` sin mover el motor, porque `abiertas` no existe fuera de `ventilacion.cpp`. Es el mismo efecto que `private` en una clase (ver [B.3](/conceptos/b-3)), pero a nivel de archivo. Las `constexpr` a nivel de archivo ya tienen enlace interno; el `static` delante es redundante pero deja la intención explícita.

### Ejemplo 3. Un caudalímetro con interrupción, dos formas

El caudalímetro de la bomba genera un pulso por cada pequeña cantidad de agua que pasa. Cada pulso dispara una interrupción que tiene que sumar uno al contador del objeto.

Primero, la forma clásica con un puntero `static`, que funciona en cualquier placa Arduino:

```cpp caudalimetro.ino
class Caudalimetro {
public:
  Caudalimetro(uint8_t pin, float pulsosPorLitro)
    : _pin(pin), _pulsosPorLitro(pulsosPorLitro) {
    instancia = this;
  }

  void begin() {
    pinMode(_pin, INPUT_PULLUP);
    attachInterrupt(digitalPinToInterrupt(_pin), alPulso, FALLING);
  }

  float litros() const {
    noInterrupts();
    uint32_t copia = _pulsos;
    interrupts();
    return copia / _pulsosPorLitro;
  }

private:
  static void IRAM_ATTR alPulso() {
    if (instancia) instancia->_pulsos++;
  }

  static Caudalimetro* instancia;
  uint8_t _pin;
  float _pulsosPorLitro;
  volatile uint32_t _pulsos = 0;
};

Caudalimetro* Caudalimetro::instancia = nullptr;

Caudalimetro caudalimetro(15, 450.0f);

void setup() {
  Serial.begin(115200);
  caudalimetro.begin();
}

void loop() {
  static uint32_t ultimoInforme = 0;
  if (millis() - ultimoInforme >= 5000) {
    ultimoInforme = millis();
    Serial.printf("%.2f litros\n", caudalimetro.litros());
  }
}
```

El ESP32 tiene además `attachInterruptArg`, que le pasa a la función un puntero que vos elegís. Así el método `static` recibe el objeto como argumento y ya no hace falta `instancia`, con lo que podés tener varios caudalímetros:

```cpp caudalimetros.ino
class Caudalimetro {
public:
  Caudalimetro(uint8_t pin, float pulsosPorLitro)
    : _pin(pin), _pulsosPorLitro(pulsosPorLitro) {}

  void begin() {
    pinMode(_pin, INPUT_PULLUP);
    attachInterruptArg(digitalPinToInterrupt(_pin), alPulso, this, FALLING);
  }

  float litros() const {
    noInterrupts();
    uint32_t copia = _pulsos;
    interrupts();
    return copia / _pulsosPorLitro;
  }

private:
  static void IRAM_ATTR alPulso(void* arg) {
    static_cast<Caudalimetro*>(arg)->_pulsos++;
  }

  uint8_t _pin;
  float _pulsosPorLitro;
  volatile uint32_t _pulsos = 0;
};

Caudalimetro caudalCantero1(15, 450.0f);
Caudalimetro caudalCantero2(21, 450.0f);

void setup() {
  caudalCantero1.begin();
  caudalCantero2.begin();
}

void loop() {}
```

`this` se convierte en un `void*` (un puntero "a cualquier cosa") al registrarse, y dentro de `alPulso` se convierte de vuelta con `static_cast` (ver [B.1](/conceptos/b-1)). Muchas APIs de C usan este patrón de "función más dato de usuario"; cuando la API lo ofrece, es mejor que el puntero `static`.

## Errores comunes

### Una variable `static` en un header

```cpp
// Mal: estado.h, incluido desde sensores.cpp y pantalla.cpp
static uint32_t lecturasHoy = 0;   // cada .cpp tiene SU copia

// Bien: estado.h
extern uint32_t lecturasHoy;
// estado.cpp
uint32_t lecturasHoy = 0;
```

Este error no da ningún mensaje. El programa compila, cada archivo modifica su propia copia, y los valores no coinciden. Si una variable tiene que compartirse, es `extern` en el header y se define una vez (ver [B.6](/conceptos/b-6)).

### Olvidar la definición de un miembro `static`

```cpp
// Mal
class Nodo {
  static uint8_t cantidad;   // solo declarado
};
// undefined reference to `Nodo::cantidad'

// Bien, opción 1: definirlo en un .cpp
uint8_t Nodo::cantidad = 0;

// Bien, opción 2 (C++17): inline en la clase
class Nodo {
  inline static uint8_t cantidad = 0;
};
```

### Esperar que un `static` local se recalcule

```cpp
// Mal: el umbral se lee de la flash una sola vez, aunque después cambie
void controlarRiego(int humedad) {
  static int umbral = leerUmbralGuardado();
  if (humedad < umbral) regar();
}

// Bien: leerlo cada vez, o guardarlo en un lugar que se actualice al cambiar
void controlarRiego(int humedad, int umbral) {
  if (humedad < umbral) regar();
}
```

La inicialización de un `static` local ocurre solo la primera vez. Si el valor puede cambiar, no lo pongas en la inicialización.

### Usar miembros comunes desde un método `static`

```cpp
// Mal
class Nodo {
public:
  static void reiniciar() { _temperatura = 0.0f; }   // ¿de cuál nodo?
private:
  float _temperatura = 0.0f;
};

// Bien: un método común, o un método static que recibe el objeto
class Nodo {
public:
  void reiniciar() { _temperatura = 0.0f; }
private:
  float _temperatura = 0.0f;
};
```

Si un método necesita los datos de un objeto, no es `static`.

## Ejercicio

El controlador tiene dos archivos con funciones auxiliares, y el build falla con `multiple definition of 'promedio(float const*, unsigned int)'`. Además, la función `informarCiclo` debería numerar los ciclos (1, 2, 3...), pero siempre imprime `ciclo 1`. Corregí los dos problemas.

## Resumen

- Variable local `static`: se inicializa una vez y conserva su valor entre llamadas.
- `static` fuera de una clase: la función o variable solo existe en ese archivo. Usalo para todo lo que es interno del módulo.
- Miembro `static`: uno solo para toda la clase. Necesita definición en un `.cpp`, o `inline static` en C++17.
- Método `static`: función de la clase sin objeto y sin `this`. Sirve para APIs de C que piden un puntero a función.
- Nunca pongas una variable `static` en un header para compartirla: cada archivo tendría su propia copia.
