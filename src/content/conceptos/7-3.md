Los nombres e identificadores parecen lo más simple de un sistema, y por eso se diseñan con supuestos que los datos reales rompen enseguida: que un nombre no cambia, que es único, que solo tiene letras sin acento, que una letra ocupa un byte, que la dirección MAC identifica a un equipo para siempre. La defensa es separar dos cosas que se suelen mezclar: el **identificador**, interno, estable y sin significado, que se usa para relacionar datos; y el **nombre**, que es para las personas, se puede editar, repetir y escribir en cualquier idioma.

## Por qué te importa

En el sistema del invernadero hay muchos nombres: organizaciones, invernaderos, zonas, cultivos, usuarios, equipos. Los productores los escriben como quieren ("Almácigos", "Ñandú 2", "Invernadero de Don José"), los cambian cuando reorganizan, y a veces dos zonas de invernaderos distintos se llaman igual. Si el diseño supone otra cosa, los errores son de los que cuestan arreglar: historiales partidos cuando alguien renombra, usuarios duplicados que solo difieren en una tilde, o una pantalla del controlador que muestra caracteres rotos.

## Cómo funciona

*"Un nombre identifica algo."* Los nombres cambian (un renombre, una corrección de ortografía) y se repiten. Las tablas se relacionan por un `id` interno que no cambia nunca, y el nombre es una columna más, editable. Lo mismo vale para el email de un usuario: identifica para iniciar sesión, pero la gente cambia de email, así que las demás tablas apuntan al `id` del usuario (ver [5.1](/conceptos/5-1)).

*"Un nombre es único."* Dos productores pueden tener una zona "Norte". Cuando la unicidad importa, es dentro de un ámbito: el nombre de la zona es único **dentro de su invernadero**, no en todo el sistema.

*"Mayúsculas, acentos y espacios no importan"* (o al revés, *"siempre importan"*). "José" se puede escribir en Unicode de dos formas que se ven iguales y son bytes distintos (la é como un carácter, o como una e seguida de un acento). Para comparar o exigir unicidad, se normaliza: espacios recortados, minúsculas y la misma forma de Unicode (NFC).

*"Una letra es un byte."* En UTF-8, la á, la ñ y la ü ocupan 2 bytes, y un emoji, 4. En el backend, `length()` de PostgreSQL cuenta caracteres; en C++, `strlen()` cuenta bytes. Recortar un texto por bytes puede partir un carácter por la mitad. Y la fuente de la pantalla del controlador puede no tener la Ñ.

*"El hardware identifica al equipo."* La dirección MAC o el número de serie del chip parecen un buen identificador, pero si se reemplaza la placa de un controlador, el equipo lógico (su invernadero, su configuración, su historial) tiene que seguir siendo el mismo. El backend asigna el identificador del equipo al darlo de alta (ver [3.4](/conceptos/3-4)); el dato del hardware se guarda como un atributo más.

*"Los identificadores son secretos."* Un `id` consecutivo (1, 2, 3...) se adivina. No es un problema si cada ruta verifica a quién pertenece el objeto (ver [6.2](/conceptos/6-2)); sí lo es si alguien usa el `id` como si fuera una contraseña, por ejemplo en un link "público" para compartir un tablero. Para eso, un token aleatorio largo.

## Ejemplo

En la base, nombres únicos dentro de su ámbito, comparados después de normalizar:

```sql zonas-nombres.sql
-- El nombre se guarda tal como lo escribió el usuario, para mostrarlo.
-- La unicidad se exige sobre la versión normalizada: sin espacios en los bordes,
-- en minúsculas y en forma NFC. "Almácigos" y " almácigos " chocan.
CREATE UNIQUE INDEX zonas_nombre_unico
    ON zonas (invernadero_id, lower(normalize(btrim(nombre), NFC)));
```

`normalize` existe desde PostgreSQL 13 y requiere que la base use UTF-8. El índice es sobre una expresión: el nombre original queda intacto para mostrarlo, y la comparación se hace sobre la versión normalizada. Como el nombre no se usa en ninguna relación, renombrar una zona es un `UPDATE` de una fila.

En el controlador, recortar un nombre UTF-8 sin partir un carácter:

```cpp recortar-utf8.ino
#include <string.h>

// Copia como máximo maxBytes de origen, sin cortar un carácter UTF-8 por la mitad.
// destino tiene que tener lugar para maxBytes + 1.
void copiarRecortado(char* destino, const char* origen, size_t maxBytes) {
  size_t n = strlen(origen);
  if (n > maxBytes) {
    n = maxBytes;
    // Los bytes de continuación de UTF-8 tienen la forma 10xxxxxx.
    // Si el corte cae sobre uno, se retrocede hasta el comienzo del carácter.
    while (n > 0 && (static_cast<unsigned char>(origen[n]) & 0xC0) == 0x80) {
      --n;
    }
  }
  memcpy(destino, origen, n);
  destino[n] = '\0';
}

void setup() {
  Serial.begin(115200);
  char corto[17];
  copiarRecortado(corto, "Plantines Ñandú", 16);   // 17 bytes
  Serial.printf("[%s] %u bytes\n", corto, static_cast<unsigned>(strlen(corto)));
  // [Plantines Ñand] 15 bytes
}

void loop() {}
```

Se mira el byte que quedaría **afuera** del corte: si es un byte de continuación, el carácter empezó antes y no entra completo, así que se retrocede. El resultado es siempre UTF-8 válido. Que la pantalla pueda dibujar la Ñ depende de la fuente: con U8g2 (ver [0.7](/conceptos/0-7)), `drawUTF8` y una fuente terminada en `_tf`, como `u8g2_font_6x10_tf`, la dibujan; `drawStr` o una fuente `_tr` (solo ASCII) no. Conviene probar con nombres reales de clientes, no con "Zona 1".

## Cuándo sí y cuándo no

- Las relaciones entre tablas, siempre por un identificador interno sin significado. Nunca por nombre, email o MAC.
- La unicidad de un nombre, solo si el negocio la necesita, dentro de su ámbito y sobre el nombre normalizado.
- Los nombres se guardan tal como los escribió el usuario; se normaliza para comparar, no para mostrar.
- Los largos se validan en caracteres para el usuario, y en bytes donde hay buffers de tamaño fijo (el firmware, ver [B.12](/conceptos/b-12)).
- Para ordenar alfabéticamente en castellano (que la ñ vaya después de la n), la base tiene que usar una intercalación (*collation*) del idioma.

## Resumen

- El identificador es interno, estable y sin significado; el nombre es para las personas y se edita.
- Los nombres se repiten: la unicidad, cuando hace falta, es dentro de un ámbito y sobre el texto normalizado.
- En UTF-8 una letra puede ocupar varios bytes: `strlen` cuenta bytes, y recortar por bytes puede partir un carácter.
- El equipo lógico lo identifica el backend, no la MAC de la placa, que cambia si se reemplaza.
- Un `id` consecutivo se adivina: no reemplaza la verificación de acceso ni sirve como secreto.
