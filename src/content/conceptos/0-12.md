Un ESP32 despierto, con WiFi o BLE, consume entre 80 y 250 mA: una batería de 2000 mAh dura un día. En **deep sleep**, el chip apaga la CPU, la RAM principal y las radios, y solo queda funcionando un pequeño controlador de bajo consumo (el **RTC**), que gasta del orden de 10 µA. Un nodo que duerme casi todo el tiempo y se despierta unos segundos para medir y transmitir puede funcionar meses con la misma batería. Al despertar, el programa vuelve a empezar desde `setup()`.

## Por qué te importa

Los nodos sensores del invernadero están lejos de cualquier enchufe. Si mandan una lectura cada 5 minutos y pasan el resto del tiempo despiertos, la batería se cambia todas las semanas; durmiendo, dura meses. El deep sleep es lo que hace práctico un nodo a batería.

Pero cambia la forma de programar. No hay un `loop()` que corra para siempre: el nodo despierta, hace su trabajo en `setup()` y se vuelve a dormir. Las variables comunes se pierden en cada ciclo. Solo algunos pines pueden despertarlo, y un pin mal configurado lo despierta solo cada pocos segundos, gastando la batería sin que nadie se dé cuenta.

## Paso a paso

### 1. Los modos de consumo

| Modo | Qué queda encendido | Consumo aproximado del chip | Al despertar |
|---|---|---|---|
| Activo con radio | todo | 80 a 250 mA | (no duerme) |
| Light sleep | RAM, estado de la CPU pausado | menos de 1 mA | sigue en la línea siguiente |
| Deep sleep | solo el RTC y su memoria | unos 10 µA | arranca desde `setup()` |

El consumo real de una placa de desarrollo es mayor, porque el regulador de voltaje, el LED de encendido y el chip USB también consumen. Para un nodo a batería se usan placas preparadas para bajo consumo, o un módulo ESP32 sin esos componentes.

### 2. Qué se pierde y qué se conserva

Al despertar de un deep sleep, todo lo que estaba en la RAM principal se perdió: variables globales, `static`, objetos. El programa arranca como si se hubiera encendido.

Lo que tiene que sobrevivir entre ciclos va en la **memoria RTC** (8 KB en el ESP32):

```cpp
RTC_DATA_ATTR uint32_t ciclos = 0;            // se inicializa en 0 solo al encender
RTC_DATA_ATTR float ultimaTemperatura = 0.0f;
```

Lo que tiene que sobrevivir a un corte de batería va en la flash (ver [0.11](/conceptos/0-11)).

### 3. Despertar por tiempo

```cpp
esp_sleep_enable_timer_wakeup(5ULL * 60ULL * 1000000ULL);   // 5 minutos, en microsegundos
esp_deep_sleep_start();                                      // no vuelve
```

El tiempo va en **microsegundos** y como `uint64_t`. Escribilo con `ULL` para que la cuenta se haga en 64 bits: 40 minutos en microsegundos ya no entran en un entero de 32 bits (ver [B.1](/conceptos/b-1)). `esp_deep_sleep_start()` no vuelve nunca: la próxima línea que se ejecuta es la primera de `setup()`, en el siguiente despertar.

### 4. Despertar por un pin

```cpp
#include <driver/rtc_io.h>

constexpr gpio_num_t PIN_BOTON = GPIO_NUM_33;   // tiene que ser un RTC GPIO

rtc_gpio_pullup_en(PIN_BOTON);                  // pull-up que funciona dormido
rtc_gpio_pulldown_dis(PIN_BOTON);
esp_sleep_enable_ext0_wakeup(PIN_BOTON, 0);     // despertar cuando el pin esté en LOW
```

**ext0** despierta cuando un pin está en un nivel. Solo funciona con los **RTC GPIO**: en el ESP32 clásico, 0, 2, 4, 12 a 15, 25 a 27 y 32 a 39. Durante el sueño, los pull-up comunes (`INPUT_PULLUP`) se apagan, así que se activan los del dominio RTC con `rtc_gpio_pullup_en`. Sin eso, el pin flota y el nodo se despierta solo, al azar.

Hay más fuentes: **ext1** (varios pines a la vez), el sensor táctil y el coprocesador ULP. Los chips más nuevos, como el ESP32-C3, no tienen ext0 y usan `esp_deep_sleep_enable_gpio_wakeup`: revisá la documentación de tu chip.

### 5. Por qué despertó

```cpp
switch (esp_sleep_get_wakeup_cause()) {
  case ESP_SLEEP_WAKEUP_TIMER: /* tocaba medir */ break;
  case ESP_SLEEP_WAKEUP_EXT0:  /* alguien presionó el botón */ break;
  default:                     /* se encendió o se reinició */ break;
}
```

`setup()` usa la causa para decidir qué hacer: medir y dormir, mostrar algo porque alguien presionó el botón, o inicializar todo porque el equipo se acaba de encender.

### 6. El ciclo de un nodo a batería

```text
despertar → setup(): leer sensores → transmitir → preparar el próximo despertar → dormir
```

Todo el trabajo se hace en `setup()`, y `loop()` queda vacío. El tiempo despierto define la duración de la batería: medir lleva milisegundos, pero conectarse al WiFi puede llevar 1 a 3 segundos, y BLE unos cientos de milisegundos. Cuanto menos tiempo despierto, mejor.

## Ejemplos

### Ejemplo 1. Dormir y contar los despertares

```cpp dormir-basico.ino
RTC_DATA_ATTR uint32_t despertares = 0;

void setup() {
  Serial.begin(115200);
  despertares++;

  if (esp_sleep_get_wakeup_cause() == ESP_SLEEP_WAKEUP_TIMER) {
    Serial.printf("desperté por el temporizador (vez %u)\n", static_cast<unsigned>(despertares));
  } else {
    Serial.println("arranque normal (encendido o reset)");
  }

  Serial.println("durmiendo 10 segundos...");
  Serial.flush();                                   // esperar que salga el texto antes de dormir
  esp_sleep_enable_timer_wakeup(10ULL * 1000000ULL);
  esp_deep_sleep_start();
}

void loop() {}   // nunca se llega acá
```

Mirá el monitor serie: el contador sube en cada ciclo porque es `RTC_DATA_ATTR`. Si presionás el botón de reset de la placa, vuelve a 0: un reset sí borra la memoria RTC. `Serial.flush()` espera a que se termine de enviar el texto; sin eso, lo último puede no llegar a salir antes de que el chip se apague.

### Ejemplo 2. El nodo: medir cada 5 minutos o cuando se presiona el botón

El nodo despierta cada 5 minutos, mide y transmite. También tiene un botón: si alguien lo presiona, mide en el momento (útil para probar el nodo al instalarlo).

```cpp nodo-ciclo.ino
#include <driver/rtc_io.h>

constexpr gpio_num_t PIN_BOTON = GPIO_NUM_33;
constexpr uint64_t INTERVALO_US = 5ULL * 60ULL * 1000000ULL;

RTC_DATA_ATTR uint32_t lecturasEnviadas = 0;

float medirTemperatura() { return 24.5f; }   // acá iría el sensor real
bool transmitir(float t) {                    // acá iría el BLE (ver 0.9)
  Serial.printf("transmitiendo %.1f C\n", t);
  return true;
}

void dormir() {
  rtc_gpio_pullup_en(PIN_BOTON);
  rtc_gpio_pulldown_dis(PIN_BOTON);
  esp_sleep_enable_ext0_wakeup(PIN_BOTON, 0);
  esp_sleep_enable_timer_wakeup(INTERVALO_US);
  Serial.flush();
  esp_deep_sleep_start();
}

void setup() {
  Serial.begin(115200);
  rtc_gpio_deinit(PIN_BOTON);                 // devolver el pin al modo GPIO normal

  esp_sleep_wakeup_cause_t causa = esp_sleep_get_wakeup_cause();
  if (causa == ESP_SLEEP_WAKEUP_EXT0) {
    Serial.println("lectura manual (botón)");
  }

  if (transmitir(medirTemperatura())) {
    lecturasEnviadas++;
  }
  Serial.printf("lecturas enviadas desde el encendido: %u\n",
                static_cast<unsigned>(lecturasEnviadas));
  dormir();
}

void loop() {}
```

Se habilitan dos fuentes a la vez: lo que ocurra primero despierta al nodo. `rtc_gpio_deinit` al arrancar devuelve el pin al control normal, por si el programa lo quiere leer despierto. Con un ciclo de unos 300 ms despierto cada 5 minutos, el nodo pasa el 99,9 % del tiempo durmiendo.

### Ejemplo 3. Transmitir solo cuando hace falta

Transmitir es lo que más consume. El nodo mide cada 5 minutos, pero solo transmite si la lectura cambió de forma importante o si pasó media hora desde la última transmisión. Además, si la batería está baja, mide cada 15 minutos.

```cpp nodo-ahorro.ino
constexpr float CAMBIO_MINIMO_C = 0.5f;
constexpr uint32_t CICLOS_MAXIMOS_SIN_ENVIAR = 6;   // 6 x 5 min = 30 min
constexpr float BATERIA_BAJA_V = 3.5f;

RTC_DATA_ATTR float ultimaEnviada = -1000.0f;       // valor imposible: obliga a enviar la primera
RTC_DATA_ATTR uint32_t ciclosSinEnviar = 0;

float medirTemperatura() { return 24.5f; }          // acá iría el sensor real
float medirBateria() { return 3.8f; }               // ver 0.4
bool transmitir(float t, float bateria) {
  Serial.printf("enviando %.1f C, batería %.2f V\n", t, bateria);
  return true;
}

void setup() {
  Serial.begin(115200);

  float temperatura = medirTemperatura();
  float bateria = medirBateria();

  bool cambioImportante = fabsf(temperatura - ultimaEnviada) >= CAMBIO_MINIMO_C;
  bool hayQueReportar = ciclosSinEnviar + 1 >= CICLOS_MAXIMOS_SIN_ENVIAR;

  if (cambioImportante || hayQueReportar) {
    if (transmitir(temperatura, bateria)) {
      ultimaEnviada = temperatura;
      ciclosSinEnviar = 0;
    }
  } else {
    ciclosSinEnviar++;
    Serial.println("sin cambios: no se transmite");
  }

  uint64_t minutos = (bateria < BATERIA_BAJA_V) ? 15 : 5;
  Serial.flush();
  esp_sleep_enable_timer_wakeup(minutos * 60ULL * 1000000ULL);
  esp_deep_sleep_start();
}

void loop() {}
```

La memoria RTC guarda el último valor enviado y cuántos ciclos pasaron sin enviar, así cada despertar puede decidir. Una temperatura estable de madrugada genera una transmisión cada media hora en lugar de seis; un cambio brusco se reporta en el siguiente ciclo. La transmisión periódica obligatoria le sirve al controlador para saber que el nodo sigue vivo: si pasa más de media hora sin noticias, algo le pasó.

## Errores comunes

### Despertar con un pin que no es RTC

```cpp
// Mal (ESP32 clásico): el GPIO 23 no es RTC
esp_sleep_enable_ext0_wakeup(GPIO_NUM_23, 0);

// Bien
esp_sleep_enable_ext0_wakeup(GPIO_NUM_33, 0);
```

### Un pin de despertar flotando

```cpp
// Mal: sin pull-up durante el sueño, el pin flota y despierta al nodo solo
esp_sleep_enable_ext0_wakeup(PIN_BOTON, 0);

// Bien
rtc_gpio_pullup_en(PIN_BOTON);
rtc_gpio_pulldown_dis(PIN_BOTON);
esp_sleep_enable_ext0_wakeup(PIN_BOTON, 0);
```

El síntoma: la batería dura días en vez de meses. Imprimí la causa del despertar en cada ciclo durante las pruebas.

### Esperar que las variables sobrevivan

```cpp
// Mal: siempre vale 1
uint32_t ciclos = 0;
void setup() { ciclos++; }

// Bien
RTC_DATA_ATTR uint32_t ciclos = 0;
```

### Tiempos en 32 bits

```cpp
// Mal: 60 minutos en microsegundos desborda un int de 32 bits
esp_sleep_enable_timer_wakeup(60 * 60 * 1000000);

// Bien
esp_sleep_enable_timer_wakeup(60ULL * 60ULL * 1000000ULL);
```

### Perder los últimos mensajes del monitor serie

Sin `Serial.flush()` antes de `esp_deep_sleep_start()`, el chip se duerme antes de terminar de enviar el texto, y parece que el programa nunca llegó a esa línea.

## Ejercicio

Este nodo debería dormir una hora entre lecturas, numerar sus transmisiones y despertar también con un botón en el GPIO 27. En las pruebas, se despierta mucho antes de la hora, el número de transmisión siempre es 1, y a veces se despierta sin que nadie toque el botón. Corregilo.

```cpp nodo-problemas.ino
uint32_t numeroTransmision = 0;

void setup() {
  Serial.begin(115200);
  numeroTransmision++;
  Serial.printf("transmisión %u\n", numeroTransmision);

  esp_sleep_enable_ext0_wakeup(GPIO_NUM_27, 0);
  esp_sleep_enable_timer_wakeup(60 * 60 * 1000000);
  esp_deep_sleep_start();
}

void loop() {}
```

<summary>Ver solución</summary>

```cpp nodo-corregido.ino
#include <driver/rtc_io.h>

constexpr gpio_num_t PIN_BOTON = GPIO_NUM_27;   // el 27 es RTC GPIO en el ESP32 clásico

RTC_DATA_ATTR uint32_t numeroTransmision = 0;

void setup() {
  Serial.begin(115200);
  rtc_gpio_deinit(PIN_BOTON);

  numeroTransmision++;
  Serial.printf("transmisión %u (causa %d)\n", static_cast<unsigned>(numeroTransmision),
                static_cast<int>(esp_sleep_get_wakeup_cause()));

  rtc_gpio_pullup_en(PIN_BOTON);
  rtc_gpio_pulldown_dis(PIN_BOTON);
  esp_sleep_enable_ext0_wakeup(PIN_BOTON, 0);
  esp_sleep_enable_timer_wakeup(60ULL * 60ULL * 1000000ULL);
  Serial.flush();
  esp_deep_sleep_start();
}

void loop() {}
```

`60 * 60 * 1000000` son 3.600.000.000, que no entra en un `int` de 32 bits (el máximo es 2.147.483.647): el resultado desbordaba y el temporizador recibía otro número. Con `ULL` la cuenta se hace en 64 bits. `numeroTransmision` estaba en la RAM principal y se perdía en cada sueño; con `RTC_DATA_ATTR` se conserva. Y el GPIO 27 flotaba durante el sueño: cualquier ruido lo llevaba a `LOW` y despertaba al nodo. Imprimir la causa del despertar ayuda a encontrar este tipo de problema.

</details>

## Resumen

- En deep sleep el ESP32 consume unos 10 µA; al despertar arranca desde `setup()`.
- Solo sobrevive lo marcado con `RTC_DATA_ATTR` (y lo guardado en la flash).
- Despertar por tiempo: `esp_sleep_enable_timer_wakeup` en microsegundos, como `uint64_t`.
- Despertar por pin (ext0): solo RTC GPIO, con pull-up del dominio RTC para que no flote.
- Un nodo a batería hace todo en `setup()`: medir, transmitir solo si hace falta, y volver a dormir lo antes posible.
