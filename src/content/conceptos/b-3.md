Una clase agrupa datos y las funciones que trabajan con esos datos. En C++ se puede declarar con `struct` o con `class`, que son casi lo mismo. `public` y `private` deciden qué partes puede usar el resto del programa, y el **constructor** deja el objeto en un estado válido desde el momento en que se crea.

## Por qué te importa

En Python o JavaScript cualquier código puede leer y escribir cualquier atributo de un objeto. En C++ podés decidir que no. Eso importa en firmware porque muchos objetos representan hardware: si el resto del programa puede escribir `bomba.encendida = true` sin tocar el pin, la variable dice que la bomba está encendida y la bomba está apagada. El controlador muestra "regando" en la pantalla y el cantero se seca.

Hay otra diferencia que sorprende: en C++, un miembro que nadie inicializó no vale `undefined` ni `None`, vale lo que haya quedado en esa memoria. Un umbral sin inicializar puede valer 0, 1e38 o cualquier otra cosa, y cambiar de un arranque al siguiente. Los constructores existen para que eso no pase.

## Paso a paso

### 1. `struct` para agrupar datos

```cpp
struct Lectura {
  float temperatura;
  float humedadAire;
  float humedadSuelo;
};

Lectura actual = {24.5f, 68.0f, 41.0f};
Serial.println(actual.temperatura);   // 24.50
```

Un `struct` como este es un paquete de datos. Se inicializa con llaves, en el orden en que se declararon los campos, y cada campo se lee con un punto.

### 2. Métodos: funciones que pertenecen al tipo

```cpp
struct Lectura {
  float temperatura;
  float humedadAire;
  float humedadSuelo;

  bool hayQueVentilar() const {
    return temperatura > 30.0f || humedadAire > 85.0f;
  }
};

Lectura actual = {31.2f, 70.0f, 40.0f};
if (actual.hayQueVentilar()) { /* ... */ }
```

Dentro de un método, los campos se usan directamente: `temperatura` es la temperatura de *ese* objeto. El `const` al final promete que el método no modifica nada; se explica en [B.4](/conceptos/b-4).

### 3. `public` y `private`

```cpp
class Bomba {
public:
  void encender() {
    digitalWrite(_pin, HIGH);
    _encendida = true;
  }
  void apagar() {
    digitalWrite(_pin, LOW);
    _encendida = false;
  }
  bool encendida() const { return _encendida; }

private:
  uint8_t _pin = 26;
  bool _encendida = false;
};

Bomba bomba;
bomba.encender();          // bien
// bomba._encendida = true; // no compila: '_encendida' is private
```

Lo que está en `public:` es la interfaz: lo que el resto del programa puede usar. Lo que está en `private:` solo lo pueden tocar los métodos de la clase. A las reglas que la clase mantiene siempre ("`_encendida` coincide con el estado del pin") se las llama *invariantes*, y `private` es lo que permite garantizarlas.

El guion bajo en `_pin` es solo una convención para distinguir miembros de variables locales. Algunos proyectos usan `m_pin` o `pin_`; lo importante es ser consistente.

### 4. `struct` o `class`: la convención

El lenguaje solo distingue una cosa: en un `struct` todo es `public` hasta que digas lo contrario, y en una `class` todo es `private`. Lo demás es una convención que vale la pena seguir:

- **`struct`** cuando son datos que se pueden cambiar libremente, sin reglas entre ellos: una lectura, una configuración, un mensaje.
- **`class`** cuando hay invariantes que proteger: un objeto que controla hardware o que lleva un estado que tiene que ser coherente.

Quien lee `struct Lectura` ya sabe que son datos; quien lee `class Bomba` sabe que hay que usar sus métodos.

### 5. Constructores

```cpp
class Bomba {
public:
  explicit Bomba(uint8_t pin) : _pin(pin) {}

  void begin() {
    pinMode(_pin, OUTPUT);
    apagar();
  }
  void encender() { digitalWrite(_pin, HIGH); _encendida = true; }
  void apagar()   { digitalWrite(_pin, LOW);  _encendida = false; }
  bool encendida() const { return _encendida; }

private:
  uint8_t _pin;
  bool _encendida = false;   // valor por defecto del miembro
};

Bomba bombaCantero1(26);
Bomba bombaCantero2(25);
```

El constructor tiene el mismo nombre que la clase y no devuelve nada. Se ejecuta automáticamente cuando el objeto se crea. Hay dos formas de dar valores iniciales: en el constructor, o directamente en la declaración del miembro (`bool _encendida = false;`), que se usa cuando ningún constructor dice otra cosa.

`explicit` evita una conversión automática sorprendente: sin él, `Bomba b = 26;` compilaría y crearía una bomba en el pin 26. Ponelo en todo constructor que reciba un solo parámetro.

> En Arduino, los objetos globales se construyen antes de `setup()`, incluso antes de que el framework termine de preparar el hardware. Por eso el constructor solo guarda el número de pin, y la configuración real (`pinMode`) se hace en `begin()`, que se llama desde `setup()`. Las librerías de Arduino siguen la misma costumbre: `Serial.begin()`, `Wire.begin()`, `WiFi.begin()`.

### 6. La lista de inicialización

Lo que va después de los dos puntos (`: _pin(pin)`) es la lista de inicialización. Da valor a los miembros *antes* de que empiece el cuerpo del constructor. Hay miembros que solo se pueden inicializar ahí:

```cpp
class ControlRiego {
public:
  ControlRiego(Bomba& bomba, uint32_t duracionMaximaMs)
    : _bomba(bomba), _duracionMaximaMs(duracionMaximaMs) {}

private:
  Bomba& _bomba;                     // una referencia: no puede quedar sin ligar
  const uint32_t _duracionMaximaMs;  // const: no se puede asignar después
};
```

Una regla que conviene saber: los miembros se inicializan en el orden en que están **declarados en la clase**, no en el orden de la lista. Escribí la lista en el mismo orden que las declaraciones y nunca vas a tener problemas.

## Ejemplos

### Ejemplo 1. Un `struct` de datos que viaja entre funciones

```cpp lectura.ino
struct Lectura {
  float temperatura;
  float humedadAire;
  float humedadSuelo;
};

Lectura leerSensores() {
  Lectura l;
  l.temperatura = 24.5f;    // acá irían las lecturas reales
  l.humedadAire = 68.0f;
  l.humedadSuelo = 41.0f;
  return l;
}

void mostrar(const Lectura& l) {
  Serial.printf("%.1f C | aire %.0f%% | suelo %.0f%%\n",
                l.temperatura, l.humedadAire, l.humedadSuelo);
}

void setup() {
  Serial.begin(115200);
  Lectura actual = leerSensores();
  mostrar(actual);   // 24.5 C | aire 68% | suelo 41%
}

void loop() {}
```

Un `struct` permite devolver varios valores juntos y pasarlos a otra función como una sola cosa. `mostrar` lo recibe como `const Lectura&` para no copiarlo, como se explica en [B.2](/conceptos/b-2).

### Ejemplo 2. Una clase que protege el estado de un actuador

```cpp bomba.ino
class Bomba {
public:
  explicit Bomba(uint8_t pin) : _pin(pin) {}

  void begin() {
    pinMode(_pin, OUTPUT);
    apagar();
  }

  void encender() {
    if (_encendida) return;
    digitalWrite(_pin, HIGH);
    _encendida = true;
    _inicioMs = millis();
    _arranquesHoy++;
  }

  void apagar() {
    digitalWrite(_pin, LOW);
    _encendida = false;
  }

  bool encendida() const { return _encendida; }
  uint32_t arranquesHoy() const { return _arranquesHoy; }
  uint32_t msEncendida() const { return _encendida ? millis() - _inicioMs : 0; }

private:
  uint8_t _pin;
  bool _encendida = false;
  uint32_t _inicioMs = 0;
  uint32_t _arranquesHoy = 0;
};

Bomba bomba(26);

void setup() {
  Serial.begin(115200);
  bomba.begin();
  bomba.encender();
}

void loop() {
  if (bomba.msEncendida() > 10000) {   // apagar a los 10 segundos
    bomba.apagar();
    Serial.print("arranques hoy: ");
    Serial.println(bomba.arranquesHoy());
  }
}
```

Fijate en lo que la clase garantiza sola: no se puede contar un arranque sin encender el pin, encender dos veces seguidas no cuenta dos arranques, y el tiempo encendida se calcula siempre desde el momento real del arranque. Nada de eso depende de que el resto del programa lo haga bien.

### Ejemplo 3. Configuración en un `struct`, comportamiento en una `class`

La ventilación del invernadero abre las ventanas cuando hace calor y las cierra cuando la temperatura baja. Para que no abra y cierre una y otra vez cuando la temperatura ronda el umbral, abre en un valor y cierra en otro más bajo. Esos valores son datos de configuración; la lógica es de la clase.

```cpp ventilacion.ino
struct ConfigVentilacion {
  float abrirSobreC;    // abrir por encima de esta temperatura
  float cerrarBajoC;    // cerrar por debajo de esta
  uint8_t pinMotor;
};

class ControlVentilacion {
public:
  explicit ControlVentilacion(const ConfigVentilacion& config)
    : _config(validar(config)) {}

  void begin() {
    pinMode(_config.pinMotor, OUTPUT);
    digitalWrite(_config.pinMotor, LOW);
  }

  void actualizar(float temperatura) {
    if (!_abierta && temperatura > _config.abrirSobreC) {
      digitalWrite(_config.pinMotor, HIGH);
      _abierta = true;
    } else if (_abierta && temperatura < _config.cerrarBajoC) {
      digitalWrite(_config.pinMotor, LOW);
      _abierta = false;
    }
  }

  bool abierta() const { return _abierta; }

private:
  // Si la configuración no tiene sentido, se corrige en lugar de dejar
  // un objeto que no funciona: cerrar siempre por debajo de abrir.
  static ConfigVentilacion validar(ConfigVentilacion c) {
    if (c.cerrarBajoC >= c.abrirSobreC) {
      c.cerrarBajoC = c.abrirSobreC - 2.0f;
    }
    return c;
  }

  const ConfigVentilacion _config;
  bool _abierta = false;
};

ControlVentilacion ventilacion({30.0f, 27.0f, 27});

void setup() {
  ventilacion.begin();
}

void loop() {
  float temperatura = 28.5f;   // acá iría la lectura real
  ventilacion.actualizar(temperatura);
}
```

El constructor es el único lugar por donde entra la configuración, así que es el lugar natural para validarla: después de construirse, el objeto siempre tiene un `cerrarBajoC` menor que `abrirSobreC`. En firmware de Arduino no se usan excepciones, así que el constructor no puede "fallar"; corregir el valor (o guardar un indicador de error que se pueda consultar) es la alternativa habitual. La configuración es `const`: una vez construido, el control no la puede cambiar por accidente. El `static` de `validar` significa que la función no usa ningún objeto en particular, algo que vas a ver en [B.7](/conceptos/b-7).

## Errores comunes

### Configurar hardware en el constructor de un objeto global

```cpp
// Mal
class Bomba {
public:
  explicit Bomba(uint8_t pin) : _pin(pin) { pinMode(_pin, OUTPUT); }
  // ...
};
Bomba bomba(26);   // se construye antes de setup()

// Bien
class Bomba {
public:
  explicit Bomba(uint8_t pin) : _pin(pin) {}
  void begin() { pinMode(_pin, OUTPUT); }
  // ...
};
Bomba bomba(26);
void setup() { bomba.begin(); }
```

El síntoma es desconcertante: a veces funciona y a veces no, según la placa y la versión del core. Con un `begin()` explícito no hay dudas sobre cuándo se configura el hardware.

### Dejar un miembro sin inicializar

```cpp
// Mal
class Contador {
public:
  void sumar() { _total++; }
private:
  uint32_t _total;          // en un objeto local, arranca con basura
};

// Bien
class Contador {
public:
  void sumar() { _total++; }
private:
  uint32_t _total = 0;
};
```

Los objetos globales arrancan con todo en cero, pero los locales y los que se crean con `new` no. Poné un valor por defecto en todos los miembros, aunque hoy el objeto sea global.

### Estado público que se desincroniza

```cpp
// Mal
struct Ventana {
  uint8_t pinMotor;
  bool abierta;
};
ventana.abierta = true;   // el motor nunca se movió

// Bien
class Ventana {
public:
  void abrir() { digitalWrite(_pinMotor, HIGH); _abierta = true; }
  bool abierta() const { return _abierta; }
private:
  uint8_t _pinMotor;
  bool _abierta = false;
};
```

Si un dato tiene que mantenerse coherente con otra cosa (el hardware, otro campo), es una `class` con el dato `private`.

### Lista de inicialización en otro orden que las declaraciones

```cpp
// Mal
class Rango {
public:
  explicit Rango(int minima) : _minima(minima), _maxima(_minima + 10) {}
private:
  int _maxima;   // se inicializa primero, cuando _minima todavía es basura
  int _minima;
};

// Bien: mismo orden en las declaraciones y en la lista
class Rango {
public:
  explicit Rango(int minima) : _minima(minima), _maxima(minima + 10) {}
private:
  int _minima;
  int _maxima;
};
```

En la versión correcta, además, `_maxima` se calcula con el parámetro `minima` y no con el miembro, así que ya no depende del orden.

## Ejercicio

El calefactor del invernadero está modelado como un `struct` público, y en distintas partes del código aparecen líneas como `calefactor.encendido = true;` sin tocar el pin, o `calefactor.potencia = 150;` cuando el máximo es 100.

Convertilo en una `class` que:

- reciba el pin en el constructor,
- configure el pin en `begin()`,
- tenga `encender()`, `apagar()` y `encendido()`,
- tenga `fijarPotencia(int porcentaje)`, que limite el valor entre 0 y 100, y `potencia()` para leerlo.

```cpp calefactor.ino
struct Calefactor {
  uint8_t pin;
  bool encendido;
  int potencia;
};

Calefactor calefactor = {14, false, 50};
```

</details>

<details>
<summary>Ver solución</summary>

```cpp calefactor.ino
class Calefactor {
public:
  explicit Calefactor(uint8_t pin) : _pin(pin) {}

  void begin() {
    pinMode(_pin, OUTPUT);
    apagar();
  }

  void encender() {
    digitalWrite(_pin, HIGH);
    _encendido = true;
  }

  void apagar() {
    digitalWrite(_pin, LOW);
    _encendido = false;
  }

  void fijarPotencia(int porcentaje) {
    _potencia = constrain(porcentaje, 0, 100);
  }

  bool encendido() const { return _encendido; }
  int potencia() const { return _potencia; }

private:
  uint8_t _pin;
  bool _encendido = false;
  int _potencia = 50;
};

Calefactor calefactor(14);

void setup() {
  calefactor.begin();
  calefactor.fijarPotencia(150);   // queda en 100
}

void loop() {}
```

Ahora las dos líneas problemáticas no compilan: `_encendido` y `_potencia` son privados. La única forma de encender es `encender()`, que también cambia el pin, y la única forma de cambiar la potencia es `fijarPotencia()`, que la mantiene en rango. Encontrar todos los lugares que usaban el `struct` viejo es fácil: el compilador te los marca uno por uno.

</details>

## Resumen

- `struct` y `class` solo difieren en la visibilidad por defecto. Por convención: `struct` para datos sin reglas, `class` cuando hay invariantes que proteger.
- `private` hace que el estado solo cambie a través de los métodos, que mantienen coherentes los datos y el hardware.
- El constructor inicializa el objeto. Usá `explicit` en los constructores de un parámetro y valores por defecto en todos los miembros.
- En Arduino, el constructor guarda la configuración y `begin()` toca el hardware, porque los objetos globales se construyen antes de `setup()`.
- La lista de inicialización es obligatoria para referencias y miembros `const`, y se ejecuta en el orden de las declaraciones.
