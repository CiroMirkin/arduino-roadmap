**PWM** (*modulación por ancho de pulso*) simula un nivel intermedio entre apagado y encendido prendiendo y apagando un pin muy rápido. El porcentaje del tiempo que el pin pasa encendido se llama **ciclo de trabajo** (*duty cycle*): con un 25 %, una luz se ve a un cuarto de su intensidad y un ventilador gira más despacio. En el ESP32, el PWM lo genera un periférico llamado **LEDC**, por hardware, sin ocupar al procesador.

## Por qué te importa

En el invernadero, casi todo lo que necesita "un poco" en lugar de "todo o nada" se controla con PWM: la intensidad de las luces de cultivo según la luz natural, la velocidad del ventilador según la temperatura, la posición de un servo que abre la ventana cenital, el brillo de la pantalla del controlador.

La frecuencia y la resolución no son detalles: con una frecuencia mal elegida, las luces parpadean en la cámara del celular, el ventilador zumba o el servo tiembla. Y la API de LEDC cambió entre versiones del core de Arduino para ESP32, así que muchos ejemplos de internet no compilan con la versión actual.

## Paso a paso

### 1. La idea: encender y apagar muy rápido

Si un LED se prende 1 ms y se apaga 3 ms, una y otra vez, el ojo no ve el parpadeo: ve un LED al 25 % de intensidad. Lo mismo pasa con un motor: recibe energía un cuarto del tiempo y gira más lento.

```text
100 %  ████████████████████████
 50 %  ████░░░░████░░░░████░░░░
 25 %  ██░░░░░░██░░░░░░██░░░░░░
```

Dos parámetros definen la señal:

- **Frecuencia**: cuántas veces por segundo se repite el ciclo. 1000 Hz es un ciclo por milisegundo.
- **Ciclo de trabajo**: qué parte de cada ciclo el pin está en `HIGH`.

### 2. La resolución

El ciclo de trabajo se expresa como un número entero, y la **resolución** dice cuántos niveles hay. Con 8 bits, el valor va de 0 a 255; con 10 bits, de 0 a 1023; con 14 bits, de 0 a 16383. Más bits, pasos más finos. El máximo depende del chip: 20 bits en el ESP32 clásico y 14 en el S3.

Frecuencia y resolución están relacionadas: el LEDC usa un reloj de 80 MHz, y cada ciclo de PWM tiene que contener 2^bits pasos de ese reloj. Con 8 bits se puede llegar a frecuencias altas; con 14 bits, solo a unos pocos kHz. Si pedís una combinación imposible, la configuración falla.

| Uso | Frecuencia típica | Resolución típica |
|---|---|---|
| LED, luces, backlight | 1 a 5 kHz | 8 a 12 bits |
| Ventilador de 4 cables | 25 kHz | 8 bits |
| Servo | 50 Hz | 14 bits |

### 3. La API de LEDC (core 3.x)

```cpp
constexpr uint8_t PIN_LUCES = 6;

void setup() {
  ledcAttach(PIN_LUCES, 1000, 10);   // pin, frecuencia (Hz), resolución (bits)
  ledcWrite(PIN_LUCES, 512);         // ~50 %: 512 de 1023
}
```

`ledcAttach` configura el pin y devuelve `false` si la combinación de frecuencia y resolución no es posible. `ledcWrite` cambia el ciclo de trabajo cuando quieras; el hardware sigue generando la señal mientras tu código hace otras cosas.

En el core 2.x de Arduino-ESP32 la API usaba canales: `ledcSetup(canal, frecuencia, bits)`, `ledcAttachPin(pin, canal)` y `ledcWrite(canal, valor)`. Si un ejemplo no compila con esos nombres, es de la versión anterior.

`analogWrite(pin, valor)` también funciona en el ESP32: usa LEDC por dentro con 8 bits y una frecuencia fija. Sirve para pruebas rápidas; para controlar frecuencia y resolución, usá `ledcAttach`.

### 4. El pin da la orden, no la potencia

Un GPIO entrega unos pocos mA (ver [0.3](/conceptos/0-3)). Las luces de cultivo, un ventilador o un motor se manejan con un **MOSFET** (o un driver) que conmuta la carga con su propia fuente; el ESP32 solo le manda la señal PWM. Con motores y bobinas, además, va un **diodo** en paralelo con la carga para absorber el pico de voltaje al apagarse.

Los ventiladores de 4 cables son más simples: tienen un cable de control PWM propio, y la potencia la manejan ellos mismos.

### 5. Servos: la posición en el ancho del pulso

Un servo no usa el ciclo de trabajo como "intensidad". Espera un pulso cada 20 ms (50 Hz), y el **ancho** del pulso indica la posición: alrededor de 0,5 ms es un extremo, 1,5 ms el centro y 2,5 ms el otro extremo (los valores exactos varían según el modelo).

Para convertir un ancho de pulso en un valor de `ledcWrite`:

```cpp
// período de 20.000 µs, resolución de 14 bits (0 a 16383)
uint32_t valor = anchoUs * 16383UL / 20000UL;   // 1500 µs -> 1228
```

Con 14 bits, cada paso del valor equivale a 1,2 µs de pulso, una fracción de grado, y el servo se mueve suave. Se usan 14 bits porque es el máximo del LEDC del ESP32-S3 (el ESP32 clásico llega a 20).

## Ejemplos

### Ejemplo 1. Un LED que sube y baja de intensidad

```cpp fade.ino
// nodo (ESP32 clásico)
constexpr uint8_t PIN_LED = 2;
constexpr uint8_t BITS = 10;
constexpr int MAXIMO = (1 << BITS) - 1;   // 1023

void setup() {
  Serial.begin(115200);
  if (!ledcAttach(PIN_LED, 1000, BITS)) {
    Serial.println("no se pudo configurar el PWM");
  }
}

void loop() {
  static uint32_t ultimo = 0;
  static int valor = 0;
  static int paso = 8;

  if (millis() - ultimo >= 10) {        // un paso cada 10 ms, sin delay
    ultimo = millis();
    valor += paso;
    if (valor >= MAXIMO || valor <= 0) {
      paso = -paso;
      valor = constrain(valor, 0, MAXIMO);
    }
    ledcWrite(PIN_LED, valor);
  }
}
```

`1 << BITS` es 2 elevado a `BITS` (desplazar un 1 a la izquierda), así el máximo se calcula solo si cambiás la resolución.

### Ejemplo 2. Velocidad del ventilador según la temperatura

El ventilador de 4 cables del invernadero gira al 20 % por debajo de 26 °C (para mover algo de aire siempre) y al 100 % desde los 34 °C, con una rampa lineal en el medio.

```cpp ventilador.ino
constexpr uint8_t PIN_PWM_VENTILADOR = 5;
constexpr uint32_t FRECUENCIA = 25000;   // 25 kHz: lo que piden los ventiladores de 4 cables
constexpr uint8_t BITS = 8;

constexpr float TEMP_MINIMA = 26.0f;
constexpr float TEMP_MAXIMA = 34.0f;
constexpr float VELOCIDAD_MINIMA = 0.20f;

void fijarVelocidad(float fraccion) {
  fraccion = constrain(fraccion, 0.0f, 1.0f);
  uint32_t valor = static_cast<uint32_t>(lroundf(fraccion * 255.0f));
  ledcWrite(PIN_PWM_VENTILADOR, valor);
}

float velocidadParaTemperatura(float temperatura) {
  if (temperatura <= TEMP_MINIMA) return VELOCIDAD_MINIMA;
  if (temperatura >= TEMP_MAXIMA) return 1.0f;
  float t = (temperatura - TEMP_MINIMA) / (TEMP_MAXIMA - TEMP_MINIMA);
  return VELOCIDAD_MINIMA + t * (1.0f - VELOCIDAD_MINIMA);
}

void setup() {
  Serial.begin(115200);
  ledcAttach(PIN_PWM_VENTILADOR, FRECUENCIA, BITS);
  fijarVelocidad(VELOCIDAD_MINIMA);
}

void loop() {
  static uint32_t ultimo = 0;
  if (millis() - ultimo >= 2000) {
    ultimo = millis();
    float temperatura = 29.0f;           // acá iría la lectura real
    float v = velocidadParaTemperatura(temperatura);
    fijarVelocidad(v);
    Serial.printf("%.1f C -> ventilador al %.0f%%\n", temperatura, v * 100.0f);
  }
}
```

A diferencia de un control de abrir y cerrar con dos umbrales, la velocidad proporcional a la temperatura no necesita margen: un cambio pequeño de temperatura produce un cambio pequeño de velocidad, sin saltos. La lógica (qué velocidad corresponde a cada temperatura) está separada del hardware (cómo se escribe en el pin), lo que permite probarla sin ventilador.

### Ejemplo 3. Un servo que abre la ventana cenital

Un servo mueve la ventana del techo entre cerrada (0°) y abierta (90°). Moverlo de golpe sacude el mecanismo, así que se mueve de a un grado cada 20 ms hasta llegar al objetivo.

```cpp ventana-servo.ino
class ServoVentana {
public:
  ServoVentana(uint8_t pin, uint16_t pulsoMinUs, uint16_t pulsoMaxUs)
    : _pin(pin), _pulsoMinUs(pulsoMinUs), _pulsoMaxUs(pulsoMaxUs) {}

  bool begin() {
    if (!ledcAttach(_pin, 50, 14)) return false;   // 50 Hz, 14 bits
    escribirAngulo(_actual);
    return true;
  }

  void irA(int angulo) { _objetivo = constrain(angulo, 0, 180); }
  int angulo() const { return _actual; }

  // Llamar en cada vuelta de loop()
  void actualizar() {
    if (_actual == _objetivo) return;
    if (millis() - _ultimoPaso < 20) return;
    _ultimoPaso = millis();
    _actual += (_objetivo > _actual) ? 1 : -1;
    escribirAngulo(_actual);
  }

private:
  void escribirAngulo(int angulo) {
    uint32_t anchoUs = _pulsoMinUs + (static_cast<uint32_t>(_pulsoMaxUs - _pulsoMinUs) * angulo) / 180;
    uint32_t valor = anchoUs * 16383UL / 20000UL;     // fracción del período de 20 ms
    ledcWrite(_pin, valor);
  }

  uint8_t _pin;
  uint16_t _pulsoMinUs;
  uint16_t _pulsoMaxUs;
  int _actual = 0;
  int _objetivo = 0;
  uint32_t _ultimoPaso = 0;
};

ServoVentana ventana(7, 500, 2500);    // los anchos dependen del modelo de servo

void setup() {
  Serial.begin(115200);
  if (!ventana.begin()) Serial.println("error configurando el servo");
  ventana.irA(90);                     // abrir
}

void loop() {
  ventana.actualizar();
  // el resto del controlador sigue funcionando mientras la ventana se mueve
}
```

`irA` solo fija el objetivo y vuelve enseguida; `actualizar` mueve un grado por vez sin bloquear (ver [0.1](/conceptos/0-1)). Los anchos mínimo y máximo van como parámetros porque cada modelo de servo es un poco distinto: si el servo zumba en un extremo, está forzando contra su tope y hay que achicar el rango. El servo se alimenta con su propia fuente de 5 V (compartiendo GND con el ESP32), no desde la placa.

## Errores comunes

### Combinación imposible de frecuencia y resolución

```cpp
// Mal: 25 kHz con 14 bits necesitaría un reloj de 410 MHz
ledcAttach(PIN_VENTILADOR, 25000, 14);   // devuelve false y el pin no hace nada

// Bien
if (!ledcAttach(PIN_VENTILADOR, 25000, 8)) {
  Serial.println("PWM no configurado");
}
```

Chequeá siempre el valor de retorno de `ledcAttach`.

### Usar la API del core 2.x en el 3.x (o al revés)

```cpp
// Core 2.x
ledcSetup(0, 1000, 8);
ledcAttachPin(PIN_LUCES, 0);
ledcWrite(0, 128);          // canal

// Core 3.x
ledcAttach(PIN_LUCES, 1000, 8);
ledcWrite(PIN_LUCES, 128);  // pin
```

Fijate qué versión del core tenés en *Herramientas → Placa → Gestor de placas* (ver [0.13](/conceptos/0-13)).

### Conectar la carga directo al pin

Un ventilador de 12 V o una tira de luces no se conectan a un GPIO. El PWM va a la compuerta de un MOSFET (o a la entrada PWM del ventilador de 4 cables), y la carga se alimenta de su propia fuente.

### Frecuencia audible o visible

Por debajo de unos 100 Hz, las luces parpadean a simple vista; entre unos cientos de Hz y unos kHz, en una cámara se ven bandas. Entre 1 y 20 kHz, motores y bobinas pueden zumbar. Elegí la frecuencia según la carga (tabla del paso 2).

## Ejercicio

Las luces de cultivo se manejan con un MOSFET y deberían ajustarse en pasos de 1 % según un valor que llega de la pantalla. El código actual hace que las luces parpadeen, y los porcentajes bajos (1 a 5 %) se ven todos iguales. Corregilo.

```cpp luces.ino
}

void fijarIntensidad(int porcentaje) {
  ledcWrite(PIN_LUCES, porcentaje * 255 / 100);
}
```

```cpp luces.ino
constexpr uint8_t PIN_LUCES = 6;
constexpr uint32_t FRECUENCIA = 2000;   // por encima del parpadeo visible
constexpr uint8_t BITS = 12;            // 0 a 4095
constexpr uint32_t MAXIMO = (1u << BITS) - 1;

void setup() {
  Serial.begin(115200);
  if (!ledcAttach(PIN_LUCES, FRECUENCIA, BITS)) {
    Serial.println("no se pudo configurar el PWM de las luces");
  }
}

void fijarIntensidad(int porcentaje) {
  porcentaje = constrain(porcentaje, 0, 100);
  uint32_t valor = static_cast<uint32_t>(porcentaje) * MAXIMO / 100;
  ledcWrite(PIN_LUCES, valor);
}
```

A 50 Hz el parpadeo se ve a simple vista; 2 kHz está muy por encima. Con 8 bits, 1 % a 5 % daban valores de 2 a 12: pocos pasos, en la zona donde el ojo es más sensible a las diferencias. Con 12 bits, el mismo rango da de 40 a 204, cinco niveles bien distintos. 2 kHz con 12 bits es una combinación posible para el LEDC.

## Resumen

- PWM prende y apaga un pin muy rápido; el ciclo de trabajo es la fracción del tiempo encendido.
- La frecuencia se elige según la carga: kHz para luces, 25 kHz para ventiladores de 4 cables, 50 Hz para servos.
- La resolución da cuántos niveles hay (8 bits: 0 a 255). Frecuencia alta y resolución alta no siempre se pueden combinar: chequeá el retorno de `ledcAttach`.
- Core 3.x: `ledcAttach(pin, frecuencia, bits)` y `ledcWrite(pin, valor)`. Los ejemplos con canales son del core 2.x.
- El GPIO da la señal; la potencia la maneja un MOSFET, un driver o la electrónica del propio dispositivo.
